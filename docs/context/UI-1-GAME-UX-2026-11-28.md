## 1. 경기 화면·점수판
**원인(재현):** 로컬 다인전 데스크톱(2인 포함, 768·1280px)에서 점수 버튼이 약 10px 폭으로 줄어 족보 이름(하단 족보의 주사위 그림 포함) 위에 겹쳤다. `.scoreboard .score-option { width: auto }`(table-v4) + `.multi-scoreboard.compact .score-option { padding: 2px 0; min-width: 0 }`(multi-compact)가 겹쳐 `<button>`이 내용 폭으로 수축한 것. 스크린샷 `docs/ui/ui1-2026-11/before-local*`.

**공통 점수판(`src/MultiScoreboard.tsx`, `src/ui/sheet-layout.ts`, `src/ui/scoreboard-ui1.css`)** — 로컬·온라인 다인전·1인·기보 보기가 같은 컴포넌트를 쓴다(온라인/AI 1:1은 기존 `Scoreboard` 유지, 같은 버튼 규칙).
- 최소 크기: 들어가는 가장 넓은 단계를 고른다 — wide(족보 164 / 플레이어 72px), mid(124 / 60), tight(88 / 50, 3px 여백 + 44px 버튼). 점수 버튼은 폭 ≥ 44px이고 칸을 채움, 높이는 터치 36px·마우스 26px(1인 플레이 12칸이 1280×635 한 화면에 들어가도록, A2 기준 유지). 2~4인은 320px 휴대폰에서도 스크롤 없이(A4 기준 유지). 하단 족보의 주사위 그림은 점수판에서 숨기고 이름만(말줄임 + `title`).
- 실제 지원 인원(소스 확인): 로컬 2~50명(`MAX_LOCAL_PLAYERS`), 온라인 2~20명(`MAX_SEATS`). 테스트·설계 범위 2~20명.
- 적응형: 측정한 폭에 모든 열이 최소 크기로 들어가면 좌석 순서 그대로 한 화면. 아니면 **고정 열**(온라인 = 나, 로컬 = 현재 차례)을 족보 열 옆으로 옮겨 sticky로 고정하고 나머지 열은 가로 스크롤(안내 "옆으로 밀어 다른 플레이어 보기").
- 현재 차례: 헤더 빨간 하단 띠 + "· 차례" + 열 배경. 총점 줄도 현재 열을 구분.
- 9인 이상 기본값을 "전체 점수표"로 변경(이전: 한 명만). "현재 차례만"/"내 점수판" 전환은 유지.
- 휴대폰 로컬 다인전: 점수판 시트에 "현재 차례 / 전체 점수표" 전환 추가(전체 = 같은 공통 점수판).
- 데스크톱 배치: 2~4인은 ≥ 1100px에서 보드 옆에 점수판(폭 = 164 + 인원×100px), 5인 이상·좁은 폭은 보드 아래 전체 폭, 보드 최소 높이 `clamp(280px, 40vh, 420px)`로 빈 공간 축소.

## 2. 자동 매칭 팝업 (`src/play/MatchPopup.tsx`, `src/ui/floating.ts`)
- `createPortal(…, document.body)` + `position: fixed` → 본문 레이아웃·스크롤 높이 불변(테스트로 확인).
- 빠른 대전 시작 즉시 표시, 기본 위치 우측 하단(휴대폰은 하단 바 위 88px), 마우스·터치 드래그(창 밖으로 끌어도 window 리스너로 추적, 4px 미만은 탭), 화면 밖 방지(8px 여백, 창 크기 변화·회전 시 재보정), 위치는 화면 비율로 이 기기에 저장, 손잡이에 포커스 후 방향키로 이동.
- 최소화 → 경과 시간이 보이는 알약, 다시 눌러 복원. 매칭 취소·경과 시간·AI 대안·재연결·진행 중 경기 복귀 버튼은 기존 상태 기계(`useBackgroundMatch`) 그대로. 상태는 App 수준이라 페이지 이동 중 유지, 매칭 성사 시 기존 입장 절차(`entered()`로 숨김).
- 접근성 이름("빠른 대전 상태", "최소화", "빠른 대전 상태 보기", 타이머 "매칭 경과 시간")은 기존 테스트와 호환.

## 3. 글로벌 헤더·친구 패널
- 버튼 44×44(≤ 374px는 40×44), PC(≥ 1024px)는 아이콘 + 메뉴명(상점·인벤토리·친구), 그 아래는 아이콘만. 휴대폰은 로고 글자를 먼저 숨겨 겹침 방지(이전 390px에서 버튼 추가 시 로고와 겹침 확인). 재화는 PC에서 알약형, 휴대폰은 2줄 축약.
- `html { scroll-padding-top }`으로 sticky 헤더가 앵커·포커스 이동 대상을 가리지 않게.
- **친구 패널**(`src/shell/FriendsPanel.tsx`): 헤더 "친구" 버튼(받은 요청+유효한 초대 수 배지, `.header-badge`는 향후 공지·보상함 알림에 재사용) → 모달 `<dialog>`(top layer): PC 우측 서랍, 휴대폰 하단 시트. 내용은 기존 친구 화면(`FriendsPage`: 목록·요청·코드로 추가·검색·서버 접속 상태). 어느 페이지에서나 열리고 본문 위치 불변.
- **하지 않은 것:** 패널에서 친구 경기 관전·방 초대 — 서버가 친구의 방 코드·초대 가능 상태를 주는 계약이 없으므로 표시하지 않음(SOC-1 계약 대기, §10). 접속 상태는 서버 inbox 확인으로 생긴 값만.

- 퀵 이모티콘 버튼 PC 52px·글자 27px, 휴대폰 46px·25px. 보유권·전송 제한(서버·`useTableChat`)은 그대로. 상품별 이펙트·사운드는 FX-1.

## 5. 경기 종료·결과 공유
**모든 온라인 결과창을 A3 디자인(`MatchResultPanel`)으로 통일**(D-099 후속). 입력은 공개 이벤트 로그 → `match-result/adapters.fromOnline`. 결과창에 판단 정확도·주사위 운·판단 손실 등 고급 분석 지표는 넣지 않는다(E2E에서 금지 문구 검사).

| 화면 | 레이아웃 | 제목 예 | 버튼(권한) | 보상 |
|---|---|---|---|---|
| 온라인 1:1 | 대결형 | 승리 · 패배 · 무승부 · 승리(상대 기권/시간 초과/이탈) · 기권패 | 재대결(요청/수락, 다시 열기 버튼 "경기 결과 · 재대결 요청") → 게임 리뷰 → 결과 공유 → 나가기 | `MatchRewardSummary`(서버 receipt만) |
| 온라인 다인전(3~20) | 순위표형 | 1위 · 공동 2위 · n위 + "n명 중", 기권자는 "기권" | 한 번 더 플레이(요청)·지금 시작(방장만) → 리뷰(다인전은 비활성 + 사유) → 나가기. 공유 없음(공유 카드는 1:1 형식) | 좌석이 있는 참가자만 |
| 관전자 | 순위표형/대결형, **경기 전체 결과** | "OO 승리" · 공동 1위 · 무승부, 부제 "n명 경기 결과"/"OO 님이 기권했어요" | 관전 종료만(재대결·리뷰·공유·친구 추가 없음) | 없음 |

- 순위표: 공동 순위(같은 번호 + 스크린리더 "공동 n위"), 기권 사유 배지(기권 / 시간 초과 / 이탈 — 사유 이벤트가 없는 화면은 좌석 상태로 "기권"), 기권자는 아래·흐리게, 내 줄 강조. 9명 이상은 촘촘한 행 + 창 안 스크롤(20명 확인).
- 관전자: 본인 승패가 없으므로 승리 색·승리 음악·결과 효과음을 쓰지 않는다(tone neutral, sound off). 개인 최고·연승 하이라이트, 재화 보상, 참가자 전적(방 전적 승패)을 표시하지 않는다.
- 무효 경기: 표시 모델(`voided` → "무효 경기", 승패·연출 없음)만 준비. 현재 서버는 무효 종료 사유를 보내지 않아 쓰지 않는다(§10).
- 리뷰할 기록이 없는 경기(경기 중 새로고침 등)와 다인전: "리뷰 기록 없음" 비활성 버튼 + 사유(`title`, 스크린리더 문구).
- **공유 창이 좌측 상단에 붙는 버그:** CSS 리셋이 `<dialog>`의 `margin: auto`를 지워서. 공유 창을 공통 `Sheet`(PC 가운데 모달, 휴대폰 하단 시트, 배경, Esc, 포커스 복귀)로 교체하고, 공통 규칙으로 모든 `dialog.modal`·결과창에 `margin: auto`.
- 공유 이미지: 어두운 그라데이션, 결과 제목, 두 점수 패널(이긴 쪽 강조), 경기 종류 알약, VS. 닉네임 기본 비공개(체크해야 표시) 유지. 분석 지표 없음.

## 6. 게임 리뷰·프로필
- **주요 장면 한 글자씩 줄바꿈:** 행운/불운 행이 3열 그리드(주사위 5개·텍스트·수치)에 들어가 250px 카드에서 텍스트 열이 수십 px로 줄고 `overflow-wrap: anywhere`가 글자마다 끊었다. 카드 최소 폭 420px(2×2), 행운/불운은 주사위·수치 위 / 텍스트 아래 2줄, `word-break: keep-all`, 수치 `nowrap`.
- 실제 선택과 AI 추천을 "내 선택"/"AI 추천" 라벨 줄로 분리(화살표 인라인 제거). 분석 공식·모델·데이터 계약 불변.
- 프로필: 카드 행 높이 맞춤(2열 900px~, 3열 1100px~), 빈 상태 가운데 정렬, 기록이 없을 때 1인 카드의 중복 안내("공식 랭킹·보상에는…") 숨김. 대표 업적 편집은 A4 구현 그대로(서버 저장은 SOC-1 계약 대기).

## 7. 공통 디자인 규칙 (`src/ui/ui1-common.css`)
간격 4px 단위(`--ui1-space-*`), 터치 대상 44px(`--ui1-target`), 모서리 8(컨트롤)/12(카드)/18(대화상자), 떠 있는 요소 그림자 `--ui1-shadow-float`. 모달은 kit `Sheet` 사용(직접 `<dialog>`를 쓰면 `margin: auto` 필수). 상점·인벤토리(UI-2)는 이 토큰과 Sheet 규칙을 사용하면 된다.

## 10. SOC-1 연동 요구사항
현재 서버 계약으로 구현할 수 없어 **표시하지 않는** 기능과, 연결에 필요한 인터페이스(제안 — SOC-1이 확정):

**친구 패널**
- 현재 사용: `GET /api/me/friends`(목록·요청·차단, 친구별 `status: online | playing | offline` — 서버가 inbox 확인으로 만든 값), `GET /api/me/inbox`(요청 수·방 초대), 친구 코드 요청/수락/거절/삭제/차단, `inviteFriends(room, codes)`(방 안 초대 화면에서만). 클라이언트는 접속 상태를 추정하지 않는다.
- 필요(관전): 친구가 경기 중일 때 관전 가능 여부와 입장 수단. 예: `FriendEntry.watch?: { room: string; key?: string; mode: "turns" | "simultaneous"; seats: number; round: number } | null` — 친구 방의 관전 범위가 그 사용자에게 허용될 때만 서버가 채움. UI: 친구 줄에 "관전" 버튼 → 기존 `enterWatch(code, key)`.
- 필요(패널에서 초대): 내가 대기실에 있을 때의 방 코드와 남은 자리. 클라이언트는 현재 방 코드를 알고 있으므로 서버 쪽은 기존 `inviteFriends` 그대로면 충분하나, 친구별 "초대 가능"(차단·오프라인·이미 경기 중) 판정을 서버가 줘야 한다: `FriendEntry.invitable?: boolean`.
- 필요(알림): 헤더 배지(`.header-badge`)는 `requests + 유효 초대` 수만 쓴다. 공지·보상함(ADMIN-1·C5)은 같은 배지 구조에 `GET /api/me/notifications { unread: number }` 같은 합계 하나면 연결 가능.
- 대표 업적 공개 표시: 서버 저장 API(A4 계약 후보 문서) 필요.

**결과창**
- 무효 경기: `matchFinished`에 `outcome?: "normal" | "void"`와 `reason?` 필요(서버 점검·전원 이탈 등). 받으면 `fromOnline`에서 `voided`로 넘기면 끝.
- 관전자 재접속 시 기권 사유: 늦게 들어온 관전자는 `playerForfeited` 이벤트가 없어 좌석 상태로 "기권"만 표시한다. 사유를 보이려면 `PlayerView.players[].forfeitReason?` 필요.
- 다인전 리뷰·다인전 결과 공유 카드: 리뷰 분석은 2인 전용(C2 계약), 공유 카드는 1:1 형식 — 확장 시 C2·UI-1 후속.
- 매칭 팝업: 대기 인원·예상 대기 시간은 서버가 주지 않아 표시하지 않는다(필요 시 `queued` 응답에 `estimateMs?`).

### 11.3 알림함과 보상함의 역할(중복 방지)
C5 계약(`docs/economy/c5/REWARD-GRANT-CONTRACT.md` §7, `INTEGRATION-C5.md` §3)과 ADMIN-1 문서(§9.7)가 이미 **지급 경로 하나**(C5 `RewardGrants`, 원장 `g:`)로 수렴하기로 했다. 화면도 그에 맞춘다.
- **보상함 = C5 `#rewards`의 "받을 보상"** 한 곳: 출석·연속 활동·주간 연승·운영 보상·제안 채택 보상·일일 콘텐츠 보상을 모두 여기서 수령(`/api/me/rewards/claim`).
- **알림함 = ADMIN-1 `#mailbox`**: 공지·점검·제재 통지·운영 메시지(읽기 전용). 보상이 붙은 우편은 본문에 "보상함에서 받기" 링크만 두고, 알림함 안에 두 번째 수령 버튼을 만들지 않는다(C5 INTEGRATION §3.2 "보상함 통합").
- **교환 코드 입력칸도 하나**: `#rewards`의 C5 `/api/me/rewards/redeem`(내부에서 ADMIN-1 AdminHub 예약 → 계정 지급 2단계). ADMIN-1의 `/api/me/redeem`에는 별도 화면을 만들지 않는다.
- **헤더 배지(후속):** 합계 하나 `GET /api/me/notifications → { mailboxUnread, rewardsClaimable }`가 생기면 헤더에 벨 하나(`.header-badge` 재사용) → 누르면 작은 목록(알림 n · 받을 보상 m) → 각 화면. 그 전에는 헤더를 늘리지 않는다. 친구 요청·초대 수는 지금처럼 "친구" 버튼 배지.

**이번 단계에서 고친 것**
- `game-shell.spec.ts:14` 사이드바 닫기 테스트가 간헐적으로 실패했다.
  - 원인은 제품이 아니라 테스트의 전환 애니메이션 경합이다. Escape 직후 한 번만 상태를 확인하는데, 부하가 걸리면 그 시점에 240ms 닫힘 전환이 이미 끝나 있었다.
  - 상태 변화를 기록해 확인하도록 테스트를 바꿨다. CPU를 10배 느리게 했을 때 수정 전 20회 중 8회 실패 → 수정 후 20회 모두 통과.
