## 1. 요약 (2026-11-25)

- **PR #75(v5)를 최신 main에 병합했다**(`c543b8d`). 병합 전 확인: PR CI 전부 성공, main+PR 트리에서 로컬 `npm test` 415/415 통과, `npm run build` 통과.
- **v6의 핵심 아이디어:** 지수효용 `E[exp(λG)]`는 이미 얻은 점수와 분리되므로, 그 최적 정책은 자기 점수판 (mask, u)에만 의존한다. 따라서 **모든 λ마다 정확한 미래 득점 PMF 은행**을 만들 수 있다(λ=0은 DP Expert와 비트 단위로 같다). 이를 이용해 "이번 턴 이후의 나 = DP Expert"라는 v5-R의 가정을 다음 세 가지로 넓혔다. ① 정책군 롤아웃(v6-P), ② K칸 이하 전 구간 정확 최적 대응(v6-A), ③ 상대 정책군에 대한 최대최소·혼합(v6-L/Lm).

- **원인 분석(§3.2):** 고정된 상대 분포에 맞춰 "미래의 나"를 더 정확히 최적화할수록, 정확한 상호작용 가치를 **더 크게 과대평가**한다. 남은 3칸 기준 편향은 롤아웃 +0.65%p, 정책군 +0.84%p, 전 구간 BR +0.97%p였다. 상대가 내 결과를 보고 대응하는 효과를 무시한 낙관이 의사결정을 흐린다는 해석과 일치한다.
- **실행 최적화는 실질적인 성과가 있었다.**
  - WASM 은행 빌더: 7 KB, 외부 의존 없음. TS 은행과 **비트 단위로 동일**하며 Node 8.0초, Chromium Web Worker 8.1초.
  - Rust 포팅: 비트 동일, 3.5초.
  - 로더 최대 RSS: 677 MB → 379 MB.
  - Float32: 실제 결정 4,023건에서 실질 불일치 0건.
  - PMF 신경망 증류와 하이브리드는 정확도가 부족해 채택하지 않았다.
- 복기용 **버전 지정 분석 API `yachtlab-analysis-v6`**: 승·무·패 확률, 굴림 전 가치, 결정 손실과 주사위 운의 분해, 모델 메타데이터를 제공한다. 기존 `analysis.ts`는 바꾸지 않았다. 예제는 [examples/analysis-v6-example.json](examples/analysis-v6-example.json).

## 3. 정확 확률·동적계획법 (축 A)

### 3.1 문제 구분

| 문제 | 정의 | 이번 연구의 처리 |
|---|---|---|
| 고정 상대 점수분포에 대한 정확 최적 대응 | 상대 최종점수 X의 분포가 내 행동과 독립. 효용 F(x)=P(X<x)+0.5P(X=x)를 내 남은 모든 턴에서 최대화. 상태 (mask, u, 현재 점수 x) | v6-A(K): 남은 칸 ≤K일 때 정확 Bellman DP(K=3,4,6). 매 결정마다 상대의 현재 PMF로 다시 계획 |
| 상대 점수판 변화를 관측하며 대응 | 상대가 비반응형이어도, 상대의 중간 결과를 본 뒤 내 정책을 바꿀 수 있음(정보 가치) | 다시 계획(receding horizon)으로 일부만 반영. 정확한 해는 양측 상태 곱이라 전 구간에서는 불가능 |
| 상대가 내 행동에 반응하는 상호작용 게임 | 양측이 모두 승리 점수율을 최대화 | v5 정확 expectiminimax(양측 ≤3, 복기용 ≤4)를 재사용(v6-PB3) |
| 전체 게임 균형 | 위 게임의 전 구간 해 | 상태 ≈ (4096·64·~400)² 규모라 계산 불가. 축소 게임에서만 정확(≤4칸) |

**전 구간 고정 상대 BR의 계산량:**
- 게임 시작부터 풀면 (mask, u, x) ≈ 4096 × 64 × ~400 ≈ 1.05억 상태이고, 상태마다 턴 풀이(≈3만 연산)가 필요하다. 합계 약 3×10¹² 연산이고, 상대 PMF가 바뀔 때마다 다시 계산해야 하므로 실시간이나 대국 실험에서는 불가능하다.
- 남은 칸 ≤6에서는 메모이제이션한 하향식 풀이로 판단 평균 10.5 ms(p99 309 ms)였다(CI 측정).

### 3.3 정적 정책 메타게임 (정확)

게임 시작부터 λ를 고정한 두 정책의 승리 점수율은 두 초기 PMF의 합성곱으로 정확히 계산된다(`training/results/v6/static-metagame.json`).
- **λ=0(DP Expert)이 유일한 순수 Nash다.** λ=0 대 λ=±0.02는 50.256% / 50.295%, 대 λ=+0.08은 54.889%.
- λ별 평균과 표준편차: −0.08은 186.4 / 35.3, 0은 191.8 / 37.9, +0.08은 184.9 / 42.8.
- 위험 선호나 회피는 국면에 따라 바꿀 때만 의미가 있다. v6-P는 바로 그 전환을 정확하게 구현했지만, 대국에서는 이득이 없었다.

## 4. 잔차·가치 학습 (축 B)

- **Ridge 잔차(v6-C).** 교사 자료는 상대 차례 시작 국면(양측 ≤4칸)이다. v5-R과 v2를 좌석 교대로 둔 2,000경기에서 얻은 12,600행이며, 목표는 정확 상호작용 가치에서 v6-P 가치를 뺀 값이다.
  - 분할은 **경기 단위**다(경기 번호 mod 5 = 0 보류: 학습 1,600경기, 보류 400경기).
  - 정규화 강도와 적용할 k는 학습 경기 안의 내부 검증 분할로만 골랐다(k ∈ {2,3,4}).
  - 보류 MAE: 기준 0.611 → 전체 적용 0.618(악화) → 게이트 적용 **0.558%p(−8.7%)**.
  - v5 연구에서 행 단위 분할로 얻은 −17%는 경기 단위 분할에서 재현되지 않았다.
  - 대국 효과는 §6.3(개발 9012)에 있다.
- **분포형 가치(PMF 증류, 기법 15/옵션 16):** §7.4.
- LightGBM, Cross-Attention, DeepSets, QR-DQN, IQN, C51, Rainbow는 §9의 상태표 참고.

## 8. 복기용 분석 API — `yachtlab-analysis-v6` (Codex UI 계약)

- **진입점:** `analyzeV6(state, cfg, engine?, played?)`와 `decomposeStep(before, played, after, cfg)`. 파일은 `src/research-v6/analysis6.ts`. 기존 `src/research-v5/analysis.ts`의 `analyzePosition`과 `rerollDistribution`은 **그대로 두었다**(호환 유지).
- **엔진 설정:**
  - `V6_LIVE`: 깊이 1 정책군, 남은 칸 ≤4에서 전 구간 BR, 50 ms 예산.
  - `V6_REVIEW`: 깊이 2, ≤6칸 BR, 양측 ≤3칸이면 정확 상호작용, 5 s 예산.
  - 예제 기준 판단 시간: 중반 복기 60 ms, 실시간 5 ms, 종반 정확 12 ms.
- **반환 필드:**

| 필드 | 의미 |
|---|---|
| `schema` | `"yachtlab-analysis-v6"` |
| `model` | name · version(`v6-research-2026-11-25.1`) · stage · policySet · opponentModel · depth · brWindow · minimaxWindow |
| `exactness.kind` | `exact-interactive`(양측 최적 대응, 종반 창) 또는 `exact-vs-fixed-opponent-distribution`(상대 미래를 고정 PMF로 본 모델 안에서 정확). 그 밖의 경우는 note에 표기 |
| `budget` | budgetMs, elapsedMs |
| `position` | player, rollsUsed, rollsLeft, dice, myTotal, opponentTotal, myRemaining, opponentRemaining |
| `preRollValue` | 이번 턴 첫 굴림 전의 모델 가치 |
| `currentValue` | 현재 굴린 상태의 가치(최선 행동의 승리 점수율) |
| `actions[]` | **모든 합법 행동**: kind(score / reroll) · category 또는 ids(고정할 주사위 id, 엔진 `hold`와 같음)와 kept 값 · label · winCredit · pWin · pTie · pLoss · expectedFinal(DP 기대 최종점수, 보조 정렬 키) · lossVsBest · tiedWithBest |
| `best` | 최선 행동 label과 동률 행동 목록(허용 오차 1e-12) |
| `played` | 실제로 둔 행동과 그 winCreditLoss, expectedPointsLoss |
| `scoreDiffDPExpert` | 양측 DP Expert일 때 (내 최종 − 상대 최종)의 정확 PMF(차트용) |
| `accuracy.measuredError` | 검증된 오차표 위치(§3.2: k별 MAE와 편향) |

- **결정과 운의 분해(`decomposeStep`):** 같은 모델 기준으로 계산한다.
  - decisionLoss = value(before의 최선) − value(실제로 둔 행동)
  - luck = value(after) − value(실제로 둔 행동)
  - 과거 행동을 평가할 때 미래 RNG, 시드, 미래 주사위를 쓰지 않는다. 다음 결정 시점의 공개 상태만 사용한다.
- **킵 토글과 확정 재굴림의 구분:** 행동 단위는 "재굴림 확정" 시점의 고정 집합이다. UI에서 개별 킵 토글은 행동이 아니다.
- **주의:** 모든 값은 명시된 모델 아래의 확률이다. 실제 최적 승률이라고 단정하지 않는다. §3.2에서 상호작용 효과로 0.1~1%p의 낙관 편향이 측정되었으므로, UI에 "추정치"로 표시하기를 권한다. pWin과 pTie는 비상호작용 단계에서만 채워지고, 정확 상호작용 단계에서는 null이다.
- **예제:** [examples/analysis-v6-example.json](examples/analysis-v6-example.json). 생성 스크립트는 `scripts/research-v6/analysis-example.ts`.

## 9. 기법별 상태 (50개 연구·평가 기법 + 20개 실행 최적화)

상태 표기:
- **재사용**: 기존 구현을 다시 씀
- **신규**: 이번에 새로 구현함
- **실험**: 실험까지 마침
- **입증**: 개선이 입증됨
- **실패**: 실험했지만 개선이 확인되지 않음
- **미완료**: 구현하지 않음(사유 병기)

"실패"는 개발 또는 확증 대국에서 v5-R 대비 개선이 유의하지 않거나 음수였다는 뜻이다.

## 11. 한계

- **세계 SOTA를 주장하지 않는다.** 비교 대상은 이 저장소의 AI와 레드팀 정책뿐이며, 외부 공개 AI와 사람 상대 평가는 하지 않았다. 같은 12칸 규칙과 공정한 계산 예산으로 실행 가능한 외부 AI를 찾지 못했다.
- **전 구간 정확 해는 계산하지 못했다.**
  - 고정 상대 BR은 남은 ≤6칸까지만 풀었다.
  - 상호작용 균형은 ≤4칸까지만 정확하다.
  - 전체 게임 균형과 v5-R 사이의 거리는 측정하지 못했다.
- λ-정책군은 지수효용 한 계열뿐이다. 목표 점수형이나 CVaR형 정책은 최적 정책이 이미 얻은 점수에 의존하므로, 같은 방식의 정확 은행을 만들 수 없다.
- **잔차 모델의 교사 라벨은 k≤4 종반에만 있다.** 정확 라벨이 없는 초중반 상호작용 효과는 학습하지 못했다.
- **미완료 항목:**
  - LightGBM, Cross-Attention, DeepSets, QR-DQN, IQN, Rainbow, PPO 신규 학습, MuZero, MCTS, HMM, CFR 비교.
  - 사유: 도구가 설치되어 있지 않고 설치도 거부됨, 또는 정확 해가 이미 있어 이득이 없다는 판단. 기법별 사유는 §9.
- **이 세션 환경의 제약:**
  - 다운로드한 툴체인(zig) 설치가 권한 정책으로 거부되었다. 그래서 WASM은 libc 없는 C와 시스템 clang으로 구현했다.
  - Actions 아티팩트 저장소 호스트가 프록시에서 차단되었다. 그래서 원시 샤드는 CI 아티팩트에만 있고(90일 보존), 집계는 CI 로그에서 읽었다.
  - 장시간 로컬 대국 일부가 작업자 재시작과 메모리 부족으로 종료되어, 개발 대국을 CI로 옮겼다(결과 손실은 없고 재실행했다).
- **모바일:** CDP CPU 감속은 Web Worker에 적용되지 않는다. 모바일 생성 시간과 메모리는 실기기 측정이 필요하다.
