# A4 서버 계약 후보 (2026-11-27) — 제안만, 구현·Worker 변경 없음

> A4(모바일·프로필·친구 UX)가 필요로 하지만 **현재 Worker API로는 안전하게 할 수 없는** 것들. 친구 API와 계정 보안은 C4.2 담당이라 A4는 Worker를 바꾸지 않았다. 아래는 계약 후보이며, 클라이언트는 현재 API로 최대한 동작하도록 어댑터 뒤에 두었다.

## 1. 계정 ID로 친구 요청 — C4.2와의 통합 후속 작업 (현재 클라이언트는 요청을 보내지 않는다)
**문제:** 친구 API는 **친구 코드**(`YL` + 8자 무작위)로만 사람을 가리킨다. 경기 중 상대·서버 기록·`members`는 **계정 ID**(`userId`)로만 안다. 친구 코드는 계정 ID에서 유도되지 않고 공개 프로필(`GET /api/profiles/:userId`)에도 없다. 친구 코드는 그 사람이 친구 API를 처음 쓸 때 생성·색인되어 한 번도 쓰지 않은 계정은 검색에 나오지 않고, 검색은 결과가 제한되며, 닉네임은 유일하지 않고 바뀔 수 있다. **닉네임 검색이나 공개 전적(가입 시각·승패·최고점) 비교는 계정을 식별하는 근거가 되지 못한다**(색인 누락·검색 제한·닉네임 변경·동명이인에서 다른 사람에게 요청이 갈 수 있음).

**A4(#127 검토 반영)의 동작:** 서버가 계정 ID와 친구 코드의 대응을 **보증**해 주는 경로가 없으므로 클라이언트는 **아무것도 조회·추정·전송하지 않는다.** 경기 중 프로필과 "최근 대전 상대"는 "친구 요청은 상대의 친구 코드로 보낼 수 있어요. 친구 화면에서 코드를 입력해 주세요 + 친구 화면 열기"만 안내한다(친구 추가 버튼·친구/대기/차단 상태 표시 없음 — 추정한 상태도 보여 주지 않는다). 친구 화면의 코드/정확한 닉네임 검색은 기존 그대로.
상태 기계(`src/social/friend-relations.ts`)는 완성돼 있고 가짜 "검증 어댑터"로 테스트한다. 서버가 아래 계약을 제공하면 `liveApi`에 `relationByUserId`만 연결하면 버튼·상태 표시가 켜진다.

**계약 후보 A (권장):** `GET /api/me/friends/relation?userId=…` → `{ relation: "self"|"friend"|"incoming"|"outgoing"|"blocked"|"none", code, nickname }`. 서버가 `userId`↔`code`를 직접 결합해 응답하며(검색·추정 없음), 상대가 나를 차단한 경우는 `none`과 구분되지 않게 한다. 색인되지 않은 계정은 서버가 즉시 코드를 만들어 응답.
**후보 B:** `POST /api/me/friends/request { userId }`(서버가 코드로 변환). 응답·한도·차단·중복 규칙은 기존과 같다.
**후보 C:** 계정 생성(로그인) 시 친구 코드 자동 등록.
**클라이언트가 이미 충족하는 요구(계약 구현 시 그대로 사용):** 관계는 보내기 직전에 다시 조회, 진행 중 재탭 무시, 친구·대기·차단·본인은 전송 금지, **계정 격리**(캐시·진행 중 조회·진행 중 요청이 계정 단위이며 전환·로그아웃 시 폐기, 이전 계정의 늦은 응답은 표시·캐시·반영하지 않음 — `tests/friend-relations.test.ts`). 보안 메모: 계정 ID 기반 요청은 `members`(방 안 상대)·본인 서버 기록의 ID로만 허용해 열거 위험을 늘리지 않는다. C4.2의 친구 관계·회원 탈퇴 보안 수정과 함께 설계.

## 2. 대표 업적 서버 저장
**현재:** 이 기기 `localStorage`(`yachtlab.profile-pins.v1`), 최대 3개, 프로필 화면에서만 보임. `PinStore`(`load`/`save`) 인터페이스 뒤에 있어 서버 저장소를 바꿔 끼우면 UI는 그대로.
**후보:** `PUT /api/me/profile/pins { ids: string[] }`(≤3, 서버가 달성 목록으로 검증, 숨김 업적 허용 여부 결정 필요), `GET /api/me/economy` 스냅샷과 공개 프로필(`/api/profiles/:id`, `/api/me/friends/profile`)에 `pins: string[]` 포함. 응답에 라벨이 아니라 **업적 ID**만(라벨은 클라이언트 `achievementById`). 계정 삭제 시 함께 삭제. 다른 사람에게 보이게 하는 범위(전체/친구만)는 정책 결정(C4).
**미리보기(구현됨):** 프로필의 3칸 슬롯이 "이 기기에 저장돼요 · 다른 사람에게 보이게 하는 기능은 준비 중"으로 안내한다.

## 3. 그 밖의 메모
- 최근 대전 상대 목록은 `GET /api/me/records`(서버 검증 기록의 `opponent.userId`, 회원 상대만)에서 만든다. 손님·AI는 계정이 없어 친구 추가 대상이 아니다. 별도 API 불필요.
- A3(경기 종료 화면)는 `src/social/FriendRequestButton.tsx`를 그대로 import해 `userId`만 넘기면 같은 동작(상태 표시·중복 방지·차단 존중)을 쓴다.
