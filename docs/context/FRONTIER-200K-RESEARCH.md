# v3.3–v4 SOTA 후보 연구 및 200,000–1,000,000경기 단계별 독립 검증

> Nintendo Yacht **12카테고리**. 기존 v2는 배포 기준선으로 유지. 연구 후반 능력, 학습 결과, 실제 전체 12라운드 승리점수율과 계산시간을 분리 검증한다.

## 기존 실험에서 확인된 문제

- v3 대비 v3.1: 50,000경기에서 평균 차이 **0%p**, 승패가 달라진 시드쌍 **2/25,000**. 마지막 턴 정확 BR 개선이 극히 드물다는 뜻이다.
- v3 vs v2: 50,000경기 승리점수율 **50.3190%**, 사전 계획 99% CI 50.1429–50.4951%. 작은 차이의 재현과 다양한 상대 강건성은 아직 검증해야 한다.
- 기존 점수판 조건부 PMF: Win DP v2 상대 holdout CRPS가 Gaussian **17.8672**, 조건부 **17.8908**로 악화되었다. 조건부라고 무조건 좋은 것이 아니다.
- 기존 PSRO 후보 vs v2 2,400경기 **49.438%**, 3시드 PPO+DP KL 정책 vs v2 1,800경기 **50.069%**. 연구된 방법 자체가 개선을 증명하지 않는다.

## 단계별 모델

| 연구 후보 | 실제 구현 | 검증·위험 |
|---|---|---|
| v3.3 | `src/research-v33.ts`: 이름을 아는 상대에 한해 독립 정책조건부 scorecard PMF 또는 calibration Gaussian 선택. `scripts/train-v33.mjs`가 서로 다른 훈련 800 / 선택 300 / 미사용 시험 300경기를 두 상대(v2,v3) 각각 수집해 **validation CRPS만으로** 모델 선택; v2 선택에서 실패하면 raw v3.1 폴백 | test CRPS 악화도 기록. 정책 불일치·다른 상대에서는 모델 적용 금지 |
| v3.4 | `src/research-v34.ts`: 공개 상태만으로 독립 합성 주사위 난수를 생성, 마지막 2~3턴에서 현재 행동 후 실제 상대 정책(v2, v3, DP)의 대국 전체를 표본 기반으로 추적. 복수 상대일 때 worst-case 예상 승리점수율을 탐색. 정확 완전 Minimax가 아닌 **chance-sampled policy-aware finite-horizon expectimax** | 단위/판단 지연 시간은 독립 대국으로 기록. 표본수·상위 후보 제한, 각 종합본에서 느리면 우수 모델로 승격 불가. 현재 기본 설정은 후반 두 턴만 사용, 세 턴은 옵션으로 지원 |
| v4 | `src/research-v4.ts`: 초반부에 DP Q와 12차원 residual policy, 중반까지 full-game 승패 보상 REINFORCE + DP teacher imitation + PSRO league/snapshots, 후반에는 v3.3/34. `scripts/train-v4.mjs`의 3 독립 초기화×3,000 완결경기. `scripts/select-v4.mjs`로 **validation만으로** 한 시드 선택 | 소규모 경량 residual actor이지 MuZero나 신경망 대형 SOTA가 아님; full-game self-play RL 및 DP teacher policy imitation을 결합한 v4 후보 |

모든 v3.3/34/4 로직은 **연구 모듈**이며 `src/ai.ts`나 배포 AI 셀렉터에서 자동 활성화하지 않는다.

## 검증 실행

[`frontier-200k.yml`](../../.github/workflows/frontier-200k.yml) — PR에서는 smoke test만; main에서는 새 모델을 **훈련 → freeze → 모델당 20만 경기** 평가한다.

- v3 (기존 대조): 200,000경기
- v3.3: 200,000경기
- v3.4: 200,000경기
- v4: 200,000경기
- **모든 후보 각각 100,000개 초기 시드 × 선후공 교대 = 200,000경기, 총 800,000경기.** 상대 Win DP v2.
- 각 후보 공통 시드 `1301…1320` 20개 shard × 5,000 seed pairs(=10,000경기). 후보 간 짝별 delta 및 실제 바뀐 승패 수, 99% 근사 CI, 평균 판단시간 등 저장.
- 동작시간이 느린 v3.4/v4를 포함하므로 워크플로에는 명시적인 180분 job 제한과 8개 작업 동시실행을 걸어 놓음. 제한 초과·예산 부족이면 결과를 성공으로 꾸미지 않음.
- 실험 결과를 보고 모델 가중치나 알고리즘을 변경할 경우, 이 seed 군은 더 이상 미사용 최종 확인 집합이 아니다.

### 100만 경기 계획

워크플로의 수동 `workflow_dispatch`에서 `scale=1000000`, `candidate`를 택하면 **한 후보당 100개 shard × 5,000 쌍 × 2자리 = 1,000,000경기**를 실행한다. 시드군은 `1401…1500`으로 기존 20만 실험과 분리된다. 동시에 4개 후보를 비교하는 400-job matrix를 만들지 않고 **한 후보를 미리 지정**해 GitHub Actions matrix 제한과 자원을 관리한다.

**비용/위험:** 20만 전 후보 80개 job, 100만 후보당 100개 job + 훈련·메타리그. v3.4는 MC 대국 탐색에 따른 추론 부하가 매우 커질 수 있어 예비 실험의 실제 판단시간과 Actions 사용량을 확인해야 한다. GitHub Actions 사용량/할당량과 작업시간 초과 가능성 있다. 증거를 통과하기 전 자동 100만 실행 금지.

## 성과 평가

- 200,000경기 자체만으로 SOTA 확정 금지. v2뿐 아니라 DP Expert와 외부 독립 구현 대결 및 계산량 대조 필요.
- winCredit(승리=1, 무승부=0.5), 선후공 묶음 샘플(각 2경기당 1관측), 통계적 CI와 매치 시드 중복 검사.
- v3/v3.3/v3.4/v4는 같은 시드에서 **실제 최종 결과의 차이**를 분석. 행동이 많이 달라졌다는 점만으로 성능 향상을 주장하지 않음.
- 99% per-comparison 근사 CI, 반복 탐색/복수 후보 선택에 대한 추가 보정 및 fresh final holdout 필요.
- latency, 행동 정확성·공개 정보 불변, inference 메모리 비용, 실패 CI도 영구 보고.
