# 대규모 독립 재확인 및 v3.2–v4 연구 로드맵 (2026-11-21)

## 목표와 주의

- **행동 변화 != 전체 게임 승률 개선**. 이전 v3.1은 68,641번 중 정확 BR 조건에서 추가 행동 변경 3번, 그 시드의 승패 변화 0번. 개선은 정확 국소 최종턴 1대1 고정 상대에 대해서만 엄밀하다.
- 기존 v3 vs v2 상대 독립 2,000경기 50.275%, 이후 다른 2,000경기 49.725%. 이 숫자는 그대로 합치면 50.000%지만 이 작은 표본으로 동등성 증명 불가.
- 연구 규칙은 **Nintendo Yacht 12개 카테고리**. 미국식 13개 Yahtzee의 기성 SOTA와 수치 직접 비교 금지.
- Win DP v2는 정량적 승률 개선의 기존 검증 기준선. 웹 AI를 자동으로 바꾸지 않는다.

각 조건은 별도 5,000 시드 쌍 × 지정된 5개(또는 2개) shard: 1001–1005. 상대가 알려져 있을 때만 조건부 BR 적용. 모든 실험의 코드 커밋/시드/승점/결정·변경 수/지연시간 저장. 경기 로그의 원본 전체 행동 sequence 대신 짝별 최종 결과와 주요 계수를 압축 보존해서 규모를 감당한다.

5개의 계획된 대조(4개의 상대별 승점률과 v3.1−v3 동일시드 차이)의 양측 99% 근사 CI; Bonferroni 가족 오류율 5% 이하의 단순 기준. 반복적으로 보고 멈추는 순차 선택이나 후속 하이퍼파라미터 조정은 별도 통제한다. **CI가 영을 포함한다는 것은 동등성 증명이 아니며**, 전혀 달라진 승패가 없는 경우 표본 안에서 차이 0이라는 뜻일 뿐이다.

실험으로 무엇을 입증하려는지:

1. v3의 3칸 계획이 v2보다 실제로 유리한가?
2. v3.1 마지막턴 BR 추가가 **v3와 동일 시드에서** 전체 승점률을 높이는가?
3. v2.1 단독은 분명한 국소 행동 개선에도 실제 게임에서 거의 드물게 유익한가?
4. 상대 v3로 바뀌면 강건한가? 그리고 판단 시간 비용이 실용적인가?

실행 성공 후 [자동 대규모 보고서](./_generated/V31-LARGE-LATEST.md). 검증 실패하면 마지막 정상 모델 보존.

## 다음 연구: 성능 향상을 주장하기 전 필요한 엔진 작업

| 가칭 | 정확히 무엇을 개선할까 | 반증 실험 |
|---|---|---|
| **v3.2** | 상대가 DP Expert일 때 남은 3카테고리의 **정확한 정책조건부 최종 점수분포** 계산; v3 Gaussian 오차 제거 | PMF 총합 1, 기대값 DP와 동일, independent v2/v3/DP Expert 상대 직접 대결, 시간/메모리 |
| **v3.3** | 실제 상대(v2/v3)의 점수판·차례·위험수용 정책을 고려하는 **policy-conditional** PMF와 원래 Gaussian을 비교; 경험 PMF가 CRPS 나빠진 사례 보완 | CRPS/NLL/Brier + 직접 승률, 누수 없는 훈련/홀드아웃 분리, 캘리브레이션 |
| **v3.4** | 마지막 2~3턴에서 상대 행동을 인지하는 expectiminimax/finite-horizon stochastic game; 높은 분기 비용은 캐시·upper-bound pruning | 기존 정확 1턴 BR과 수치 교차검산, 2턴 소규모 brute-force, 시간/메모리, 2만 경기 이상 독립 대전 |
| **v4** | 위 솔버를 교사로 삼는 Expert Iteration, policy/value neural distillation, chance-aware MCTS, PSRO 자기 대국 앙상블 | 결과가 단순 DP/기존 v2보다 승률을 올리는지 동일 계산 예산, 복수 상대·시드에 대해 검증 |
| **v4+** | 불확실성의 영향을 받는 국면만 선택하는 adaptive compute, gap-based local certificate, 상대 불확실성에 강건한 혼합 정책 | wall-clock/CPU·방문 수 대비 승률 파레토 및 순차 비교 |

**SOTA의 의미:** 위 모든 것은 현재 게임 규칙에서의 독립 재현 가능한 **비교 모델 최고 성능** 후보이며, 전체 게임의 Nash 정책이나 외부 연구 전체를 이겼다는 뜻이 아니다. 강력한 상대를 충분히 폭넓게 포함하고 성능이 불확실한 결과도 모두 보존해야 한다.

참고 연구: Glenn (2007) stochastic Yahtzee score-distribution, Pawlewicz (2010) multiplayer opponent response, 2026 RL benchmark. Yahtzee룰이 다르면 공정한 직접 수치 대결이 불가하므로 아이디어만 참고한다.

**승격 원칙:** ① 수학적/결정성·공개상태 테스트 → ② 개발 시드 → ③ 사전 고정 홀드아웃 및 다양한 상대 → ④ 같은 CPU 지연/메모리, 정상 배포·롤백 → ⑤ 사람 승인 후 공개 AI 추가/기본값 변경.
