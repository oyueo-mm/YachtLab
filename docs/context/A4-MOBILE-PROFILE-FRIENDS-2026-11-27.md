## 2. 모바일 (320px ~ 태블릿)
- **감사:** 14개 화면 × 7개 크기(320×568, 360×740, 360×800(S21), 390×844, 412×915, 768×1024, 820×1180)에서 가로 넘침·잘림 자동 점검(서버 없는 상태): 변경 전후 모두 문제 0. 실제 방은 로컬 Worker로 별도 측정(아래).
- **1인 플레이(≤560px):** 요약+도구 높이 162px→101px, 게임판이 90px 위로(보너스 줄 포함). 점수·최고·라운드는 한 줄, 기보·다시 시작은 44px 아이콘 버튼(라벨은 `aria-label`/`title`), "최고 기록"→"최고". 데스크톱은 A2 레이아웃 그대로.
- **2~4인 점수판(≤760px):** 이전에는 4인에서 점수판이 **가로로 약 220px 스크롤**(내 열만 보임). 이제 모든 플레이어 열이 폭 안에 고정 표 레이아웃으로 들어가고(스크롤 0, 320px 포함) 점수판이 **게임판 바로 아래**, 순위 목록은 그 아래. 행은 38px(점수 버튼 34px+여백, 터치 가능), 아이콘·도움말 아이콘 제거, 헤더에 닉네임(말줄임)·순위·차례, 상단 제목 제거. 태블릿(768)은 데스크톱 규칙 그대로 스크롤 0.
- **뷰포트:** `100vh` 대신 동적 뷰포트 단위(`dvh`, 지원 시)로 주소창·PWA 크롬 변화에 맞추고, PWA(standalone)에서는 하단 안전영역 패딩. 뷰포트 메타에 `viewport-fit=cover`는 추가하지 않았다(노치 기기 실측 불가).
- **검증:** `tests/ui/a4-mobile.spec.ts` — 실제 로컬 Worker 2/3/4인 방, 5개 크기(320·360·S21 360×800·390·768): 점수판 열이 모두 보이고 가로 스크롤 0, 굴림 버튼이 화면 안. 스크린샷 `docs/ui/a4-mobile/{before,after1}-online4p-*`, `*-solo-*`.

## 3. 프로필
- **장착 중:** 슬롯마다 강화 단계 막대(●●○)+`Lv.n`(스크린리더용 "강화 2단계/최대 3단계"), 등급별 좌측 색 띠, 모바일 2열.
- **보유·컬렉션:** "N개 보유 · M개 강화 · K개 최대 강화" 요약 추가, 기존 카테고리별 수집률·테마 컬렉션 유지(모바일 2열).
- **전적·기록:** 승/패/무 배지 색 구분, 점수줄(내 점수 : 상대 점수, 큰 글자)+상대 닉네임 말줄임, 모바일 KPI 2열·큰 숫자, 320px 가로 넘침 수정(flex `min-width:0`).
- **대표 업적:** 3칸 슬롯 UI(채움/비어 있음, 눌러 해제) + 달성 업적에서 고르기, 네 번째는 가장 오래된 것을 대체. 저장은 이 기기만이며 `PinStore` 인터페이스 뒤라 서버 저장으로 교체 가능, 안내 문구로 "다른 사람 표시는 준비 중". 서버 API는 계약 후보로만 작성.
- 검증 `tests/ui/a4-profile.spec.ts`: 5개 폭(320/360/390/768/1280) 가로 스크롤 0·레벨 막대·보유 요약, 슬롯 동작과 새로고침 유지. 전후 스크린샷 `before-profile-*`, `after-profile-*`.

## 4. 친구 추가 UX (PR #127 검토 반영: 추정 금지)
- **안전 규칙:** 친구 요청은 **서버가 계정 ID와 친구 코드의 대응을 보증한 사람에게만** 보낸다. 기존 Worker는 그런 대응을 제공하지 않으므로(코드는 계정 ID에서 유도되지 않음, 색인 누락·검색 제한·닉네임 변경·동명이인) 클라이언트는 **닉네임 검색이나 공개 전적 비교로 사람을 고르지 않고, 아무것도 조회·전송하지 않는다.** 처음 구현했던 "닉네임 정확 검색 + 동명이인은 공개 수치 비교"와 `ensureSelfRegistered`는 제거했다.
- **현재 화면:** 경기 중 상대 프로필(`OpponentProfileDialog`, 기존 `OnlineGame` 내부 함수를 추출)과 친구 화면 "최근 대전 상대"(서버 검증 기록의 회원 상대, 최대 5명)는 "친구 요청은 상대의 친구 코드로 보낼 수 있어요 · 친구 화면 열기"를 안내한다. 친구/대기/차단 같은 상태도 추정해서 보여 주지 않는다.
- **공용 컴포넌트와 상태 기계:** `FriendRequestButton`·`friend-relations.ts`는 완성돼 있고(친구 추가/대기/이미 친구/상대가 먼저/차단 표시, 중복 방지, 보내기 직전 관계 재확인), 서버가 검증된 조회(`relationByUserId`)를 제공하면 어댑터 한 곳만 연결하면 켜진다. **A3 결과 화면은 그대로 import해 `userId`만 넘기면 같은 동작**(지금은 같은 안내).
- **계정 격리:** 관계 캐시·진행 중 조회·진행 중 요청은 로그인한 계정 단위. 계정 전환·로그아웃 시 폐기하고 이전 계정의 늦은 응답은 표시·캐시·반영하지 않으며, 확인 중 계정이 바뀌면 요청을 보내지 않는다. "최근 대전 상대" 목록도 계정이 바뀌면 비우고 다시 불러온다.
- **검증:** Vitest 21(`tests/friend-relations.test.ts`) — 검증 기능이 없으면 호출·전송 0, 검색 결과 1명/동명이인(수치 동일)/색인 누락·다른 사람만 나옴/검색 한도(10명)/liveApi 모두 전송 0, 검증된 어댑터의 상태 기계(보냄·동시 탭·친구·대기·차단·본인·엇갈림·오류·캐시), 계정 전환(캐시 폐기·진행 중 조회 폐기·새 계정과 섞이지 않음·확인 중 전환 시 전송 없음·전송 후 늦은 응답 무시·로그아웃), 소스에 검색/공개 프로필 호출이 없음. Playwright `a4-friends`(격리 로컬 Worker 실계정 2명, 둘 다 색인된 상태에서도): 양쪽 프로필에 버튼·상태 없이 코드 안내만, 서버에 요청 0건, 최근 대전 상대에서 계정을 바꾸면 이전 계정의 목록(느린 응답 포함)이 섞이지 않음.
- 서버 계약(관계 조회/ID 기반 요청)은 C4.2와의 통합 후속 작업으로 [계약 후보 문서](./A4-CONTRACT-CANDIDATES-2026-11-27.md)에 남겼다.

## 6. 검증 요약 / 남은 문제
- 신규 테스트: Vitest `friend-relations` 21, Playwright `a4-friends` 2, `a4-profile` 11(폭 5 + 슬롯 + 가이드 3 …), `a4-mobile` 15(2/3/4인 × 5크기). 기존 모바일·프로필·경제·온라인 스펙 152개 통과(변경 중 점검).
- **iOS WebKit 미검증:** 이 환경에서 WebKit을 내려받을 수 없어(`playwright install webkit` 실패) 실행하지 못했다. 사용한 CSS는 Safari 15.4+ 기능(`:has`, `dvh`, `display: contents`)이며 `@supports`로 가드한 부분은 가드했다. 후속 QA에서 iOS Safari/PWA 실기기 확인 필요.
- 실기기 미검증(안드로이드 Chrome 주소창 동작, PWA 안전영역). 갤럭시 S21은 360×800(DPR 3) 에뮬레이션.
- 모바일 1:1·관전 화면의 점수판은 기존 "점수판 보기" 시트 방식을 유지(이번 범위 밖).
- 경기 중 친구 요청은 서버 계약(관계 조회/ID 기반 요청) 전까지 **켜지지 않는다**(안내만).
- **PR/CI:** PR #127. `onboarding.spec`의 "정적 첫 화면 여백"은 개발 서버에서만 실패(앱 진입 파일을 막으면 CSS도 빠짐)하며 main의 `main.tsx`로도 동일 — 빌드+preview를 쓰는 CI 결과를 따른다. 결정 D-091~093은 병렬 PR과의 병합 충돌을 피하려고 `DECISIONS.md` 중간(D-087 뒤)에 두었다.
