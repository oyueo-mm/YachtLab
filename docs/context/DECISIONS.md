## D-001. 게임 규칙은 닌텐도식 12칸 Yacht Dice

**상태: 유지.** 주사위 5개, 턴당 최대 3회 굴림, 12카테고리(1~6, Choice, Four-of-a-kind, Full House, Small Straight, Large Straight, Yacht), 상단 ≥63점 +35점. 포커: 4개 이상 같으면 주사위 합. 풀 하우스: 정확한 3+2, 다섯 개 같은 눈은 해당하지 않음. 스몰/라지: 15/30, 요트 50. 미국식 13칸 Yahtzee와 섞지 않음.

**근거:** src/engine.ts, training/dp/README.md.

## D-002. 연구 목표를 단독 점수와 경쟁 승률로 분리

**상태: 유지.** 단독 게임 DP Expert는 공정 독립 난수 규칙에서 최대 기대점수 솔버. 최초 기대점수 191.760879752165. 2인전은 승리 1·무승부 0.5·패배 0의 승리 점수율. 기대점수가 높은 정책이 반드시 승률 높은 정책은 아님.

**근거:** src/dp.ts, src/win-dp.ts, src/competitive-v2.ts.

## D-003. 강한 기존 모델을 보존하고 경쟁형 후보를 별도로 추가

**상태: 유지.** DP Expert, Win DP(v1), Win DP v2를 별도 이름으로 유지. v1은 마지막 1개, v2는 마지막 2개 카테고리의 경쟁 목적을 반영. 기존 DP 테이블이나 PPO 학습 가중치를 근거 없이 덮어쓰지 않음. 연구용 MCTS와 QR-DQN Choice는 성능이 미입증이라 기본 AI 목록에서 제외.

**근거:** src/ai.ts, src/competitive-v2.ts, docs/INTEGRATED-RESEARCH.md.

## D-004. 난수 예측 누출 금지

**상태: 매우 중요.** Game 구조에 seed/rng 필드가 있지만 경쟁 AI의 결정이 미래 눈을 예측하도록 이용하면 불공정함. 현재 연구용 에이전트는 공개 주사위/카드 상태를 사용하도록 작성되었지만 **게임 상태 전달 경계에서 개인 RNG·seed를 제거하는 구조적 개선**은 후속 보안·공정성 과제. 테스트에서 시드/PRNG를 바꿔도 결과가 동일해야 하는 경우를 검증.

**근거:** src/engine.ts, src/competitive-v2.ts, tests/dp.test.ts.

## D-005. 승률 비교는 동일 규칙·선후공 교대·홀드아웃

**상태: 유지.** 동일 시드에 대해 선후공을 뒤집은 두 경기의 승리 점수율 평균을 하나의 paired observation으로 본다. 약 95% 정규 근사 CI를 계산하고 원시 대국 로그를 아티팩트로 보관. 시드 재사용·선택 편향·다중 후보 비교를 최종 증명으로 과대평가하지 않음. 같은 초기 시드여도 행동에 따라 소비 난수 수가 달라지므로 **매번 동일한 주사위 경로**가 아님.

**근거:** scripts/research-competitive.mjs, scripts/confirm-v2.mjs.

## D-006. 상대 모델은 가정된 정책임을 표시

**근거:** src/win-dp.ts, src/competitive-v2.ts.

**상태: 신규.** GitHub Push/정기 갱신에 따라 버전, 알고리즘 이름, 점수 카테고리, 커밋, 문서·워크플로 링크를 자동 인덱싱한다. 연구 내용의 해석이나 새 채팅 대화 내용은 AI 환각 없이 자동 생성할 수 없으므로, 검증된 RESULTS/ROADMAP/DECISIONS은 변경 PR을 통해 유지한다. GitHub Wiki는 **옵션 미러**이며 원본 저장소 문서가 source of truth.

## D-010. 온라인 대전은 서버 권한형·이벤트 소싱 엔진, 매치 상태에 RNG 미저장

**상태: 신규 (Online v0.1 Phase 1, 2026-11-22).** 온라인 경기에서는 클라이언트가 주사위·점수를 계산하지 않고, 서버 엔진(`src/online/`)이 명령을 검증해 이벤트를 만들고 단일 리듀서로 상태를 갱신한다. 점수 규칙은 `src/engine.ts`를 재사용(D-001). 주사위는 주입된 CSPRNG(`crypto.getRandomValues` + 거부 샘플링)에서 뽑고 seed/PRNG 상태를 매치 상태·뷰·로그에 저장하지 않는다(D-004 강화). 명령의 `playerId`는 인증된 연결에서만 받는다. `(playerId, commandId)` 멱등성과 `expectedVersion` 낙관적 동시성을 적용하며, 멱등성 키는 이벤트의 `by`에서 유도해 로그만으로 재시작 후에도 복구된다. 저장된 로그는 엔진 재실행으로 감사하되, 이는 **규칙 위반 탐지**이며 규칙상 가능한 위조(꾸며낸 눈, 꼬리 절단, 서명 없는 출처)의 진위 증명은 아니다 — 필요 시 HMAC 해시 체인·외부 anchoring·서명·검증 가능 난수를 별도 도입. 기존 로컬 엔진·AI·리플레이 형식은 변경하지 않는다. 클라우드 리소스 생성·유료 기능·실제 배포는 별도 승인 전까지 하지 않는다.

**근거:** src/online/, tests/online-engine.test.ts, [Online v0.1 Phase 1 설계](../online/ONLINE-V01-PHASE1.md).

## D-012. 규칙 확장은 규칙 ID@버전으로 분리하고 12칸을 기본값으로 고정

**상태: 설계만 (미구현).** 미국식 13칸 계열을 추가하더라도 기존 12칸 엔진·DP·AI·기보 해석은 바꾸지 않는다. 규칙은 `rulesetId@version`으로 구분하고, 기존 기보의 `ruleVersion`(`YachtLab-12-v1/v2`)은 재해석하지 않으며, 규칙 간 교차 재생과 성능 수치 혼합을 금지한다. AI는 지원 규칙 매니페스트로 호환성을 명시한다. 자세한 내용은 [규칙 확장 설계](../rules/RULESET-EXTENSION.md).

## D-013. 게임 시작 전 상세 설정, 게임 중에는 환경설정만

**상태: 신규 (2026-11-23).** 오프라인 대전은 홈 → 오프라인 → 모드 → **상세 설정** → 게임 순서로 진입한다. 난이도·이름·선공·인원·시작 순서·규칙은 설정 화면에서만 바꾸고, 게임 중 톱니바퀴는 효과음·음량·주사위 품질·모션 간단히만 제공한다. 설정값은 브라우저에 저장되며 `#play` / `#pvp` 직접 주소는 마지막 설정으로 게임을 연다. 선공 선택은 엔진을 바꾸지 않고 좌석 배치로 구현한다(먼저 하는 플레이어 = 좌석 0). 진행 중 경기를 포기하는 동작(홈·재대결·설정 변경)은 확인을 거친다.

## D-014. 3D 물리 주사위는 결과를 바꾸지 않는 연출, 2.5D는 대체 경로로 유지

**상태: 신규 (2026-11-23).** 주사위 눈은 엔진(향후 서버)이 결정하고, 3D는 cannon-es 사전 시뮬레이션 + 큐브 대칭 면 배치로 그 값에 정확히 착지하도록 표현한다(마지막 프레임 눈 교체 금지). three.js·cannon-es는 지연 로드 청크. WebGL 불가·저사양·동작 줄이기·착지 품질 실패 시 2.5D 또는 무모션으로 대체하며 2.5D 구현은 삭제하지 않는다. 검증 수치는 [3D 주사위 문서](../ui/DICE-3D.md).


## D-015. AI 모델은 단일 레지스트리에서 실행 가능성을 근거로 분류

**상태: 신규 (2026-11-23).** 지금까지 구현한 AI·연구 모델을 `src/model-catalog.ts`(메타데이터)·`src/ai-models.ts`(결정 함수)·`src/model-ids.ts`(ID)에 등록한다. 분류는 A 대전 가능 / B 조건부(조건·대체 정책 표시) / C 연구 전용(선택 불가)이며, 전체 대국·합법성·비공개 seed/RNG 미사용 테스트(`tests/ai-models.test.ts`)를 통과한 모델만 선택 가능하다. 사람 상대에서 상대 모델은 `Other`로 가정한다. 기존 11개 모델과 5단계 난이도 매핑은 바꾸지 않으며, 검증되지 않은 연구 모델을 일반 난이도로 승격하지 않는다. 상세: [모델 전수 조사](../ai/MODEL-REGISTRY.md).

## D-016. 3D 주사위는 자유 착지 + 고정 선반, 진행 중 경기는 브라우저 이동도 확인

**상태: 신규 (2026-11-23), D-014 보완.** 게임의 3D 주사위는 물리 정지 위치·회전을 유지하고(정렬·2D 교체 없음), 고정한 주사위만 트레이 아래 선반으로 옮긴다. 결과는 여전히 엔진이 결정하며 면 배치 방식(D-014)을 유지한다. 브라우저 뒤로·앞으로·해시 변경도 진행 중 경기에서는 확인을 거치고, 취소 시 히스토리를 반대 방향으로 한 칸 되돌려 중복 항목을 만들지 않는다.


## D-017. 족보 완성 연출은 엔진 밖의 표시 계층

**상태: 신규 (2026-11-23).** 점수 기록 시 족보를 이루는 주사위(`src/combo.ts`, id 기준·결정적)만 3D로 솟아오르는 연출을 `src/score-fx.ts` 이벤트로 구현한다. 점수 계산과 기보는 엔진이 그대로 담당하고 연출은 값을 바꾸지 않는다. 0점은 연출 없음, 포커는 네 개 강조·점수는 다섯 개 합계. 연출 동안 입력·AI 던지기를 잠그며 점수 명령은 한 번만 실행된다. WebGL이 없거나 동작 줄이기면 간소화(정적) 연출.

## D-018. 무광 게임 테이블과 `vigorous` 던지기 프로필

**상태: 신규 (2026-11-23), D-014/D-016 보완.** 게임판은 무광 차콜 단색, 그림자는 보드 외곽 1개 + 주사위 접지 그림자만 허용한다(그림자 맵·글로우·그라데이션 금지). 던지기는 `THROW_PROFILES.vigorous`를 기본으로 하되 `legacy`를 남겨 회귀·비교 측정에 쓴다. 결과(눈)는 여전히 엔진이 결정하고 물리는 표현만 한다.

## D-019. 모바일 AI 대전은 주사위판을 우선 노출하고 족보 연출은 작게 표시

**상태: 신규 (2026-11-23).** 화면 폭 760px 이하에서 사람 vs AI 화면은 주사위판·굴리기 → 모바일 점수판 버튼 → 점수 요약 → 기보·재대결·설정 변경 순서로 재배치한다. 게임판의 중복 정보(나의 차례/굴림 횟수)는 숨기지만 점수 요약의 현재 플레이어 강조와 굴리기 버튼의 남은 횟수는 유지한다. 3D 족보 연출은 모바일에서 상승 높이와 확대 비율을 줄이고 데스크톱은 기존 값을 유지한다. 로컬 사람 대전은 차례 확인이 중요하므로 화면·표시를 바꾸지 않는다. 게임 엔진·기보·AI 정책은 변경하지 않는다.

## D-020. 온라인 Phase 2: 방 단위 직렬 처리 + 좌석 토큰, 클라이언트는 확정 이벤트만 렌더

## D-023. 고정 순서는 표시 상태, 온라인에서는 서버가 공유 / 온라인 대전을 홈 메인으로

**상태: 신규 (2026-11-23).**
- **홈:** 온라인 대전이 첫 번째 강조 카드(CTA "친구와 대전하기", 모바일에서도 표시), 오프라인 대전은 두 번째 보조 카드. "준비 중" 표기는 없앴고, 서버 주소가 없는 빌드(로컬 미리보기)만 "온라인 서버에 연결되어 있지 않아요"를 보여 준다.
- **고정 순서:** 고정 선반의 자리는 엔진의 `order`가 아니라 **선택 순서**(`src/hold-order.ts`)로 정한다. 새로 고정한 주사위는 맨 뒤, 해제하면 그 주사위만 빠지고 나머지 순서 유지, 다시 고르면 맨 뒤, 재굴림에도 유지. 주사위 값·`held`·엔진 `order`는 바꾸지 않는 표시 전용 상태다. 오프라인은 `DiceArea`가 `held` 변화에서 추적하고, 온라인은 서버 값을 받는다.
- **온라인 화면 동기화:** 방(`OnlineRoom`)이 현재 턴의 고정 순서(`HoldState {playerId, keep, n}`)를 엔진 로그 **밖의 공유 표시 상태**로 가진다. 차례인 사람의 `hold` 메시지(순서 보존, 보낸 사람 포함 전원에게 전달, `n`으로 자기 메아리 구분)와 `roll` 명령의 `keep` 순서로 갱신하고, 새 턴·종료 시 비운다. 모든 `view`/`welcome`에 포함되며 레코드에 들어가 **다음 명령과 함께 저장**(추가 행 쓰기 없음). 엔진의 `kept`는 정렬된 집합 그대로라 이벤트 로그·감사·RNG는 바뀌지 않는다. 온라인 행 순서는 id 순 고정이고 드래그 재정렬은 끈다. 3D 물리 궤적·착지 위치는 화면마다 다를 수 있으나, 끝난 뒤의 눈·ID·고정 여부·고정 순서·굴림 수는 같다.
- **호환성:** 서버는 새 필드만 추가(구 클라이언트는 무시), 새 클라이언트는 `hold`가 없는 구 서버에서도 동작 → **서버 먼저 배포, 그다음 프런트**.
- **초대 링크:** 기존 Pages URL `https://oyueo-mm.github.io/YachtLab/?room=CODE#online`을 그대로 쓰고, 링크로 열면 그 방 전용 입장 화면(저장된 닉네임 자동 입력, "입장하기" 한 번)으로 간다. 없는 방·정원 초과·진행 중·종료를 안내하고, `#online`이 빠진 링크도 온라인 화면으로 연다. URL에는 방 코드만 있고 좌석 토큰은 없다. 코드 입력 방식도 유지.
