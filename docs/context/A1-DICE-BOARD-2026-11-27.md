## 1. 주사위 물리 (상세: [DICE-3D §8](../ui/DICE-3D.md))

- 새 기본 프로필 `impulse`: 실시간 재생(배속 1.25 → 1.0), 출발 시 겹침 제거(이전엔 던질 때마다 평균 10회 0프레임 충돌), 진행 방향으로 구르는 초기 회전, 모서리 깎은 큐브, 바닥 접촉 중 구름 저항과 정지 마찰. 물리 최고 속도 +14~24%, 충돌 1.5~1.7배, 화면상 길이 중앙값 1.05~1.13 s(이전 1.11~1.13 s).
- 고정/해제: 포물선 들어 올림·진행 방향 기울임(≤7°)·내려놓을 때 눌림(`carryPose`).
- 보드 표면 충돌음(`SURFACES`): 같은 주사위라도 펠트·원목·대리석·얼음·금속·물·모래·풀·아크릴 위에서 다르게, 세게 칠수록 밝게.
- 주사위/킵 영역 hover 테두리 제거(선택·키보드 포커스 유지).
- 사람·AI 모두 같은 `PhysicalDice`/`DiceTable` 경로. 결과는 엔진 값을 정지 후 큐브 대칭으로 배정(변경 없음).

## 2. 보드판 강화 단계 — 전수 개편

원칙: **Lv.1** 테마 고유 외형·재질(CSS, 기존 유지) → **Lv.2** 굴리지 않아도 움직이는 환경 → **Lv.3** Lv.2 + 실제 충돌 위치·세기에 반응하는 국소 연출. 입자 수·밝기만 올리는 방식 대신 보드마다 절차적 장면을 새로 만들었다(`src/play/board-scene.ts`, 26종). Lv.3 반응의 크기·개수·반경은 물리 충돌 속도(주사위 변/초 ÷ 14, 0.25~1.3)를 따른다. 많은 반응이 **Lv.2 환경 자체를 바꾼다**(풀이 눕고, 바닥 꽃잎이 흩어지고, 대리석 결이 켜지고, 별빛이 휜다).

| 보드 | Lv.2 환경 | Lv.3 반응(충돌 위치·세기) |
|---|---|---|
| 그린 펠트 | 매달린 조명이 진자처럼 흔들리고 빛 속 먼지 | 펠트가 눌렸다 회복, 세게 치면 조명이 크게 흔들림 |
| 레드 펠트 | 두 촛불의 비동기 일렁임 | 눌림 + 촛불 흔들림 |
| 블루 펠트 | 당구대 조명 호흡 + 지나가는 하이라이트 | 눌림 + 주변 먼지가 밀려남 |
| 퍼플 펠트 | 세 색 조명이 돌아다님 | 눌림 + 조명 출렁임 |
| 베이지 펠트 | 블라인드 햇살 줄무늬 이동·구름 그늘 | 눌림 + 햇살 속 먼지 흩어짐 |
| 네이비 | 달빛 반짝이는 수면 길 | 물결 링(세기→링 수), 물결이 지나간 반짝임 증가 |
| 눈 내리는 선착장(시즌) | 2층 눈 + 위쪽 전구 체이스 | 눈 튐, 착지 자리 눈더미(서서히 녹음), 강타 시 전구 번쩍 |
| 원목 | 비스듬한 햇살 기둥 속 먼지 | 나뭇결 방향 타원 울림 |
| 월넛 | 촛불 + 가끔 불씨 | 나뭇결 울림 + 촛불 흔들림 |
| 브라운/블랙 가죽 | 광택 이동 + 바느질을 따라 도는 빛 | 눌림 + 가까운 테두리 바느질이 충돌 지점부터 빛남 |
| 대리석 | 결(망)을 따라 미끄러지는 빛 | 충돌 지점 근처 결로 빛이 번짐 |
| 바다 | 물결 빛 무늬(코스틱) | 물보라·물방울 + 물결이 빛 무늬를 휘게 함 |
| 사막 | 모래 물결 이동·모래바람·아지랑이 | 움푹 팬 자국, 모래 튐, 주변 모래 물결이 밀려남 |
| 얼음 | 가장자리 서리 고사리가 자랐다 줄어듦 + 냉기 | 강한 충돌만 금(세기→길이), 착지 자리 결정 |
| 우주 | 별·성운·가끔 유성 | 중력파가 퍼지며 별 위치가 휨 |
| 네온 | 회로를 흐르는 빛 신호 | 사각 전자기 파동, 지나간 회로 접점이 켜짐 |
| 오로라 | 옆으로 물결치는 빛줄기 커튼 | 커튼이 충돌 쪽으로 휨 + 분광 고리 |
| 황금 테이블 | 반사광 스윕 + 반짝임 | 녹은 금처럼 밝음/어둠 링 출렁임 |
| 심해 | 빛줄기·바다눈·기포 | 주변 플랑크톤 생물발광(거리·세기 비례), 기포 |
| 폭풍 번개 | 비·구름·마른번개 | 충돌 지점 방전(세기→가지 수·길이), 그을음, 강타 시 하늘 번쩍 |
| 초원 | 보드 전체 풀이 바람결 파도 | 충돌 반경의 풀이 바깥으로 눕고 스프링처럼 복원 |
| 꽃밭 | 흔들리는 꽃·꽃가루 | 멈춘 자리 개화, 충돌 주변 꽃이 흔들리며 꽃가루 |
| 벚꽃길 | 꽃잎이 떨어져 바닥에 쌓임 | 바닥 꽃잎이 충돌 지점에서 세기만큼 흩어짐 |
| 숲 | 나뭇잎 햇살 + 반딧불이 | 착지 자리 새싹·빛 링, 반딧불이가 놀라 흩어졌다 돌아옴 |
| 화산 | 균열을 흐르는 용암(점선 흐름)·불씨 | 강한 충돌만 균열(백열→주황→암석), 불꽃 |

기본 차콜(기본 무료)은 강화 단계가 없어 그대로(표면음만 `matte`). 펠트 5종은 같은 소재라 반응 원리(눌림)를 공유하되 Lv.2 조명 장면과 반응하는 대상이 다르다.

가독성: 보드 캔버스는 트레이 안, 주사위 캔버스·버튼 아래(z-index 0)이며 점수판·버튼·주사위 눈을 덮지 않는다. 균열·얼음 금은 살아 있는 개수를 5~6개로 제한하고 약한 충돌에는 그리지 않는다.

## 3. 개별 효과와 세트 시너지의 분리

- **보드 Lv.3** = 그 보드만의 국소 반응(충돌 지점·세기).
- **시너지**(같은 컬렉션 주사위+보드, 기존 활성화 조건·강도 규칙 유지) = 주사위와 보드의 관계: ① 각 주사위가 **지나간 길**을 테마 재질로 보드에 새김(전선·용암 자국·꽃줄·덩굴·빙결 자국·혜성 꼬리·오로라 띠·빛나는 물길·빗질된 풀·꽃잎 소용돌이), ② **멈춘 주사위끼리 연결**(연쇄 번개·용암 강·별자리·얼음 다리·뿌리·꽃줄·빛의 물결·빛의 아치), ③ 요트·라지·승리 때 모든 연결이 번쩍임. 새 표현 이벤트 `trail`(주사위 화면 위치, 약 30 Hz)을 사용하고 디버그 이벤트 기록에는 넣지 않는다. 2.5D는 경로가 없어 플레이어 쪽 가장자리에서 착지점까지 짧은 경로를 그린다.
- 온라인·AI 대전에서는 기존처럼 내 주사위가 굴러갈 때만.

## 4. 상점 미리보기

- 기존 Lv 탭 구조 유지. 실제 게임과 **같은 컴포넌트**(`DiceArea`·`BoardFx`·`SynergyFx`·`board-scene`)를 쓴다.
- 보드 Lv.2 탭: 굴리지 않아도 환경이 움직임. Lv.3 탭을 고르면 **바로 한 번 굴려** 충돌 반응을 보여 준다(동작 줄이기 제외). 단계 설명 문구는 새 연출 기준으로 갱신(`fx-texts.ts`, 데이터와 테스트로 동기화).
- 컬렉션 조합 미리보기: 상대 아이템도 **선택한 단계**로 표시(이전: 상대는 항상 Lv.3, 시너지 강도는 단계+1).

## 5. 성능 (측정, 같은 환경 전후 비교)

측정 스크립트 `scripts/measure-board-fx-perf.mjs`(신규). 헤드리스 Chromium + **SwiftShader 소프트웨어 GL**, 60 Hz rAF 상한. **실기기 측정이 아니다**. GPU 사용량은 측정 불가(SwiftShader는 CPU에서 그리므로 CDP `TaskDuration`에 포함). 원자료: [before-desktop](../perf/a1-before-desktop.json), [before-phone](../perf/a1-before-phone.json), [after-desktop](../perf/a1-after-desktop.json), [after-phone](../perf/a1-after-phone.json).

요약(정직하게):
- **좋아진 것**: 시너지·폭풍 조합의 프레임 비용. 에뮬레이션 폰(4× CPU)에서 번개 시너지 평균 116.8 → **28.8 ms**, 용암 시너지 88.3 → **30.8 ms**, 폭풍 Lv.3 32.1 → **22.3 ms**. 시너지 조합의 정지 중 CPU 44~52% → 18~35%, 캔버스 6 → 4. 데스크톱 시너지 굴림 중 CPU 84~95% → 72~76%, 번개 시너지 평균 23.1 → 17.8 ms.
- **나빠졌거나 그대로인 것**: 초원 보드 Lv.3(폰) 평균 18.0 → 20.5 ms, 첫 굴림 19.9 → 30.1 ms(보드 전체 풀잎을 반응 중 60 fps로 다시 그림). 시너지 조합의 탭→첫 프레임 p50이 폰에서 81~90 → 102~122 ms(번개는 92 → 63). 단일 보드 Lv.3의 굴림 중 CPU는 비슷하거나 약간 높음(이전엔 반응도 30 fps, 지금은 반응 중 60 fps). 후속: 예산 < 0.75에서 반응 중에도 30 fps, 초원 풀잎 오프스크린 캐시, 첫 굴림 시점 이벤트 처리 분산.
- 메모리: GC 후 힙 8.7~9.6 MB, 18굴림 동안 증가 +2.0~2.4 MB로 전후 동일 범위(누수 징후 없음). 지속 플레이: 첫 굴림 대비 마지막 1/3 평균은 전후 모두 감소(셰이더·청크 예열 효과).
- 60 fps(16.7 ms)는 데스크톱 에뮬레이션에서 모든 조합 평균 16.6~17.8 ms. 폰 4× CPU 에뮬레이션에서는 기본 외 조합이 평균 19~31 ms로 **60 fps 미달**이다. 실기기 수치는 없다.

### 8.1 원인 분석 (프로파일링, 에뮬레이션)

`scripts/profile-first-frame.mjs`(CDP 샘플링 프로파일러, 미축소 빌드, `--window first|roll`)와 `scripts/trace-first-frame.mjs`(Event Timing·rAF·긴 작업·사전 계산 여부)를 새로 만들어 확인했다.

1. **탭→첫 프레임 지연의 주원인은 보드·시너지 계산이 아니라 "물리 사전 계산 실패"였다.** 정지 중 유휴 시간에 다음 던지기 물리를 미리 계산하는데, Lv.3 주사위 입자가 사라지는 동안(`table.animating`)에는 계산을 미뤄 빠른 재굴림 때 탭 시점에 물리(4× CPU에서 30~65 ms)를 메인 스레드에서 돌렸다. 용암 조합 18회: main 6/18, A1 12/18만 사전 계산. 사전 계산된 던지기 52~59 ms, 아닌 것 91~123 ms. A1의 악화는 이 비율 차이와 아래 2·3의 합이었다.
2. **강제 레이아웃**: 매 프레임 주사위 히트 버튼을 `left/top`으로 옮긴 뒤 화면 좌표를 읽어 동기 레이아웃 발생(3굴림당 67~149 ms). 투명 히트 버튼에 2.5D 굴림 CSS 애니메이션까지 돌고 있었다(기존 문제).
3. `fxBudget()` → `matchMedia(...)` 매번 새로 생성 + `innerWidth` 읽기(던지기 시작 직후 강제 레이아웃): 3굴림당 47~63 ms.
4. 초원: 풀잎(최대 320) × 충돌마다 `performance.now()` 호출, 반응 중 60 fps 재그리기.
5. 입자마다 `save/translate/rotate/restore`, 시너지 경로는 선분마다 `stroke()`.

측정 도구 문제도 발견·수정했다. 기존 스크립트가 `npx vite preview`를 띄우고 종료 시 `npx`만 죽여 실제 vite가 남았고, 같은 포트의 다음 측정이 **이전 빌드를 측정**할 수 있었다(이번 A1.1 초기 추적 2회가 실제로 그랬다 — 폐기). 또 4190은 fetch 금지 포트였다. `scripts/lib/preview-server.mjs`가 vite를 직접 띄우고, 이미 응답하는 포트와 금지 포트를 거부한다. 이 때문에 저장된 A1 폰 재측정값의 출처를 확정할 수 없어 **A1(08c507b)은 새로 측정**했고, main 저장값은 같은 환경 재측정(폰 default 17.3/41.5 ms, 용암 시너지 92.3 ms ≈ 저장값 17.3/41.9, 88.3)으로 유효함을 확인해 재사용했다.

### 8.3 적응형 효과 품질 (`src/fx-quality.ts`)

3D 테이블이 매 던지기의 실제 프레임 간격을 보고하고, 장식 계층만 조절한다. 주사위·물리·입력·3D 테이블은 낮추지 않는다(기존 해상도 적응은 그대로).

| 항목 | 단계 0 (기본) | 단계 1 | 단계 2 |
|---|---|---|---|
| 보드 환경 갱신 | 32 ms(~30 fps) | 48 ms | 66 ms |
| 충돌 반응 갱신 | 15 ms(60 fps) | 32 ms | 32 ms |
| 입자 수 | ×1 | ×0.7 | ×0.45 |
| 시너지 경로 샘플 | 32 ms | 48 ms | 64 ms(표식 간격도 넓게) |
| 보드·시너지 캔버스 해상도 상한 | 1.25× | 1.0× | 0.8× |
| 장식 발광(넓은 후광 선) | 켬 | 켬 | 끔(본선 유지) |
| 시너지 연결 세부(꽃줄 점·서리 눈금·번개 후광) | 1 | 0.6 | 0.35 |

- 하향: 연속 2회 느린 던지기(평균 > 22 ms, 또는 p95 > 30 ms이면서 평균 > 19 ms). 상향: 연속 5회 원활(p95 ≤ 18, 평균 ≤ 17.5). 세션 첫 던지기는 예열이라 판단하지 않음. 한 번에 한 단계, **던지기 시작 시점에만 적용**(정지·애니메이션 중 바뀌지 않음), 세션 동안 유지 → 깜빡임 없음. 단위 테스트: 2회 연속에만 하향, 5회 연속에만 상향, 느림/원활 교대 20회에 변경 0회, 예열 스파이크만 있는 던지기는 느림 아님.
- 첫 구현은 데스크톱 번개 시너지에서 예열 스파이크 때문에 단계 1로 잘못 내려갔다 → 첫 던지기 제외·"평균도 느릴 때만" 규칙으로 고친 뒤 데스크톱 전 조합 단계 0 유지를 확인.
- 설정 "효과 품질": 높음 = 단계 0 고정, 낮음 = 단계 2 고정, 자동 = 측정. 동작 줄이기·2.5D 폴백·접근성은 그대로.
- 같은 코드에서 적응 전/후(폰 4×): 용암 24.8→21.6, 번개 27.4→22.1, 벚꽃 22.8→20.7 ms. 단계 0/2 비교 스크린샷: 단계 2에서도 테마 정체성(방전·균열·용암 자국·꽃잎·풀 눕기)이 유지되고 넓은 후광과 입자 일부만 줄어든다.
