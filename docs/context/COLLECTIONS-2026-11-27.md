## 1. 기존 상품 조사 → 연결 우선

우선 테마 10개 중 6개는 이미 상품이 있어 **새로 만들지 않고 연결**했다.

| 테마 | 기존 상품(연결) | 신규 상품 |

| 번개 | 이모티콘 ⚡ | 주사위 `dice.thunder`(전설), 보드 `board.storm` 폭풍 번개(전설) |
| 풀·초원 | 이모티콘 🍀, 프로필 클로버 | 주사위 `dice.meadow`(영웅), 보드 `board.meadow`(영웅) |

신규 11종(주사위 5 · 보드 6) 모두 Lv.1~3, 고유 면 무늬(번개 갈래·풀잎·꽃·벚꽃잎+가지·심해 광선/발광 입자), 고유 보드 표면(CSS), 고유 Lv.2 환경(마른번개·흔들리는 풀·꽃잎·나뭇잎 햇살·용암 맥동 등 새 ambient 4종)과 Lv.3 반응, 고유 착지음. 밝은 면 주사위(초원·꽃밭·벚꽃)는 눈금 대비를 지키려 눈금 발광 없이 효과만 강화(테스트: 면/눈 대비 > 4.5).

**가격(가안 = 기존 등급 정가표 그대로)**: 영웅 3,000코인/300보석, 전설 10,000코인/600보석, 강화 비용도 등급표(영웅 1,500/3,000, 전설 5,000/10,000). 신규 가격 규칙은 만들지 않았다.

**뽑기**: 신규 상품은 `drawExcluded`(상점 전용). 표준 뽑기 풀에 넣으면 기존 상품의 개별 확률이 바뀌므로 소유자 결정 전까지 넣지 않는다(테스트로 고정).

**서버 반영 순서**: 상품 목록은 클라이언트와 워커가 공유한다. Pages는 자동 배포되지만 워커 배포는 수동 워크플로라, 새 상품에는 `rev: 2`를 붙이고 경제 스냅샷에 `catalogRev`를 추가했다. 예전 워커(값 없음 = 1)에 연결된 동안 신규 상품은 **"판매 준비 중"**(미리보기 가능, 구매 버튼 없음)으로 보인다. 워커가 배포되면 자동으로 판매된다.

## 2. 컬렉션 시스템 (`src/economy/live/collections.ts`)

- 데이터만: 컬렉션 id·이름·테마색·주사위·보드·기타 상품·시너지 설명. 서버·클라이언트 공용.
- 상점: "테마 컬렉션" 필터 + 컬렉션 배너(보유 수/전체), 상품 상세에 소속 컬렉션과 시너지 설명, **조합 미리보기**(같은 테마의 주사위/보드를 함께 굴려 시너지 확인, 저장 없음).
- 인벤토리: 장착 조합이 같은 컬렉션이면 "시너지 켜짐", 한쪽만이면 무엇을 더 장착하면 되는지 안내.
- 프로필: 컬렉션별 보유/전체, 시너지 가능 여부, 완성 강조.
- **완성 업적·보상은 활성화하지 않음**(경제 영향, 소유자 결정 필요). 향후 테마 패키지 판매는 이 표를 그대로 상품 묶음으로 쓸 수 있다.

## 3. 시너지 연출 (`src/play/board-synergy.ts`)

같은 컬렉션의 주사위+보드 장착 시(어느 단계든, 두 아이템의 낮은 단계에 따라 0.65~1.0 강도) 트레이 안 별도 캔버스(주사위 아래)에 그린다. 표현 계층 전용 이벤트(`fx-bus`)만 읽고 값·물리·점수·AI는 읽지 않는다. 색만 바꾼 재사용이 아니라 테마마다 동작이 다르다.

| 컬렉션 | 시너지 |
|---|---|
| 번개 | 충돌·착지 지점에서 갈래 번개가 0.16초 동안 뻗어 나가고 그을음이 남음 |
| 초원 | 보드 전체의 풀잎이 충돌 지점에서 바깥으로 눕고 스프링처럼 되돌아옴, 굴릴 때 바람이 훑고 지나감 |
| 꽃밭 | 멈춘 자리마다 꽃이 피어(오버슈트) 머물다 오므라짐 |
| 벚꽃 | 굴릴 때 꽃바람, 착지점 주변에 꽃잎이 내려앉아 수 초간 쌓여 있음 |
| 숲 | 착지점에 새싹이 자라고 위에서 나뭇잎이 떨어짐 |
| 심해 | 착지점 기포 기둥, 멈춘 주사위들을 잇는 빛의 물결 |
| 용암 | 착지점에서 균열망이 번지고 흰빛→주황→검은 암석으로 식음 |
| 얼음 | 육각 서리 수지상 결정이 자라 번짐 |
| 우주 | 별가루와 멈춘 주사위를 잇는 별자리 |
| 오로라 | 착지점에서 오로라 커튼이 보드를 가로질러 지나감 |

요트·라지 스트레이트·승리에는 보드 전체에서 같은 테마 반응. 효과음은 보드 Lv.3 착지음과 겹치지 않게 투척당 1회(낮은 음량). 동작 줄이기 0, 효과 품질 낮음 0.4 등 기존 `fxBudget`을 따르고, 화면 밖·숨은 탭에서는 멈추며, 그릴 것이 없으면 캔버스를 지우지도 않는다(30 fps).

온라인: 내 보드에서 **내 주사위가 굴러갈 때만**(상대 차례에는 꺼짐). AI 대전도 사람 차례만.

## 5. 기간 한정 (구현)

기존 시즌 구조(`SEASONS`, 크리스마스 2026)를 재사용·확장했다.

- 판매 가능 여부는 **서버 시각**: 워커가 구매 요청 시 `seasonActive` 검사(기존), 상점은 스냅샷의 `serverTime`으로 표시(게스트는 기기 시각, 표시용).
- 상점 카드 "기간 한정" 칩, 상세에 시작·종료 일시(한국 시간)와 **남은 기간**(서버 시각), "판매 종료 후에도 보유 상품 사용 가능", **재판매 여부 문구**(`rerun`, 현재 "아직 정하지 않았어요").
- 시작 14일 전부터 "판매 예정" 줄(구매 버튼 없음), 종료 후에는 "판매 기간이 끝났어요".
- 거짓 재고·거짓 마감·반복 연장 금지: 기간은 코드 상수이고 변경은 커밋·문서 기록으로만.

## 6. 수량 한정 (설계·타당성 검토만, 미출시)

목표: 서버 전체 N개, 일련번호 `No. 007 / 100`, 상점·프로필에 실제 발행 수 표시, 동시 구매 초과 발행 0, 중복 지급·장애 복구, 거래·환전 금지 유지.

**권장 구조 (Cloudflare Durable Object 1개 = 상품 1개의 재고 권위)**

1. `LimitedStock` DO(상품별 `idFromName(itemId)`): SQLite 테이블 `serials(no PRIMARY KEY, user_id UNIQUE, request_id UNIQUE, state, at)`, `meta(total, issued)`. DO는 단일 스레드라 `issued < total` 검사와 증가가 원자적이다 → 초과 발행 불가.
2. 구매 흐름(2단계, 멱등): 사용자 DO가 `requestId`로 ① 재고 DO에 `reserve(userId, requestId)` → 일련번호 예약(state=reserved, TTL 2분) ② 사용자 DO에서 재화 차감 + 인벤토리 기록(일련번호 포함) ③ 재고 DO `commit(requestId)`. 같은 `requestId` 재시도는 같은 결과를 돌려준다.
3. 장애 복구: 예약 후 ②가 실패하면 TTL 뒤 예약 해제(번호 재사용 안 함: 결번을 남겨 "발행 수"와 "판매 수"를 정직하게 분리 표시). ②는 성공했는데 ③ 전에 끊기면 사용자 DO의 미완료 기록을 알람으로 재시도(commit은 멱등).
4. 계정당 1개(UNIQUE user_id), 거래·선물 기능 없음, 계정 삭제 시 일련번호는 "소멸"로 표시(재발행 안 함).
5. 공개 표시: 재고 DO의 `issued/total`을 상점에, 보유자의 번호를 프로필에. 발행 수는 캐시 30초.

비용·위험: DO 요청이 상품당 1곳으로 몰리지만 판매량이 작아 무료 한도 안. 출시 전 필요: 실제 수량·가격·출시 여부(소유자 결정), 부하 테스트, 개인정보(보유자 공개 범위) 결정. **이번에는 구현·출시하지 않음.**
