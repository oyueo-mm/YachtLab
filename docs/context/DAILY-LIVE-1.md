## 2. 오늘의 요트 — 공정성 설계

### 2.1 난수 소비 순서 문제와 위치 인덱싱 (D-101)

순차 PRNG는 "몇 번째 난수인가"로 눈이 정해지므로, 한 사람이 주사위 하나를 더 고정하면 그 뒤의 모든 눈이 밀린다. 같은 시드를 줘도 참가자마다 다른 게임이 된다.
여기서는 눈을 **위치**로 정한다: 라운드 r(1~12, 내 몇 번째 차례인지)·굴림 k(1~3)·주사위 칸 j(0~4). 고정한 주사위는 그 위치의 눈을 쓰지 않을 뿐이다. 따라서

- 모든 참가자가 같은 위치에서 같은 눈을 만난다(어느 칸에 기록했는지, 무엇을 고정했는지와 무관).
- 다시 굴린 주사위는 아직 보지 않은 위치의 독립·균등 눈을 받는다 — 실제 주사위와 같은 확률 구조.
- 시험: 킵·칸 선택이 달라도 다음 위치 눈이 같음, 365일 × 180칸 = 65,700면 χ² = 5.92(자유도 5), 200일 테이프에서 DP 최적 플레이 평균 191.98점(DP 기대 191.76).

### 2.2 미래 주사위를 알 수 없게 (D-102)

- 공개 시드가 없다. 그날 키는 Worker 비밀(`DAILY_SECRET`, 32자 이상)에서 HMAC으로 유도되고 서버 밖으로 나가지 않는다. 클라이언트는 이미 굴린 눈만 받는다.
- 그날 아침에는 **확인값** `SHA-256("yachtlab/daily-commit/" + hex(키))`만 공개한다. 마감 뒤(`closed`) 키를 공개(`/api/daily/reveal`)하면 누구나 확인값과 맞는지, 자기 로그가 그 키로 같은 점수로 재현되는지 검사할 수 있다(실제 Worker 테스트에서 확인).
- 차례 첫 굴림은 점수 기록 요청의 응답에 함께 온다(요청 1회 절약). 기록이 이미 확정된 뒤라 판단에 쓸 수 없고, 화면은 "주사위 굴리기"를 누를 때 보여 준다.
- 굴림마다 서버에 1행 저장 → 결과를 본 뒤 같은 굴림을 다른 킵으로 다시 요청해도 `STALE`(되돌리기 불가).

### 2.3 공식 도전 전 연습 금지·반복 연습

- 공식 도전: 그날(`open`)에만 시작, 회원당 1번. 다시 시작하면 같은 시도(새로고침·다른 탭·재시도 요청 안전).
- 같은 날 연습: **그날 공식 도전이 끝난 뒤(완료/만료)만** 열린다. 같은 테이프, 서버 판정, 하루 `DAILY_PRACTICE_PER_DAY`(기본 5)회, 순위 미반영.
- 지난 날짜: 키가 공개됐으므로 **브라우저에서** 재생(`src/daily/archive.ts`) — 서버 요청 0, 횟수 무제한, 기록은 이 기기에만. 키는 그날 아침 기기가 받아 둔 확인값(없으면 서버 확인값)과 대조한 뒤 쓴다.
- 남는 위험(문서화): 다른 계정으로 먼저 플레이해 본 사람은 자기가 본 위치의 눈을 안다. 완화: 순위는 **그날 0시(KST) 이전에 만든 계정만**(`DAILY_NEW_ACCOUNTS_RANKED=off`, 당일 가입은 플레이·기록 가능하나 순위 제외), 공유 문구·이미지에 주사위 눈 없음, 연습은 공식 이후만. 계정마다 다른 테이프를 주면 이 위험은 사라지지만 "같은 조건"이라는 요구와 충돌하므로 채택하지 않았다.

## 3. 오늘의 전략 퍼즐 (D-104)

### 3.1 생성 파이프라인 (오프라인, 재현 가능)

`npx tsx scripts/daily/generate-puzzles.ts` (`--check`: 다시 만들어 저장본과 바이트 비교). 시드 20261201, DP 테이블 sha256 `cf1c1a4d…`, 이 컨테이너에서 7.1초.

1. 국면 수집 — 잡음 섞인 DP Expert 1인 게임(260판, 30% 표본), 끝난 상대 대비 종반(700판, 남은 칸 1~3), **AI 대국 기보**(`src/match.ts simulate`, Greedy vs DP Expert 40판의 실제 진행 국면), 1회 재굴림 확률 문제(500개). 후보 2,941개.
2. 정확 계산 — 모든 합법 행동(서로 다른 킵 조합 + 열린 칸)의 값:
   - 기대점수: 기존 `dpActionValues`(DP Expert 전체 게임 DP).
   - 승리 확률: 끝난 상대 점수 T에 대해 남은 칸 ≤ 3개의 역진 귀납(`EndgameWin`, 같은 주사위 커널) — **정확값**, 무승부 ½.
   - 확률 문제: 6^n 완전 열거.
3. 필터 — 차이가 너무 작음(기대 < 0.3점, 승률 < 0.5%p), 너무 뻔함(> 15점, > 50%p), 이미 결정된 경기(승률 > 99.9% 또는 < 0.2%), 최적 행동 4개 이상, 합법 행동 3개 미만, 지문(fingerprint) 중복.
4. 난이도 — 최선과 차선의 값 차이 + "가장 큰 즉시 점수/가장 많은 눈 고정"(승리 문제는 "기대점수 최적") 같은 단순 규칙이 정답을 찾는지.
5. 예약 — 2026-12-01부터 84일, 날마다 입문·보통·고급 1개씩, 유형은 10종을 돌아가며(해당 칸이 비면 같은 난이도의 다른 유형). 수준별 예비 10개.

### 3.2 유형 (10종, 282문제)

킵 판단 29 · 멈출까 굴릴까 29 · 기록할 족보 56 · 기대점수 최대화(초반) 28 · 승리 확률 최대화 28 · 상단 보너스 19 · 역전(뒤질 때 기대점수 최적과 승률 최적이 다름) 18 · 리드 지키기 19 · 대국 기보 28 · 확률 28.

### 3.3 정답·해설 원칙

- 최적 행동이 여러 개면 모두 정답(`best[]`, 1e-9). 4문제가 복수 정답.
- 해설은 숫자에서 만든다: 정답 값, 차선과의 차이, 흔한 선택의 손실, 즉시 점수/남은 기대, 상단 보너스 상태, 승리 문제의 "기대점수 최적 vs 승률 최적" 대비.
- 모든 문제가 **정확 계산**(`method: "exact"`). 확률적 추정(`"estimate"`) 필드는 형식에 있지만 현재 쓰지 않는다. 기대점수는 "DP Expert 모형(공정한 독립 주사위) 기준의 정확값"이라고 표기한다.
- 기존 엔진 비교(`tests/daily-puzzles.test.ts`): 기대점수 189문제 전부 `dpDecision` 값(1e-5)·행동 일치, 남은 칸 1개 승리 문제 8개 전부 기존 Win DP 정확 마지막 턴 값·행동 일치, 확률 28문제 전부 독립 완전 열거와 일치.

### 3.4 정답 노출 통제

- 웹 번들은 `bank.json`을 가져오지 않는다(시험으로 고정). 질문(`questionOf`)에는 정답이 없다.
- 오늘의 퍼즐: 회원의 **첫 답만 기록**, 채점 후에야 키·해설을 받는다. 게스트는 문제는 보지만 오늘 답은 회원만. 마감된 날: 누구나 풀고 즉시 해설(기록 없음).
- 한계(D-104): 저장소가 공개이고 분석 도구도 공개이므로, 마음먹은 사람은 답을 계산할 수 있다. 그래서 퍼즐 기록은 "참여·정답 기록"이며 **보상·경쟁 순위에 쓰지 않는다**.

## 5. 일일 랭킹 (D-103)

- 첫 공식 기록만. 같은 날 연습·지난 도전은 절대 반영되지 않는다.
- 높은 점수 우선. **동점은 같은 순위**(1, 1, 3), 동점 안에서는 먼저 끝낸 사람이 위에 표시(표시 순서일 뿐 더 좋은 순위가 아님).
- 날짜·규칙 버전(`yacht-12@1`)마다 별도 객체(`daily:<rules>:<date>`) — 기록이 섞이지 않는다.
- 페이지네이션: 전체 순서(비공개 포함)로 페이지를 나눠 순위가 항상 참값이고, 응답 전에 공개 범위·차단을 걸러 낸다(내부 ID는 응답에 없음). 방금 끝낸 내 기록은 캐시와 무관하게 내 페이지에 합쳐진다.
- 공개 범위: 전체(기본)·친구만·나만. 차단은 양방향 모두 서로의 목록에서 숨긴다(`fr_blocks` ∪ `fr_blocked_by`). 탈퇴하면 모든 날짜 보드에서 기록 삭제.
- 범위 밖(이번에 하지 않음): 일반 대전 레이팅, 랭크전, 시즌 티어, 토너먼트.

## 6. 07(경제)·06(운영) 연동

- **07**: `DailyActivity` 이벤트(공식 시작·완료, 퍼즐 답)와 `DailyRewardHook.proposals()`만 정의. 구현은 `NO_DAILY_REWARDS`(항상 빈 목록), `DAILY_REWARDS_APPROVED = false`. Worker는 일일 콘텐츠로 원장에 쓰지 않는다. 출석·연속 참여 계산은 `dailyStreak()`로 제공(화면 표시용). 07이 지급 계약을 승인하면 보상은 (userId, date, kind) 멱등 키로 원장 트랜잭션 안에서 지급하도록 붙인다 — 그 전에는 지급 금지.
- **06**: `GET /api/admin/daily?date=` → `DailyAdminReport`: 시작·완료·순위 반영 수, 완료율, 25점 구간 분포, 평균·최고, 같은 날 연습 수, 퍼즐별 응답·정답·정답률·내림 여부. 계정 ID·닉네임 없음. 문제 운영은 `POST /api/admin/daily/puzzle {date, puzzleId, disabled}`.

## 8. 공개 전 남은 일 (운영 공개 조건)

1. Worker 배포: `wrangler.toml`에 바인딩·마이그레이션 `v5`(DailyBoard)·변수가 추가돼 D-100의 **보호 입력** → 자동 배포가 멈추고 승인된 수동 배포가 필요하다. `DAILY="off"`로 배포하면 사용자에게 보이는 변화는 없다.
2. 운영자가 `DAILY_SECRET`(32자 이상, Worker 비밀)을 설정 — 저장소·대화에 쓰지 않는다. 비밀을 바꾸면 그날 이후의 테이프가 바뀌므로 날짜 중간에 바꾸지 않는다.
3. 비공개 경로(`?online-server=…#daily`)에서 운영 Worker로 1주일 관찰: 완료율, 쓰기량, `DAILY_VERIFY_FAILED` 로그 0건.
4. 01과 로비 카드·내비게이션 위치 협의(`DailyHomeCards`).
5. 07 보상 계약 승인 전까지 보상 없음. 06 운영 화면은 보고서 API를 쓴다.
6. 퍼즐 은행 연장: 2027-02-22 이후 날짜가 비므로 그 전에 `--days`를 늘려 다시 생성(재현성 시험이 함께 갱신을 요구).
