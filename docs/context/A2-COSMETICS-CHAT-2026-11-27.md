## 6. 성능 (헤드리스 Chromium + SwiftShader 에뮬레이션, 실기기 아님)

A1.1 회귀(`scripts/measure-board-fx-perf.mjs`, main `0939a27` vs A2, 같은 컨테이너·2회×6굴림): default 평균 16.6/16.6 ms; lava-synergy 16.7/16.8; thunder-synergy 16.9·17.3·17.7 (main) vs 17.5·17.2·17.7 (A2) — 시도 간 편차(p95가 16.8↔33)가 main끼리도 같아 **유의한 회귀 없음**. 이 경로(1인 플레이)는 A2가 건드리지 않는다.

꾸미기 고부하(미리보기 페이지, Pixel 7 에뮬 + CPU 4배 스로틀, 5초): 기준선 / 고부하 조합(네온 Lv.3 닉네임+크리스탈 Lv.3 프레임+홀로그램 말풍선 Lv.3+효과·이모티콘 초당 1회) 모두 **평균 16.7–16.8 ms, p99 16.8, 33 ms 초과 0**. CPU(작업 시간 비율)는 기준선 ~8% → 조합 ~55%(소프트웨어 렌더링 합성 비용; 실기기 GPU는 더 낮을 것으로 예상하나 **미측정**). 병목이던 홀로그램 프레임(conic+mask 회전)·홀로그램 말풍선(연속 배경 이동)은 SVG 링·단계 애니메이션으로 교체(프레임 단독 +23%p → +14~25%p로 하향). 항목별 단독 +1~25%p.
통제: 동작 줄이기(시스템/설정 `data-fx-reduced`)·효과 품질 낮음(`data-fx-tier=2`)에서 CSS 루프 중지, 화면 밖 썸네일 일시정지, 입자 0이면 DOM 미생성.

## 7. 남은 문제

1. 실기기(저사양 안드로이드) 프레임·배터리 미측정. 프레임 Lv.3 회전은 항상 켜져 있어 좌석 3개면 레이어 3개 상시 합성.
2. 온라인 대전 전체 화면(좌석 말풍선·요트/라지 효과)의 컬러 스크린샷은 서버 필요로 미촬영.
3. 채팅 mood는 문구 추정(`chat-mood.ts`): 새 문구가 어색하면 C5가 `mood` 필드를 줄 수 있음(제안서 §2).
4. fx 레벨 문구는 "요트 연출 추가" 그대로(라지 포함 문구는 C5 요청).
5. 좌석 말풍선은 기존 설계(D-060)대로 좌석 칩 아래에 걸려 3D 트레이 위 모서리를 약 4초간 덮을 수 있다. 굴림 버튼·킵 슬롯·점수판은 가리지 않음을 실제 온라인 대전에서 검증했지만, 굴러가는 주사위가 그 모서리를 지나는 순간은 막지 않는다.
6. 게스트는 꾸미기를 소유하지 않아 실제 Worker 대전에서는 꾸미기 클래스를 좌석 DOM에 주입해 검증했다(아이템 자체는 미리보기 페이지 테스트가 담당). 아이템을 가진 회원으로 실제 대전을 돌리려면 재화 획득 경로(테스트 지급 없음)가 필요해 하지 않았다.
7. `review.spec.ts`의 "저장된 1:1 기보…"(C2 소유)는 빌드 산출물 `assets/product-worker-*.js` 경로를 가로채므로 Vite 개발 서버로는 시간 초과한다(A2 변경과 무관, 빌드+preview를 쓰는 CI에서 판정).
