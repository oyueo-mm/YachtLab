# 제품 방향 (PRODUCT-PLAN)

> 확정된 제품 방향만 적는다. 후보·아이디어는 [IDEAS](./IDEAS.md), 기능 상태는 [PRODUCT-BACKLOG](./PRODUCT-BACKLOG.md), 병렬 트랙은 [PARALLEL-PLAN](./PARALLEL-PLAN.md).
> 근거가 되는 결정 번호(D-xxx)는 [DECISIONS](./DECISIONS.md)에 있다. 이 문서는 2026-11-28 UI-1 작업에서 기존 문서(ONLINE-YACHT-PRODUCT, PRODUCT-2026-11-24, ROADMAP 장기 로드맵, COLLECTIONS, A1~A5·C2~C4 기록)를 한곳에 모은 색인이며 새 정책을 만들지 않는다.

## 1. 게임
- 규칙: 12칸 Nintendo-style Yacht Dice(주사위 5개·최대 3회, 상단 63점 이상 +35). 미국식 Yahtzee 수치와 혼용하지 않는다. 13룰·15룰·고전 요트는 **미승인 후보**([ideas/game-modes](./ideas/game-modes.md)).
- 모드(출시됨): 1인 플레이, 사람 vs AI(난이도 5단계), 로컬 다인전(2~50명, `MAX_LOCAL_PLAYERS`), 온라인 빠른 대전(1:1)·친구 방(2~20명, `MAX_SEATS`)·서버 AI 대전·관전.
- AI: 매우 어려움 기본 모델은 v4-D 유지(D-V7-6). 연구 후보 교체는 확증 대국 후 별도 결정.

## 2. 플레이 경험 원칙
- 게임판 중심 화면(D-060대), 모바일 우선 확인(320px부터), 동작 줄이기 존중.
- 경기 종료 화면은 사실만(점수·순위·확인된 보상). 판단 정확도·주사위 운·판단 손실 같은 분석 지표는 **게임 리뷰에서만**(A3, UI-1).
- 닉네임은 공유 이미지에서 기본 비공개(D-064).
- 공정성: AI·리뷰는 공개 관측만 읽는다. RNG/seed 등 엔진 비공개 상태는 입력이 아니다.

## 3. 온라인·소셜
- 친구 요청은 서버가 계정과 친구 코드의 대응을 보증한 경우만(A4 §4). 클라이언트가 접속 상태·관계를 추정해 표시하지 않는다.
- 매칭 프로토콜·대기/성사 정책은 서버 담당(트랙 04). UI는 상태만 표시한다(UI-1).

## 4. 경제·꾸미기
- 재화: 코인·보석, 현금 결제 없음(현재). 보상은 서버 원장/receipt로 확인된 것만 표시(D-040~D-042, A3).
- 상점·인벤토리 전면 개편은 트랙 02. 공통 디자인 규칙은 UI-1([UI-1 기록](./UI-1-GAME-UX-2026-11-28.md) §7).

## 5. 장기 방향(검토 단계 — 확정 아님)
한국·일본 시장 우선 검토, 다국어, 독립 도메인 이전 뒤 홍보·SEO, 광고 우선 수익화와 광고 제거·멤버십·시즌 패스·꾸미기/재화 직접 판매·고급 분석 혜택·후원, Android·iOS 앱. 상세와 상태는 [FUTURE-UPDATES](./FUTURE-UPDATES.md)·[ideas/monetization](./ideas/monetization.md). **어느 것도 승인된 정책이 아니다.**
