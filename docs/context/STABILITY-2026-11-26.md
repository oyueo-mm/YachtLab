# 화면·초대·다인전 조작 안정성

기준은 PR #102의 운영 배포와 테스트 시간 제한을 수정한 PR #103입니다. #103의 [main 빌드·배포](https://github.com/oyueo-mm/YachtLab/actions/runs/45832120300)와 [배포 후 IndexNow 검사](https://github.com/oyueo-mm/YachtLab/actions/runs/45833196799)가 성공했습니다.

## 갤럭시 S21 상단 잘림 신고

- Chromium 모바일 컨텍스트에서 360×800, 360×620, 360×568 CSS px로 높이를 줄였다가 복원했습니다. 홈, 온라인 진입, 오프라인 메뉴, AI·로컬 게임, 상점, 프로필, 한 차례 연습에서 첫 콘텐츠가 상단 헤더 아래에서 시작했습니다. 800×360 가로 화면에서는 일부 콘텐츠가 화면보다 길어 문서 스크롤이 필요했습니다.
- 셸은 `100vh` 폴백과 `100dvh` 최소 높이, 일반 문서 스크롤, `position: sticky` 헤더를 사용합니다. 게임판 높이는 `dvh`와 최소 높이로 계산하며, 작은 높이에서는 문서가 더 길어질 수 있습니다. 페이지 높이를 `100svh`로 고정하거나 헤더 높이를 임의 조정할 근거를 찾지 못했습니다.
- 물리 S21, 삼성 인터넷이나 Android Chrome의 실제 주소창 전환, 키보드·시스템 글꼴·확대 설정, 컷아웃의 안전 영역, 설치된 PWA 창은 재현하지 못했습니다. 현재 재현에 필요한 정보는 문제 화면의 경로와 상태, 브라우저·버전, 주소창/설치 모드, 방향, 표시 크기·글꼴, 화면 캡처입니다. 잘림을 해결했다고 판정하려면 해당 조건에서 헤더·보드의 위치와 `visualViewport`를 다시 측정해야 합니다.

## 설정

한 스크롤 컨테이너 안에 스티키 제목, 닫기 버튼, 본문이 함께 들어 있었습니다. 휴대폰에서 스크롤할 때 헤더가 위쪽 여백만큼 이동했고 스크롤 영역이 헤더까지 덮었습니다. 제목·닫기·그립을 스크롤 바깥에 두고, 본문에만 스크롤과 내부 스크롤바 여백을 적용했습니다. 사운드·화면·조작·도움말 그룹에서 기존 설정과 자동 저장을 유지합니다. 품질 선택 목록은 본문에서 위아래로 열린 공간을 계산합니다. 짧은 PC와 모바일에서 헤더 위치, 목록 경계, 키보드 선택, Esc, 닫은 뒤 포커스 복귀와 저장을 검사합니다.

## 클릭과 초대

- ‘빠르게 가기’라는 이름의 컨트롤은 확인되지 않았습니다. 빠른 대전 시작·대기·복귀, 첫 튜토리얼의 건너뛰기, AI 속도 ‘빠르게’를 기존 경로에서 검사했습니다. 확인한 경로에서 같은 클릭 문제를 재현하지 못했습니다.
- 방 이동은 해시만 `pushState`로 변경해 `?room=`을 다른 화면에 남겼고, 방 주소를 기록하기 전에 직전 로비 URL까지 같은 코드로 덮어쓰는 경로가 있었습니다. 방 코드와 해시를 함께 기록합니다. 직접 초대는 입장에 성공하면 해당 주소를 방 주소로 전환합니다. 홈·프로필로 이동할 때는 새 주소에서 코드를 제거하고, 취소나 브라우저 뒤로·앞으로로 방문한 방은 해당 히스토리의 코드와 저장 좌석으로 복구합니다.
- 방을 명시적으로 나가면 기존 좌석 삭제와 주소 정리를 사용합니다. UTM은 기존 로컬 저장과 주소 정리를 사용합니다. 전화기 컨텍스트의 해시 없는 초대, 프로필 이동·새로고침, 뒤로 가기, 입장, 방 새로고침, 홈 이동과 복귀, 방 나가기를 실제 로컬 서버로 검사합니다.

## 온라인 단축키

3인 이상 경기에서는 공통 훅의 화살표 선택이 다인전 점수판에 전달되지 않았습니다. 다인전 점수판과 공통 키가 선택 상태를 공유하고, Enter 또는 점수 확인 버튼으로 서버가 허용한 족보를 기록합니다. 클라이언트의 굴림·킵·기록은 서버가 보내는 내 차례의 허용 동작과 기존 송신·애니메이션 상태를 확인합니다. 채팅과 정보 팝업이 열려 있을 때는 아래 게임에 키 입력을 보내지 않습니다. 2인, 3인 순차와 동시 진행의 굴림·킵·기록을 기존 서버 경로에서 검사합니다.
