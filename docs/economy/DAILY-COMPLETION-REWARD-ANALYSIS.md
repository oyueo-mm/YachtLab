# 오늘의 요트 완료 보상 검토 (2026-11-28, D-141 후속)

> **상태: 분석만. 지급액·신규 지급 출처 미승인, 실제 지급 비활성.**
> - 일일 보상은 0을 유지한다(`NO_DAILY_REWARDS`, `DAILY_REWARDS_APPROVED = false`).
> - C5 `APPROVED_SOURCES`에 `daily-play`·`daily-content` 출처는 없다.
> - 승인되더라도 C5 `RewardGrants` 단일 지급 경로만 쓰고 별도 지급 엔진을 만들지 않는다.

## 1. 보상 대상과 제외 대상

- **대상:** 공식 도전을 정상적으로 완료한 경우, 계정당 KST 하루 1회. 판정은 서버가 한다.
  - 기존 `dailyContentDone`과 같은 시점에, 같은 KST 날짜 규칙(`min(at, now)`)으로 판정한다.
- **제외:**
  - 전략 퍼즐, 같은 날 연습, 지난 도전 다시 하기
  - 시간 종료(`expired`)된 도전
  - 정지 계정(INT-1 가드)
  - 탈퇴 후 같은 날 재도전(DLY-2 가드로 시작 자체가 불가)
- **점수별 차등 보상 금지(D-141).** 완료 여부만 본다.
- **기존 C5 연동 유지:** 공식 완료 → 연속 활동(ACT-REST1) 활동일 1회.

## 3. 중복·악용 검토

| 항목 | 판단 |
|---|---|
| 출석 보상과 중복 | 출석은 "접속", 완료 보상은 "공식 도전 완료"라 다른 행동이다. 같은 날 둘 다 받을 수 있으므로 합산 발행을 시뮬레이션에 반영해야 한다. 대안: 완료 보상을 출석 보상에 포함(별도 출처 없이 출석 7회차 보너스 조정)하는 방법도 있다(정책 결정) |
| 연속 활동과 중복 | 연속 활동은 이미 공식 완료를 활동일로 센다(코인은 이정표에서만). 완료 코인은 별도 출처(`daily-content`)가 된다 |
| 다계정 파밍 | 계정마다 Google 계정이 필요하다. 재화는 계정 사이에 옮길 수 없어(거래 없음) 다른 계정의 코인은 본 계정에 쓸모가 없다. 위험은 낮다 |
| 탈퇴·재가입 중복 | 탈퇴하면 지갑이 초기화되므로 순이득은 0이다(ECO-7과 같음). 같은 날 재도전은 DLY-2로 막힌다. C5 txId가 `(계정, 날짜)`에서 결정적이라 재시도해도 중복 지급되지 않는다 |
| 점수 조작 | 점수와 무관하게 지급하므로 DLY-1(사전 정보)로 이득을 볼 수 없다 |

## 4. Workers Free 영향 (코드 경로 추정)

- **추가 요청:** 0. 완료 처리(`dailyFlush`) 안에서 같은 계정 객체가 C5 지급을 함께 쓴다.
- **추가 SQLite 쓰기:** 완료 1회당 약 2~3행(`grant_tx` 1행, 원장 1행, 수령 시 갱신 1행).
- **규모:** 하루 완료 1,000명이면 약 3,000행/일이다. Free 쓰기 한도 10만 행/일의 약 3%다.

## 5. 승인 시 필요한 결정

1. 지급액: 5 또는 10코인(또는 출석에 포함)
2. 출처: 신규 `daily-content` 출처를 승인 목록에 추가할지. 추가하면 `worker/src/grants.ts`가 바뀌므로 D-100 보호 입력이 되어 수동 배포가 필요하다
3. C5 시뮬레이션 재실행: 출석·연속 활동·완료 보상을 합산한 발행을 365일로 확인
4. `DAILY` 활성화 순서와 함께 결정(완료 보상은 `DAILY`가 켜진 뒤에만 의미가 있음)
