# C5 인수인계 · 경제 정책 적용과 검증

C1 조건부 추천은 **C1-PRICE**다. 일반·고급·영웅의 기준 가격에 각각 55%·70%·90%를 적용하고, 전설·신화는 100%로 둔다. 코인 단위는 5, 보석 단위는 1로 내림한다. 경기·퀘스트·업적, 강화, 뽑기, 상한, 강화 가능 레벨, 등급과 상품 판매 범위는 기준 버전을 따른다. 연구 결과와 의사결정 상태는 [C1 보고서](../ECONOMY-V2-RESEARCH.md)에서 확인한다.

## 승인 및 운영 확인

1. 운영 권한 소유자가 활성 Worker 버전, Free 플랜·결제, 실제 바인딩, 가격 설정, 카탈로그 revision 및 롤백 대상을 확인한다. PR #112의 보류 조건을 해제하기 전에는 운영 배포를 시작하지 않는다. C1 공개 집계에는 활성 버전이나 개인 원장이 포함되지 않는다.
2. C1-PRICE, 적용 카탈로그 버전, 기존 구매자 대응을 각각 승인받는다. 확정 디자인 재분류도 경제 수치와 확률은 별도 승인한다. 제안 보드와 채팅은 기존 ID 소유권·슬롯·장착 처리 검토 후 별도 결정한다.
3. A1 및 A2와 `catalog.ts`, `content-items.ts`, `config.ts`, `draw.ts`, `src/social/catalog.ts` 변경 시점을 조율한다. 승인받은 정책의 품목별 코인·보석·강화·뽑기 전후를 스냅숏으로 검토하고 경제 `config` 버전과 시효를 문서화한다.

## 구버전 클라이언트와 견적

- Pages에서 상품·통화·현재 단계·`expectedPrice`·`configVersion`을 확인 후 보낸다. Worker는 유효한 상품/통화/레벨/재고, 서버 현재 견적과 버전, 잔액을 같은 트랜잭션에서 검증한다. 가격이나 버전 불일치에는 409와 최신 견적을 보내고 사용자 재확인을 받는다.
- `requestId` 재시도는 원 결제·원 응답을 반환한다. `userId` 범위에 명령 유형·품목·통화·레벨을 결합해 요청 재사용 충돌을 검출한다. 중복 응답으로 정산을 한 번 더 진행하지 않는다. 신규 견적 승인은 원 결과가 없음을 확인한 뒤 새 요청을 사용한다.
- 지금 Worker는 `buy`/ `upgrade`에서 서버가 가격을 계산하며 구버전은 예상가·버전을 보내지 않는다. 먼저 기능 신호와 견적·오류 처리 양쪽을 경제 수치 동일한 상태로 검증한다. Pages의 신규 견적 지원 후, 견적 필수 정책이 적용된 Worker에서 구버전 요청을 업데이트 안내로 처리한다. 캐시에 남은 구 Pages가 새 가격을 자동 결제하지 않도록 로컬 격리 환경에서 반드시 확인한다.
- 롤백 가능한 스키마는 추가형을 쓴다. 안전한 원복 대상은 견적 불일치 거부를 이해하는 직전 버전으로 지정한다. 활성 정책 전환 전에 이전 Worker·Pages 호환 조합, 대기 중 요청, 재시도, 원복 후 사용자 장착과 레벨을 확인한다.

## 인벤토리 및 가격 하락 보호

- 상품 ID, 보유 단계, 장착을 유지한다. 채팅 의미가 달라지는 항목에는 새 ID를 할당한다. 새 버전에서 판매를 그만두는 문구의 서버 전송·기존 장착은 별도 접근 상태로 보존한다. 현재 `retired`는 전송도 막으므로 이를 소유권 보존 플래그로 사용할 수 없다.
- `chat.great`를 기존 소유자의 무료 권리로 남기려면 출시 전 생성 계정용 entitlement 또는 동등한 호환 경로를 정의한다. 신규 기본 장착 6종과 분리한다. 출시 후 신규 가입자는 해당 제안에 따라 유료 라인을 구입할 수 있다.
- 가격 인하 차액 지급을 승인할 경우 원장에서 원거래의 품목 ID·통화·당시 금액·정책 버전·시점을 검증한다. 기존 ID `buy:<requestId>`·`up:<requestId>`·`draw:<requestId>`와 인벤토리 `via/at`가 있으나 원장 품목/강화 단계는 항상 구조화돼 있지 않다. 레이블 텍스트만으로 금액을 확정하지 말고 불확실한 거래를 별도 집계한다.
- 순상향 품목 기존 소유자 강화에는 승인 시 품목·취득 기준 revision·이전 단계별 견적을 보존한다. 보호 자격은 도입 시점 소유 원본으로 고정한다. 신규 구매·뽑기 계정에는 새 가격을 사용한다. 소급 추가 청구와 회수는 금지한다.
- 보상 결정 시 `comp:v2:<ruleVersion>:<accountScope>`나 원거래별 키를 지불과 상태 변경 트랜잭션에서 검사한다. 자격·코인·보석 양쪽 소요를 읽기 전용 dry run으로 보고한다. 이중 지급·부분 실패·재시도·관리자 중복 실행·롤백 이후 재실행을 검증한다.

## 승인 후 검증 순서

1. C1-PRICE 기준 카탈로그 수치와 샘플 견적을 고정한다. 300→165코인 일반 주사위, 1,000→700 고급, 3,000→2,700 영웅, 전설·신화 동일. 세부 반올림은 품목별 기준가에 적용한다.
2. 신규·보유·강화·중복 뽑기·무료 기본·기존 인벤토리·채팅 권리와 승급/강등의 fixture로 확인한다. 이전/현재 클라이언트 × 이전/현재 Worker × 재시도/동시 요청을 시험한다. 원장 합계와 잔액의 양 통화 보존, 운영 배포 전 격리 Worker 교체·롤백, 운영 DO의 앱 ID/바인딩/키는 유지한다.
3. 작은 사용자 평가로 첫 실제 원하는 상품과 구매 실패 사유를 확인한다. 가격표 표시/견적 오류, 원장 불일치, 구매 중복, 부당 청구가 나오면 적용을 중단하고 안전한 설정과 버전으로 복구한다. 이용 행태 변화는 C1 수치와 구분해 보고한다.
