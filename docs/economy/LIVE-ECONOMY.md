# 실서비스 경제 — 코인·보석·퀘스트·업적·상점·인벤토리 (제품 Phase 5/6, 2026-11-24)

> 운영안 **M3i-W30**(연구 [ECONOMY-RESEARCH §16](./ECONOMY-RESEARCH.md), D-034/D-035)을 실제로 구현했다. 결정 기록: DECISIONS D-040~D-042.
> 모든 수치는 `src/economy/live/config.ts`(버전 `M3i-W30@1`) 한 곳에 있고, 원장 행마다 지급 당시 버전을 기록한다. 상품은 `src/economy/live/catalog.ts`.
> **코드 대조(2026-11-28, C5):** 현재 운영 버전은 `M3i-W30@2`다. 아래 가격표는 등급 기준가이고, 실제 판매가·강화비에는 카테고리 배율(보드 90·프로필 75·칭호 55·말풍선 70·닉네임 효과 80·특수 연출 95%, 기본 스타일 채팅 55·이모티콘 75%)이 붙는다. 퀘스트 교체는 일일 1회(한 칸 또는 미완료 전부)와 주간 전체 교체 1회다. 골드 말풍선·왕관 프로필은 영웅이다. 판매 상품은 Rev.2 212종 + 시즌 10종이다. 뽑기는 [ONLINE-YACHT-DRAW](./ONLINE-YACHT-DRAW.md)에 있다. 무작위 연승은 무승부에도 0으로 돌아간다. 신규 가입 보상은 경제 기능 첫 사용 시 지급된다. 전체 대조표: [C5 연구 §1.4](./C5-RETENTION-RESEARCH.md).
> **구매 요청 검증(2026-11-28, SEC-1 경제 항목, 운영 미배포):** 구매·강화·슬롯·뽑기 요청은 선택 필드 `expectedPrice`·`expectedLevel`(강화)·`configVersion`·`oddsVersion`(뽑기)을 받는다. 서버는 이 값을 같은 트랜잭션에서 대조하고, 다르면 `409`(`PRICE_CHANGED`·`LEVEL_CHANGED`·`POLICY_CHANGED`·`ODDS_CHANGED`)를 돌려주며 차감하지 않는다. 요청 ID를 다른 요청에 다시 쓰면 `409 REQUEST_REUSED`다. 필드가 없으면 기존 동작이다. 금액·확률은 그대로다.
> 실제 현금 결제 없음. 재화 간 교환·선물·거래·환전 없음. Pay to Win 없음(아이템은 표시 계층만, 주사위·물리·전략·승패에 영향 없음).

## 2. 경기 보상 계산 순서 (`src/economy/live/rewards.ts` `applyMatch`)

1. **신뢰**: server-verified, 회원 좌석, 처음 저장되는 matchId일 때만.
2. **집계 대상(countable)**: 12라운드 완료, 또는 상대가 기권·시간 초과했고 내가 6칸 이상 채운 경우(완료 보상만, 승리 보너스 없음). 본인 기권·탈주는 아무것도 없음.
3. **모드별 상한(하루 순번 계산 전)**: 친구 대전 하루 10경기, 같은 회원 상대 무작위 대전 하루 3경기까지 보상. 상한을 넘은 경기는 "보상 대상"이 아니며 하루 순번을 쓰지 않는다(전적·퀘스트는 정상).
4. **하루 순번 k**(모든 모드 공유, 한국 시간 하루):
   - k = 1~10: 모드 보상(완료 + 승리/무승부 보너스) + 신규 7일 보너스 +5 + 진행 중 이벤트의 경기당 보너스
   - k = 11~30: 경기당 **3코인 고정**(승리 보너스·신규·이벤트 보너스 없음)
   - k ≥ 31: 경기 코인 0
5. **퀘스트**: 집계 대상 경기마다 진행(코인 상한 이후에도).
6. **업적**: 하루 40경기까지 누적(플레이 일수·일일 퀘스트 완료 수는 항상). 전적·통계는 상한 없음.

| 모드 | 완료 | 승리 | 무승부 |
|---|---:|---:|---:|
| 무작위 대전 | 10 | +3 | +2 |
| 친구 대전 | 10 | 0 | 0 |
| 서버 AI 대전 | 7 | +2 | 0 |

신규 회원: 200코인·20보석(계정당 1회, 원장 키 `welcome`), 가입 후 7일 동안 1~10번째 보상 경기마다 +5. 이벤트: 설정 구조(`ECONOMY.events`)만 있고 출시 시 비어 있음(자동 반복 이벤트 없음).

## 5. 상품·가격·강화·슬롯

등급: 기본 → 일반 → 고급 → 영웅 → 전설 → 신화, 그리고 확장용 **특수**(`specialKind: "achievement" | "symbolic-purchase"`). 등급·획득 방식(`default/coins/gems/either/achievement/symbolic`)·가격(등급 기본가 또는 상품별 덮어쓰기)·강화 여부는 상품마다 독립. 신화 일반 판매는 코인·보석 선택. 업적 전용은 서버가 구매 요청을 거부.

## 6. 원장 (`worker/src/economy.ts`, 계정별 SQLite DO `UserStore`)

- 테이블: `econ`(잔액 정수·`CHECK ≥ 0`, 슬롯, 장착, 진행 상태 JSON), `ledger`(event_id 기본키, 증감, 잔액 추적, `funding`=`play`(유료 `paid` 자리만 마련), 설정 버전), `inventory`(아이템·해금 단계·획득 경로).
- 고유 이벤트 ID: 경기 `m:<matchId>`, 퀘스트 `q:…`, 퀘스트 보너스 `qb:…`, 업적 `a:<id>`, 가입 `welcome`, 구매 `buy:<requestId>`, 강화 `up:<requestId>`, 슬롯 `slot:<requestId>`.
- **원자성**: 경기 기록 저장 + 보상 원장 + 상태 갱신이 `transactionSync` 하나. 구매는 잔액 확인·차감·인벤토리·원장·업적 해금이 한 트랜잭션. 실패하면 아무것도 남지 않음(테스트).
- **멱등**: 같은 matchId의 재전달은 기록이 이미 있어 아무것도 지급하지 않음. 구매·강화·슬롯은 클라이언트가 만든 요청 ID로 재시도·응답 유실에도 1회만(같은 ID 재요청은 `duplicate: true`).
- **동시성**: 계정 객체는 직렬 실행 → 동시 구매도 하나씩 처리, 두 번째 요청은 줄어든 잔액을 본다.
- **잔액 부족**: 거부(402), 잔액 변화 없음.
- **격리**: 요청은 세션이 인증한 사용자 ID의 객체에만 도달.
- **일관성 검사**: `verify()`가 원장 합계·행별 누적 잔액·음수 여부를 확인. 관리자 `GET /api/admin/ledger/:userId`.
- 기존 server-verified 아웃박스(방 → 계정, matchId 멱등 재시도)를 그대로 보상 입력으로 쓴다.

| 봇·이상 획득 속도 | 운영 지표 `econ.maxCoinsOneAccount`(하루 최대 획득 계정의 코인) — 이론상 최대(정상 10경기·감소 20경기·퀘스트·업적) 대비 감시 |

## 8. 운영 지표 (개인정보 최소화)

`MatchHub`가 메모리에서 하루 단위로 세고 10분마다 하루 1행으로 저장(경기마다 추가 행 쓰기 없음). 계정 ID·IP·닉네임 없음. 항목: 빠른 대전 대기·취소·유령·만료·성사·공개·회원 경기, 대기 시간 합/건수·p50/p90, 모드별 완료/기권 경기와 경기 시간 합, 회원 일일 활성(첫 경기 기준), 코인·보석 발행량, 보상 사유별 경기 수(상한·동일 상대 포함), 퀘스트 완료·일일 전체 완료, 업적 해금, 잔액 구간 분포(활성 회원), 등급·결제수단별 구매, 강화·슬롯 구매, 계정별 하루 최대 획득. 소비량 = 구매 건수 × 가격표. 조회: `GET /api/admin/metrics`(Worker 시크릿 `ADMIN_TOKEN` ≥ 32자, 없으면 404). Cloudflare 사용량은 대시보드(또는 `/usage`).

## 9. 기능 플래그

`ECONOMY = "on"`(wrangler.toml)일 때만 지급·구매가 동작. `"off"`로 즉시 멈출 수 있고(잔액 보존), 꺼져 있던 동안의 경기는 소급하지 않는다.
