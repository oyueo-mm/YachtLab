# SEC-1 — YachtLab 독립 애플리케이션 보안 감사 (1차, 2026-11-28)

- **대상:** `main` `edc2fbf`(CI-1.2 자동 Worker 배포 병합 직후). 프런트엔드(`src/`, `public/`, `index.html`, PWA), Worker(`worker/src/*`), 공용 엔진·경제(`src/online/*`, `src/economy/live/*`, `src/identity/*`), GitHub Actions 41개, `scripts/ci/*`.
- **방법:** 소스 정적 분석, 격리 로컬 재현(node:sqlite 메모리 DB, `wrangler dev --local`), `npm audit`. **운영 Worker·Pages·실제 계정·재화에는 요청을 보내지 않았다.** 부하·무차별 대입 시험은 하지 않았다.
- **공개 범위(D-098):** 이 문서는 공개 요약이다. **수정되지 않은 항목은 재현 절차·코드 위치·임계값을 싣지 않는다.** 상세 보고서는 운영자에게 비공개로 전달했다. 수정된 항목(SEC-1-01)만 수정 내용과 회귀 테스트를 공개한다.
- **한계:** 이 감사만으로 운영 환경이 안전하다고 단정하지 않는다. GitHub·Cloudflare 설정(브랜치 보호, Environment 규칙, 시크릿 잔존, 토큰 범위, 로그 수집 항목)은 코드로 확인할 수 없어 소유자 확인이 필요하다(§5).

## 1. 결론 요약

1. **치명(Critical)·높음(High) 등급의 재현된 취약점은 없다.** XSS 싱크(`dangerouslySetInnerHTML`·`innerHTML`·`eval` 등)가 없고, 계정 간 접근(IDOR/BOLA), 클라이언트의 주사위·점수 위조, 재화 복제·음수 잔액 경로를 찾지 못했다.
2. **재현된 중간(Medium) 1건을 이 브랜치에서 수정했다(SEC-1-01).** 자기 계정에 기기 기록을 먼저 올리면, 같은 경기의 서버 검증 결과가 저장되지 않았다. 이 결과에는 공개 전적·연승 정산이 포함된다. 현재 서버 검증 기록이 우선한다(D-101).
3. **잠재 높음 1건은 소유자 확인이 필요하다.** CI-1.2 이전 방식의 저장소 수준 Cloudflare 배포 시크릿이 아직 남아 있을 수 있다. 워크플로에서는 더 이상 참조하지 않지만, 남아 있으면 `worker-production` Environment 경계를 우회하는 경로가 된다.
4. **C4 후속 반영 상태:** 배포 통제(SEC-07)·탈퇴 잔존(SEC-03)·세션 정리(SEC-04 일부)·PR118-01~03은 코드에 반영됐다. 다음 항목은 아직 열려 있다.
   - 강화 기대 단계(SEC-08)
   - 공개 프로필 차단 반영(SEC-05)
   - 관리자 감사 로그(SEC-06)
   - CSP(SEC-04 일부)
   - 의존성 자동화(SEC-14)
   - 본문 사전 길이 검사(SEC-15)

## 3. SEC-1-01 수정 내용 (공개)

- **원인:** 계정 기록 저장소는 `record_id` 하나로 중복을 막았다. 기기 기록 가져오기(`/api/me/import`, 클라이언트 보고)와 서버 검증 결과 배달이 같은 키 공간을 쓴다. 온라인 경기의 기기 사본은 원래 같은 matchId를 쓰므로 키 공간을 나눌 수 없다. 그래서 기기 기록이 먼저 들어가면 서버 결과가 "중복"으로 처리되어 저장·정산되지 않았다.
- **수정(`worker/src/account.ts` `insert`):** 같은 ID에 클라이언트 보고 기록만 있으면, 서버 검증 기록이 그 행을 **대체**하고 정산 콜백을 정상 실행한다. 그 밖의 경우는 기존처럼 멱등이다. 이미 서버 검증 기록이 있으면 기기 업로드는 건너뛴다.
- **보존:** 경제 정책·보상량·원장 키(`m:<matchId>`)·기록 형식·스키마는 바꾸지 않았다. 서버 결과 대체는 기존 재화 정산과 같은 트랜잭션 안에서 일어난다.
- **회귀 테스트:** `tests/accounts.test.ts` "SEC-1-01" — 기기 기록 선점 뒤에도 서버 결과 저장, 정산 1회, 공개 전적 반영을 확인한다. 이후 재배달·기기 재업로드가 결과를 바꾸지 않는 것도 확인한다. 수정 전 코드에서는 같은 격리 재현이 `server record stored: false`, 정산 미실행, 공개 패배 0을 보였다.
- **남은 한계:** 이미 운영에서 이 방식으로 숨겨진 과거 경기는 복구되지 않는다(서버 결과는 방 48시간 보존 뒤 사라짐). 탐지 지표는 없다.
- **배포:** Worker 입력 변경이므로 CI-1.2 규칙상 main 병합 후 자동 배포 대상이다(`account.ts`는 수동 전용 경로가 아님 — 담당자 재확인 필요). 병합·배포는 운영자 승인 후.

## 5. 확인한 양호 통제 (요약)

- **OIDC:** PKCE S256·state·nonce, RS256 고정, iss/aud/azp/exp/iat 검증, `openid` 범위만 요청, 봉인된 `__Host-` 쿠키를 쓴다. 로그인 코드는 시작 탭의 상태 해시에 묶인 일회용이다. 열린 리디렉션은 없다.
- **세션:** 해시만 저장하고, 로그아웃·전체 로그아웃·탈퇴 시 삭제한다. 계정당 상한이 20개다. 토큰이 URL·로그·분석에 노출되지 않는다.
- **인가:** 모든 `/api/me/*`는 인증된 계정의 객체에만 도달한다. 관전자는 읽기 전용이고 명령을 거부한다. 관전 범위는 방장만 바꿀 수 있다. 좌석 ID는 인증된 소켓에서만 취한다. 이탈 몰수는 서버 유예로만 결정되고 클라이언트 `abandon`은 거부된다.
- **게임 무결성:** 클라이언트는 고정할 주사위 위치와 카테고리만 보낸다. 주사위는 서버 CSPRNG(거부 샘플링)이고 난수 상태를 저장하지 않는다. 명령은 멱등이고 버전을 확인한다. 같은 계정은 한 방에 한 좌석만, 진행 중 경기는 하나만 허용된다(예약).
- **경제:** 금액을 서버만 계산한다. 원장은 이벤트 ID 멱등이고, 음수 잔액은 CHECK 제약으로 막는다. 구매·뽑기·강화·슬롯은 단일 트랜잭션이다. 장착은 보유·슬롯을 검증한다. 일일·친구·같은 상대·AI 시작 상한이 있고, 재가입 신규 보상은 쿨다운으로 막는다. 원장 검증 기능도 있다.
- **웹:** 허용 출처 외 요청은 거부한다. 세션은 쿠키가 아닌 Bearer라 CSRF 영향이 없다. 렌더링은 React 텍스트만 쓰고, 상대 외형은 카탈로그 ID로 정규화한다. 채팅은 프리셋 ID만 쓴다. Service Worker는 API·인증 요청·쿼리 URL을 캐시하지 않는다. 외부 스크립트·CDN이 없다.
- **CI:** 자동 배포는 `push`·`main`·같은 저장소·성공만 받는다. 최소 권한과 `persist-credentials: false`를 쓰고, 배포 동시성 그룹을 공유한다. 비상 정지 변수가 있고, Cloudflare 응답을 로그에 출력하지 않는다. `pull_request_target`은 쓰지 않는다.

## 6. 운영자 확인·정리 절차 (코드로 확인 불가)

1. **구형 Cloudflare 시크릿(SEC-1-02):** 저장소·조직 수준에 이전 방식의 Cloudflare 토큰 시크릿이 남아 있는지 이름만 확인한다. 남아 있으면 다음 순서로 정리한다.
   1. 현재 `worker-production` 토큰으로 자동 배포가 성공하는지 기록한다.
   2. Cloudflare에서 구형 토큰의 마지막 사용 시각을 확인한다.
   3. 구형 토큰을 **폐기**한다.
   4. GitHub 시크릿을 삭제한다.
   5. 다음 자동 배포가 성공하는지 확인한다.
   
   임의 삭제는 하지 않았다.
2. `worker-production`: main 전용 배포 규칙, Environment 시크릿만 사용하는지, 비상 정지 변수 설정을 확인한다.
3. `worker-production-approval`: 필수 검토자, 자기 승인 방지, 관리자 우회 여부를 확인한다.
4. main 보호: PR 필수, `ci-result` 필수, 강제 푸시 금지, 우회 목록 없음.
5. 포크 PR 워크플로 승인 요구, 기본 `GITHUB_TOKEN` 읽기 전용 여부.
6. Cloudflare 배포 토큰 범위: 단일 계정 Workers Scripts 편집만 허용되는지 확인한다. Cloudflare 대시보드·Git 연동 등 GitHub 외 배포 경로가 없는지도 확인한다.
7. Workers Logs 실제 수집 항목(SEC-01), Workers Free 일일 사용량과 Durable Object 사용량 추이.
8. 백업·복구: DO PITR 복구 절차와 리허설은 아직 없다(C4 SEC-13/B-23).

## 7. 출시 차단 조건

- **현재 서비스(1차):** 재현된 Critical·High는 없다. SEC-1-02가 "존재함"으로 확인되면 정리 전까지 높음으로 취급한다.
- **신규 기능 출시 전 필수:**
  - **관리자 쓰기 기능:** 서버 측 역할 검사, 읽기·쓰기 권한 분리, 감사 로그, 관리자 세션 분리(C4 SEC-06)
  - **유료 재화:** C4 게이트 G-01~G-10
  - **사용자 건의 첨부:** 서버 측 형식·크기 검증과 저장형 XSS 방지
