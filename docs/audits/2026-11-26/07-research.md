# AI 연구 인프라 개선 제안

## 관측한 작업

기존 `scripts/research-v5/bench.ts`는 독립 주사위 스트림·선후공 교대·시드 family/shard/pair, 판단시간·단계 자료와 원시 점수 gzip을 기록한다. Workflow는 매트릭스, 작은 smoke, 샤드별 로그 통계와 아티팩트 집계를 이미 갖춘다. `scripts/research-v7/run-jobs.sh`는 로컬 병렬 실행과 파일 존재 기준의 샤드 재시작을 지원한다. 개별 샤드 안에서는 경기 완료 후에만 파일이 쓰인다. 프로젝트 문서의 WASM·압축 및 I2RO1 수치는 해당 팀 측정이다. [벤치](../../../scripts/research-v5/bench.ts), [로컬 샤드 실행](../../../scripts/research-v7/run-jobs.sh), [워크플로](../../../.github/workflows/v5-apex-research.yml), [V7 제품 후보](../../../docs/context/V7-PRODUCT-HANDOFF.md)

11/26 오후 KST의 읽기 조회에서 Claude 성장 브랜치의 한 배포 검증은 queued, 대상 smoke는 success였다. 별도 v7 연구 실행 #45726546327은 success였다. 성장 CI의 scope 완료 13:41:25와 build 시작 13:51:22 사이 9분 57초, build 자체 42초를 관측했다. 종속 작업 해제 후 경과 시간의 단일 관측이며 전체 러너 대기 분포는 미확인이다. 실제 샤드 시작 시간은 workflow의 `run_started_at`만으로 대체하면 안 된다. 각 job의 `started_at-created_at`와 step의 실행시간을 수집한다. [성장 CI](https://github.com/oyueo-mm/YachtLab/actions/runs/45756594253), [연구 실행](https://github.com/oyueo-mm/YachtLab/actions/runs/45726546327)

## 우선 실행안

| 단계 | 제안 | 합격 조건 |
|---|---|---|
| 로컬 PC | 깨끗한 체크아웃의 지정 SHA, 잠금 파일, Node/C++ 버전으로 수동 실행. 개발 샘플·프로파일링 먼저, 브라우저·확증 결과는 기존 연구 소유자와 시드 조정. CPU와 RAM에 맞춰 1→2→4 동시 작업 측정. | 오프라인 샘플의 동일 시드 점수·행동이 동일. 메모리 피크·완료 경기/분·판단 p95 기록. |
| 중단·재개 | 실험 키를 규칙·코드 SHA·모델/은행 해시·family·샤드 범위·상대·설정의 정규화 해시로 결정. 100~500 pair마다 임시 파일에 기록 후 원자적으로 최종 파일 이름으로 이동. | 중지 후 재개 결과와 중지 없는 결과에서 원시 seed pair·합계가 일치. 잘린 파일, 중복 pair, 설정 충돌은 명시적으로 실패. |
| 중간 집계 | pair별 승점, 합, 제곱합, 표본 크기, 진행률·CPU시간·RSS, 선언한 seed 구간을 보관. 병렬 작업자마다 별도 로그. 마감된 아티팩트만 집계하고 범위 중복은 스키마 검증으로 거부. | 대시보드 중간 상태와 전체 확증 결과를 명확히 구분. 아티팩트 저장소 접속 실패 시 로그의 샤드 통계로 진단한다. |
| 결과 캐시 | 결과와 초기화된 은행 자산 캐시를 분리. 규칙·DP 정책·산술 정밀도·코덱·컴파일러와 데이터 해시가 맞을 때만 재사용. 모델은 실험 메타데이터에 고정. | 캐시 히트·미스에서 parity와 해시를 확인. 임의로 다른 seed를 대신 채우지 않는다. |
| 최적화 | 기존 WASM 대비 TS/C++ 또는 Rust의 PMF 구축, 액션 평가, 직렬화, 메모리 배치 각각 프로파일. 실행 전후 warm/cold, CPU·wall·RSS를 나눠 기록. | 가령 브라우저는 준비 시간과 p95, 대국은 경기/초와 bit-identical 또는 사전 정의 허용오차를 통과해야 한다. |

`run-jobs.sh`의 파일 이름에는 pairs와 모델/은행 해시가 들어가지 않는다. 동일 디렉터리에서 설정을 바꾸면 기존 완료 파일을 새 결과로 오인할 수 있다. 완료 검증과 실험별 출력 디렉터리를 먼저 도입하는 편이 인프라 비용이 적다. 래퍼는 워커 오류가 파이프의 후속 명령 성공에 가려지지 않도록 종료 상태와 결과 검증을 별도로 남겨야 한다. 제품의 기본 AI 선정은 기존 소유자가 한다.

### 실행 자원과 통계

- 공개 저장소의 외부 PR을 개인 PC self-hosted runner로 받지 않는다. 필요 시 별도 접근 제한 실험 저장소에서 승인된 SHA 전용 일회용 VM을 사용한다. 최소 읽기 권한, 비밀/배포 자격 공유 금지, 제한된 네트워크와 작업 종료 후 VM 폐기·외부 감사 로그를 전제로 한다. 러너 단위 격리를 먼저 확보하면 개인 PC 수동 실행은 단기 대안으로 바로 사용할 수 있다. [GitHub 보안](https://docs.github.com/en/actions/reference/security/secure-use), [러너](https://docs.github.com/en/actions/reference/runners/self-hosted-runners)
- 로컬 수동 실행은 작은 파일럿과 프로파일, GitHub-hosted는 소수의 재현·확증 샤드에 쓴다. 시작 전 메모리 비용을 확인해 큐 벽시간을 줄이고, 예정 시간을 넘는 샤드는 파일럿 결과로 다음 배치 크기를 조정한다. 기존 Actions는 실행·취소하지 않았다.
- 같은 seed pair의 선후공 교대 결과를 단일 관측 단위로 사용한다. 대조와 후보에 동일한 독립 난수 흐름을 쓰되 모델에는 미래 난수 상태를 넘기지 않는다. 충분히 큰 효과만 조기 스크리닝하며 확증은 사전 정의한 고정 표본 또는 알파 지출/always-valid 방법을 사용한다. 다후보·여러 상대 비교는 기존 Holm 가족 정의를 따른다. 중간 로그는 보고용이며 임의 중단 후 고정 표본 p값을 쓰지 않는다.
- Node는 `node --cpu-prof --import tsx`, OS는 `/usr/bin/time -v`로 CPU/벽시간/RSS, 네이티브는 여건에 따라 `perf stat`, 브라우저는 Worker 타임라인과 메모리 샘플. 기존 TS·WASM 결과와 같은 시드·규칙·해시로 비교한다.
