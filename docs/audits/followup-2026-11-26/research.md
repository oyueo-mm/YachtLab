# 연구 재개와 캐시 충돌

기존 실행기의 격리 사본에 `dp vs greedy`, 개발 family 9099, shard 997, 1 pair(2경기)만 기록했다. 같은 출력 위치에서 래퍼에 2 pair를 요청하자 실행이 건너뛰어져 이전 1 pair 결과가 그대로 남았다. 출력 파일이 상대·family·shard로만 결정되고 완료 조건이 ‘파일 존재’라서 pairs, 코드 커밋, 정책 옵션, 모델/은행 변경과 중단에서 남은 파일을 구분하지 못한다. 또 워커 실행 뒤 grep을 쓰는 파이프는 실행기의 실패 종료를 보존하지 않고 후속 grep의 종료 상태를 돌려줄 수 있다. [실측](evidence/research-collision.json), [래퍼](../../../scripts/research-v7/run-jobs.sh), [연구 실행기](../../../scripts/research-v5/bench.ts)

시드의 현재 선형 주소에도 허용 범위가 충돌할 수 있다. 예를 들어 family 9099/shard 50/pair 0과 family 9100/shard 0/pair 547는 식의 해시 전 주소가 같다. 주소 수식에서 (50×20,011−1,000,003=547)이다. 합법 범위의 가능한 조합을 산술로 검증한 결과이며 진행 중인 특정 실험이 중복됐다는 판정은 아니다. 기존 seed family를 일방적으로 새 규칙으로 재해석하면 기존 데이터와 달라진다. [시드 함수](../../../scripts/research-v5/bench.ts#L28)

## 병행 적용 제안

1. 실행 ID는 규칙/스키마, 정확한 커밋, 실행기 내용, 양쪽 정책, 시드 계획과 오프셋·길이, 런타임/옵션, 모델과 PMF/DP 자산의 내용을 정렬된 SHA-256 매니페스트로 고정한다. 깨끗한 체크아웃 또는 모든 전이 의존성의 내용 해시로 커밋과 실행 소스가 일치하는지 확인한다. 시드 계획을 만들 때 원시 seed 영역이 다른 확증이나 샤드와 겹치는지 검사한다. 별도 seed v2는 사전등록 이후의 새 연구에서만 검토한다.
2. 샤드 내부는 고정된 pair 오프셋을 보존하고 100–500 pair 단위로 기록한다. 두 좌석을 다 수행한 pair만 완료로 계산한다. 파일을 임시 경로에 쓰고 동기화한 뒤 원자적으로 게시한다. 결과 받는 쪽은 해시·범위·중복을 확인한다. 재개 시 간격만 계산하고 한 번 기록한 pair는 덮지 않는다. 저장소 장애나 머신 재시작까지 보장하려면 저장소별 디렉터리 영속화와 손상 복구도 검증한다.
3. 중간 집계는 N·승점 합·제곱합·미완료 범위를 공유한다. 확증 판정은 마감과 승인된 검정 절차를 따라 보고하고, 취소된 실험 결과는 완료에서 제외한다. 원시 경기·버전별 latency와 분리된 통계도 병행한다.
4. 새 파일 경로의 독립 프로토타입은 입력 파일 변경과 pairs 변경에서 다른 ID, 프로세스 상태 없이 두 번째 호출로 재개, 동시 동일 게시, 다른 결과 충돌, 손상, 범위 중복 검사를 확인한다. 기존 실행기·시드·워크플로나 현재 실험에는 연결하지 않았다. [프로토타입](checkpoints.mjs), [재현 테스트](checkpoints.test.mjs)

충돌은 독립 임시 디렉터리에서 다음으로 재현한다. 마지막 명령에 다른 pair 수가 들어가도 결과 gzip 헤더의 pairs는 1이다.

```sh
trial=$(mktemp -d)
printf 'dp greedy 997\n' > "$trial/jobs.txt"
node --import tsx scripts/research-v5/bench.ts --a dp --b greedy --family 9099 --shard 997 --pairs 1 --out "$trial"
sh scripts/research-v7/run-jobs.sh "$trial/jobs.txt" 9099 2 "$trial" 1
```
