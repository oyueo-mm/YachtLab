# 첫 튜토리얼 성능 프로파일

2026-11-26 KST, 기준 `de312e8`. 같은 머신, Chromium 156, Lighthouse 13.6, 새 프로필, 같은 로컬 gzip 서버로 측정했다. 모바일 Lighthouse는 simulated CPU 4배 감속·150ms RTT·1.64Mbps 기본 프리셋을 사용했고, 상호작용은 별도의 Pixel 7 프로필에 CDP 4배 CPU 감속·150ms·200KB/s 다운로드를 적용했다. 두 실험은 각각 조건당 3회, 순서를 회차마다 바꿨다. 로컬 머신은 소프트웨어 WebGL이며 운영 CDN과 실제 모바일 GPU 수치는 별도다. ## 원인 분해

1. **네트워크와 앱 게이트.** `Tutorial`은 3D 모듈 로드가 끝날 때까지 주사위 DOM을 표시하지 않고 굴리기를 비활성화한다. `dice3d-loader`는 진입 JS와 분리되어 있어도 첫 방문의 효과에서 즉시 로드된다. 압축 3D stage 약 146.9kB, table 5.8kB, face-paint 1.7kB다. SW 등록을 지연한 경우 이 모듈 로드가 중앙값 약 1.02초였고 기준은 101ms였다. [튜토리얼](../../../src/play/Tutorial.tsx), [로더](../../../src/dice3d-loader.ts)
2. **초기 렌더링이 주된 블로킹 차이.** 3D 로드 경로를 유지하고 튜토리얼 렌더만 DOM으로 바꾸면 TBT가 821→276ms였다. 별도 3회 계측의 WebGL 생성·텍스처 객체 준비 중앙값은 85ms, 연결된 shader compile·texture upload·첫 draw 워밍업은 122ms였다. 워밍업 내부 중앙값은 컴파일 48ms, 텍스처 24ms, 첫 draw와 정리 45ms다. 구간별 중앙값의 합과 전체 중앙값은 다를 수 있다. 이 값은 소프트웨어 렌더러에서 관측한 API 경과시간이다. Lighthouse 최초 기준 표본에서 table에 귀속된 작업은 약 660ms이며, 워밍업 포함 여러 작업을 더한 값이다. [셸·물리 렌더러](../../../src/PhysicalDice.tsx), [워밍업](../../../src/dice3d/table.ts#L190), [구간 계측](evidence/warmup.json)
3. **PWA가 가시 페이지와 다운로드 집계를 바꾼다.** 기준·DOM·3D 지연·split의 테스트 서버는 첫 상호작용부터 SW 활성화까지 각각 약 2,119KiB를 보냈다. Lighthouse 페이지 전송 집계에는 일부 SW 채움 요청이 빠졌고 기준 3D 리소스는 페이지 집계상 0B였다. 서버는 같은 실행에서 stage와 1,324,626B DP gzip을 실제 전송했다. SW 등록만 늦추면 3D를 페이지에서 받고 사전 캐시에 다시 받아 총 약 2,269KiB였다. `defer-3d`도 SW가 3D와 DP를 모두 사전 캐시해 설치 총량은 줄지 않았다. [SW 설치](../../../src/pwa-worker.js), [매니페스트](../../../vite.config.ts)
4. **분리만으로 이득 없음.** 수동으로 Three·Cannon을 분리해도 튜토리얼이 서버에서 두 런타임을 즉시 요구한다. 전송량은 비슷하고 이번 반복에서는 TBT가 늘었다. LCP는 초기 DOM 변형에서 거의 그대로이고 첫 셸과 React 전환에 따른 CLS가 기준 0.15 수준이므로, 초기 셸의 레이아웃 예약은 3D 분리와 별도의 작업이다.

## 준비한 변경안

- 첫 안내는 같은 크기의 DOM 주사위로 바로 렌더링하고, ‘한 차례 연습’이나 다음 게임에서 3D를 준비하는 변형을 우선 검토한다. 첫 튜토리얼의 물리 연출을 유지해야 한다면 준비 동작 이후에만 3D 진입을 요청해 첫 조작 전후를 다시 비교한다. 중간에 렌더러를 바꾸면 킵 위치·포커스가 바뀔 수 있어 전환은 라운드 경계로 제한하고 사용자 모션 감소 선택을 우선한다. 이번 2.5D 변형은 측정용이며, 기존 3D 온보딩 계약은 제품 패치에서 그대로 썼다.
- 등록 5초 지연 단독은 적용 우선순위에서 제외한다. 오프라인 필수 셸과 이미 지원하는 규칙·AI를 버전 일관성을 유지해 설치하고, 선택적 시각 자료는 사용 또는 별도 설치 준비 단계에서 내려받는 방안을 시험한다. 완료·실패·새 버전 대기 조건을 기본 PWA 회귀로 확인한다.
- 분리로 실익을 얻으려면 첫 안내가 Three와 Cannon을 요구하지 않는 경로가 필요하다. 단계별 번들 bytes, 새로운 3D 준비 시간, 캐시 준비 시각, 실제 저성능 기기의 첫 킵·기록을 동시에 확인한다.
