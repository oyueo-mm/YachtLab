## 1. 결론 요약

1. **가장 시급한 것은 문서다.** 개인정보 처리방침·이용약관·연령 정책·운영자 연락처가 전혀 없다. 계정·전적·친구 관계를 DB로 관리하는 공개 서비스이므로 처리방침 공개 의무가 적용될 가능성이 높고, Cloudflare(한국 관할 옵션 없음)로의 국외 이전 고지도 필요하다. 코드 변경 없이 바로 해결할 수 있다(P0).
2. **보안 기본기는 견고하다.** OIDC(PKCE·state·nonce·RS256 고정·`openid`만), 해시 저장 세션·좌석 토큰, 계정별 DO 격리, 서버 권위 게임 엔진, 멱등·원자적 재화 원장, 프리셋 채팅, 기능 차단 스위치가 잘 갖춰져 있다. `npm audit` 취약점 0. **확인된 XSS·계정 간 접근·재화 복제 취약점은 없다.**
3. **확인된 결함은 주로 "주변부"다:** 탈퇴 후 일부 친구 관련 데이터 잔존(격리 재현), 세션 정리·수명 관리 미흡(격리 재현), 신고·제재 수단 부재, Worker 수동 배포의 브랜치·승인 통제 부재, 복구 절차 부재.
4. **가장 큰 잠재 위험은 로그와 가용성이다.** 운영 로그가 인증 정보·접속 정보를 필요 이상으로 수집하고 있을 가능성이 있어 소유자의 대시보드 확인이 필요하다(P0). 무료 플랜 일일 한도와 서비스 전역 상한은 비용을 막아 주지만, 남용되면 온라인 기능 전체가 멈출 수 있다.
5. **현재 무료 구조는 게임 규제상 위험이 낮다.** 무상 재화로만 돌리는 뽑기는 확률형 아이템 표시 의무 대상이 아닌 것으로 보이며(이미 자발적으로 공개 중), 환전·거래가 없어 사행성 위험도 낮다. 광고·결제·후원이 없으면 비영리 등급분류 면제 가능성이 높다 ⚖ — GRAC 서면 질의 권장.
6. **수익화는 게이트를 통과한 뒤에만.** 광고·결제·후원 중 하나만 넣어도 등급분류가 필수가 되고, 유상 재화가 뽑기와 연결되면 확률 표시 의무·손해배상 책임이 생긴다. 청약철회(미사용 유상 재화·시용 제공), 통신판매업·사업자 표시, 미성년자 결제 취소, 다크패턴·구독 해지 규정이 함께 온다. 원장은 지금 유상/무상을 구분하지 못하므로 결제 전에 재설계해야 한다. GitHub Pages의 상업 이용 제한도 걸리므로 커스텀 도메인·호스팅 이전을 권장한다.

## 4. 방법과 한계

- **소스 분석:** Worker 전 파일(`worker/src/*.ts`, 약 4,100줄), 방·프로토콜(`src/online/room.ts`), 경제·뽑기·소셜·닉네임·계정 클라이언트, 워크플로, 운영 문서. 열린 PR 4건은 `main`과의 diff로 검토.
- **격리 재현:** `main`의 계정·친구 로직을 메모리 SQLite에서 실행하는 스크립트로 SEC-03·SEC-04를 재현했다. 수정 전 공개를 피하기 위해 스크립트와 상세 보고서는 저장소에 넣지 않고 운영자에게 비공개로 전달했다(D-098). 수정 PR에서 회귀 테스트로 공개한다.
- **하지 않은 것:** 운영 엔드포인트 호출, 실제 Google 로그인, Cloudflare 대시보드 열람(SEC-01·SEC-12 등은 소유자 확인 필요), 부하·DoS 실험, 법령 원문 대조(네트워크 정책으로 실패 — SOURCES 재확인 목록).
- **기준 시점:** 법령 개정·플랫폼 약관·요금은 2026-11-27 검색 결과 기준이다. Cloudflare Observability 요금 체계가 2026-12-01에 바뀌므로 그 이후 재확인이 필요하다.
