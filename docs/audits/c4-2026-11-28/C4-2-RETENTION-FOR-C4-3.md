# C4.2 → C4.3 전달: 탈퇴·세션 관련 실제 보관 데이터 (처리방침 작성용)

> 출처: PR #124 (`claude/c4-2-account-security`) 코드 기준. 대상: C4.3 처리방침 초안(PR #126 `src/legal/content/privacy.md` 4·5항, `docs/legal/OPERATOR-CHECKLIST.md` B9·D1·D2).
> **효력 조건:** 아래 내용은 PR #124가 **main에 병합되고 운영 Worker에 배포된 뒤부터** 사실이 된다. 그 전까지 운영 중인 Worker는 C4 감사가 확인한 기존 동작이다(탈퇴자가 다른 회원에게 남긴 요청 잔존, 만료 세션 미정리). 배포 일자가 확정되면 처리방침 시행일과 맞춰야 한다.
> 법적 근거 문구는 정하지 않았다(⚖ = 법률 검토 필요). 이 문서는 사실만 전달한다.

## 1. 탈퇴 후에도 남는 데이터

| # | 데이터 | 어디에 | 목적 | 실제 보관 기간 | ⚖ |
|---|---|---|---|---|---|
| R1 | 탈퇴 일시 | 탈퇴한 계정의 저장소 | 탈퇴·재가입 반복으로 신규 회원 보상을 다시 받는 것 방지(기존) | 탈퇴 후 30일(+약 1분) 뒤 자동 삭제 | 기존 B9 |
| R2 | 탈퇴 전 사용하던 친구 코드(무작위 문자열) | 탈퇴한 계정의 저장소 | 같은 Google 계정으로 재가입한 계정이 옛 코드를 다시 받지 않게 하고, 옛 요청·친구·초대가 새 계정에 효력을 갖지 않게 함 | 탈퇴 후 30일. 재가입한 경우 그 시점부터 정리 완료와 30일 경과를 모두 충족하면 삭제 | 정당한 이익 등 |
| R3 | 정리 대기열: 탈퇴 계정의 내부 ID, 정리해야 할 상대 회원의 내부 ID, R2의 코드, 시도 횟수·다음 시각 | 탈퇴한 계정의 저장소 | 다른 회원 저장소에 남은 친구 요청·친구·초대·차단 정보를 지우라는 요청을 전달하고, 실패하면 다시 시도 | 건마다 전달에 성공하면 즉시 삭제. 실패 시 최대 16회 재시도(약 9.5일). 그래도 실패하면 보류 상태로 두고, 탈퇴 후 30일에 폐기. 운영자가 재시도를 요청하면 그때까지 다시 시도 | 정당한 이익 등 |
| R4 | 차단한 회원의 목록에 남는 탈퇴자 항목: 내부 ID(가명)·차단 시각. 화면에는 "탈퇴한 사용자"로만 보이고 닉네임·친구 코드는 지움 | **차단한 회원**의 저장소 | 같은 Google 계정으로 재가입해 차단을 회피하는 것 방지(차단한 회원 보호) | 기간 제한 없음. 차단한 회원이 차단을 해제하거나 탈퇴할 때 삭제 | **검토 필요**: 보관 근거, 기간 제한 여부 |
| R5 | 다른 회원의 경기 기록에 있는 상대 닉네임·내부 ID | 상대 회원의 기록 | 상대 회원 본인의 경기 기록(기존, SEC-05) | 그 회원이 탈퇴할 때까지. **C4.2에서 변경하지 않음** | 기존 고지 대상 |
| R6 | 진행 중이던 방의 좌석 정보 | 방 저장소 | 경기 진행(기존) | 방 정리 규칙(최대 48시간) | 기존 |
| R7 | 운영 집계: 정리 재시도·보류·재처리·폐기 건수, 잔존 데이터 발견·정리·색인 불일치 건수 | Hub 통계, Workers Logs | 정리 기능의 정상 동작 확인 | 숫자만 저장하고 ID는 없음. Hub 통계는 기존 보관 규칙을 따르고, Workers Logs는 3일 | 익명 집계 |

**탈퇴 시 즉시 지워지는 것(R1~R3 외 전부):** 프로필·닉네임, 세션·로그인 코드, 경기 기록·리뷰, 1인 기록, 재화·원장·아이템, 친구 목록·받은/보낸 요청·초대·차단 목록, 게스트 연결.

**다른 회원 쪽에서 지워지는 것:** 친구 관계, 그 친구가 받은 내 방 초대, 내가 보낸 요청(상대의 받은 요청), 내가 받은 요청(상대의 보낸 요청), 거절된 요청의 대기 기록, 내가 차단한 상대 쪽의 서버 전용 차단 기록. 친구 검색 색인에서도 빠진다. 전달은 탈퇴 즉시 이뤄지고, 실패한 건은 R3 절차로 다시 보낸다.

## 2. 로그인 세션

| 항목 | 실제 동작 |
|---|---|
| 유효기간 | 발급 후 30일(변경 없음) |
| 만료된 세션 정보 삭제 | 그 계정의 다음 로그인, 다음 인증 요청(하루 1회), 계정 알람(다음 만료 약 1분 후) 중 가장 이른 때 |
| 계정당 개수 | 유효 세션 최대 20개. 21번째로 로그인하면 가장 오래된 세션 1개가 끝남 |
| 로그아웃 / 모든 기기 로그아웃 / 탈퇴 | 해당 세션 즉시 삭제 / 전부 즉시 삭제 / 전부 즉시 삭제 |
| 로그인 코드 | 2분 유효, 다음 정리 때 삭제 |
| 저장 형태 | SHA-256 변환 값만 저장(변경 없음) |

→ 초안의 `[[확인 필요: 만료 세션 정보 자동 정리(백로그 B-11) 적용 후 문구 확정]]`은 배포 이후 "만료 후 자동 삭제"로 확정할 수 있다. 단, §3-7의 예외가 있다.

## 3. 미정리 데이터의 한계 (처리방침에서 "즉시·완전 삭제"를 약속하면 안 되는 부분)

1. **배포 전에 탈퇴한 회원이 남긴 데이터.** 다른 회원의 받은/보낸 요청, 한쪽에만 남은 친구 행, 차단 목록의 닉네임·코드가 남아 있다. 정리 기능(`FRIEND_RESIDUE_CLEANUP`)은 구현돼 있지만 **기본 꺼짐**이다. 운영자 결정은 "배포 후 별도 승인 하에 7일 dry-run(집계만)"이며, **실제 삭제는 미승인**이다. 승인 전까지는 남는다.
2. **배포 전에 만들어진 차단.** 서버 전용 역방향 기록이 없다. 그래서 배포 후에 차단된 회원이 탈퇴해도, 차단한 회원의 목록에서는 닉네임·코드가 익명화되지 않는다. 1번의 정리 기능을 승인해야 해결된다. 업그레이드 검사로 확인한 사실이다.
3. **재시도 중인 정리.** 상대 회원 저장소에 일시적으로 연결되지 않으면 그 회원 쪽 정보는 재시도가 성공할 때까지(최대 약 9.5일, 보류 시 30일) 남는다.
4. **30일까지 끝내 실패한 정리.** 해당 상대 회원 쪽 정보는 1번의 정리 기능을 승인해야 지워진다.
5. **친구 화면을 열지 않는 회원.** 1번의 정리 기능은 회원이 친구 목록을 열 때 하루 1번 동작한다. 화면을 열지 않는 회원 쪽 잔존 정보는 남는다.
6. **전역 친구 색인 정리 실패.** 옛 친구 코드가 탈퇴 계정 내부 ID와 연결된 채 남을 수 있다. 이 코드로는 아무 정보도 조회되지 않으며, 재가입하거나 재시도가 성공하면 지워진다.
7. **배포 전에 마지막으로 로그인하고 다시 오지 않는 계정.** 이 계정의 만료 세션 행(변환 값)은 그 계정이 다시 요청할 때까지 남는다. 전체 계정을 훑는 일괄 작업은 없다.
8. **다른 회원의 경기 기록**(R5)과 **차단한 회원의 가명 ID**(R4)는 탈퇴로 지워지지 않는다.

## 4. 초안 문구에 대한 사실 확인 메모

- 5항 "그 계정의 저장소 전체를 즉시 삭제하고 … 탈퇴 일시만 30일 동안 남긴 뒤": 배포 후에는 **R2·R3도 남는다**. 그래서 "탈퇴 일시, 탈퇴 전 친구 코드, 다른 회원 쪽 정리 요청 기록"처럼 적는 것이 정확하다.
- 5항 "친구에게서 내 정보를 지우도록 요청하며": 배포 후에는 대상이 **친구, 친구 요청을 주고받은 회원, 차단 관계의 회원**으로 넓어진다. 실패하면 최대 30일까지 다시 시도한다.
- 4항 보관 표에 R4(차단 가명 ID, 기간 제한 없음, 차단자가 해제할 때까지)를 추가할지 법률 검토가 필요하다.
- `OPERATOR-CHECKLIST` D1·D2는 PR #124 배포 시점에 "완료(배포일 기재)"로 바꾸고, 위 §3 한계를 함께 적을 수 있다.
