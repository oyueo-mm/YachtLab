# 모바일 UX · 주사위 화질/성능 · 효과음 · 요트/입장 연출 (2026-11-23)

> **후속(2026-11-24):** 아래 "최악 프레임 100~117 ms"의 원인은 물리 미준비가 아니라 GPU 첫 그리기였고, 개선·재측정 결과는 [PHASE-A-2026-11.md](./PHASE-A-2026-11.md)에 있다. 휴대폰 배치도 그 문서의 내용으로 바뀌었다(점수 칩 위·한 화면).

## 1. 모바일·태블릿 UI

### 1-1. 점수판 잘림 — 원인과 해결
- **재현:** 768×1024, 820×1180, 900×600, 1024×768, 1180×820, 1280×800, 1366×1024 및 가로 휴대폰 844×390·932×430에서 측정.
  - 점수표 내용 폭은 약 431px인데 옆 패널은 318~396px이고 `overflow: hidden`이었다.
  - 그래서 오른쪽 플레이어 열 1~2개가 잘렸다(`clippedCols` 1~2). 761px부터 1440px 이하 데스크톱까지 모두 해당한다.
  - 가로 휴대폰에서는 패널 높이가 화면보다 커서 아래쪽(요트 칸)이 화면 밖으로 밀렸다.
- **해결** (`src/responsive.css`)
  - 표를 `table-layout: fixed; width: 100%`로 패널 폭에 맞췄다.
  - 컨테이너 쿼리로 좁은 패널에서는 다섯 눈 장식 아이콘을 숨긴다. 칸 이름·도움말·두 플레이어 열은 항상 보인다.
  - 옆 패널은 `max-height: calc(100dvh − 상단)`과 내부 스크롤을 쓰므로 모바일 주소창 높이 변화에도 맞춰진다.
  - 가로 휴대폰은 주사위판이 화면 높이에 맞도록 조정했다.
- **회귀 테스트:** `tests/ui/responsive.spec.ts`가 320~1440px, 세로·가로 18개 크기를 검사한다.
  - 두 플레이어 열이 패널 안에 있는지
  - 12칸 모두 도달 가능한지(휴대폰은 점수 시트)
  - 굴리기 버튼과 주사위가 보이는지
  - 가로 넘침이 없는지

### 1-2. 모바일 플레이 UI
- **배치:** 주사위판 → 굴리기 버튼 → **추천 점수 바로 기록**(최대 3개, 한 번 탭) → 점수 기록(전체 시트) → 점수 요약 → 보조 메뉴.
  - 자주 쓰는 동작이 엄지 영역(주사위판 아래)에 모인다.
  - 점수 기록은 추천 칸이면 1탭, 그 밖에는 2탭(시트 열기 → 칸).
  - 자동 기록은 없다.
- **터치:** 굴리기 56px, 점수 버튼 52px, 추천 칸 52px. 하단 안전 영역은 `env(safe-area-inset-bottom)`으로 확보했다.
- **화면 크기별:** 태블릿·데스크톱은 기존 2단(주사위판 + 항상 보이는 점수판)을 유지하고 점수판 잘림만 고쳤다. 가로 휴대폰은 2단이며 점수판이 내부 스크롤된다.

### 1-3. 중복 문구 정리
- "나의 차례", "굴림 n/3"은 AI·온라인 대전에서 모든 화면 크기에 대해 시각적으로 숨겼다. 스크린리더용으로는 남겨 두었다.
  - 남은 굴림은 굴리기 버튼("2회 남음")에, 차례는 점수 요약 강조와 온라인 버튼("OO 님의 차례")에 이미 표시된다.
- 로컬 다인 대전은 한 화면을 여러 사람이 쓰므로 "OO의 차례"는 유지하고 굴림 수만 숨겼다.
- "AI의 마지막 판단"(연구 정보)은 연구용 모델을 고른 경우에만 표시하고, 공개 5단계 난이도에서는 숨겼다.

## 2. 3D 주사위 화질·성능

### 원인 분석
- **흐림:** "자동" 품질이 휴대폰에서 3D 기본 등급(캔버스 1.25배, MSAA 없음, 면 텍스처 128px)을 썼다.
  - 2.6~3배 화면에서는 주사위가 절반 이하 해상도로 그려진 뒤 확대된 것이다.
- **중복 렌더:** 애니메이션마다 rAF에서 장면 전체를 렌더해, 여러 주사위가 동시에 선반으로 미끄러지면 한 프레임에 장면을 여러 번 그렸다.
- **굴림 시작 지연:** 탭한 직후 메인 스레드에서 물리 시뮬레이션(깨끗한 착지가 나올 때까지 최대 14회 시도)을 끝내야 첫 프레임이 나왔다.

### 개선
- **해상도 정책** (`renderPolicy`)
  - 자동·고화질: 기기 픽셀의 최대 2배. MSAA는 1.5배 미만 화면에서만 켠다(2배에서는 픽셀이 이미 가장자리를 부드럽게 하고 MSAA 비용이 크다).
  - 성능 우선: 최대 1.5배.
  - 면 텍스처는 항상 256px이며 밉맵과 비등방성 필터를 쓴다.
- **적응형 화질(자동):** 굴림 프레임 p95가 22ms를 넘는 경우가 2번 연속이면 2 → 1.5 → 1.25배로 낮춘다(세션 동안 유지).
- **설정:** 자동 / 고화질 / 성능 우선 / 간단(2.5D).
- **렌더 티커 하나:** 모든 애니메이션이 갱신한 뒤 프레임당 한 번만 렌더한다.
- **물리 사전 계산:** 던지기 물리는 결과 눈과 무관하다(눈은 면 재배치로 적용).
  - 주사위가 멈춰 있는 동안 실제 유휴 시간에만(애니메이션 중에는 하지 않음) 다음 던지기를 미리 시뮬레이션한다.
  - 굴릴 때 테이블·위치·고정·방향이 같으면 재사용한다. 결과 눈과 엔진 상태는 바뀌지 않는다(단위 테스트로 확인).

### 측정 (자동화 브라우저 에뮬레이션 — 실제 기기 측정 아님)
- **환경:** Playwright Chromium 헤드리스, **소프트웨어 GPU(SwiftShader)**, Pixel 7 에뮬레이션(412×915, DPR 2.625). "자동" 품질, AI 대전 5회 굴림, 굴림 간 1.5초.
- **해석의 한계**
  - CPU 4배 감속은 CDP `Emulation.setCPUThrottlingRate`로 중저가 기기를 흉내 낸 것이다.
  - 소프트웨어 GPU라 렌더 비용이 CPU에 묶여 있으므로, 실제 휴대폰 GPU의 fps·발열과 같지 않다.

| 항목 | 이전 (main) | 이후 |
|---|---|---|
| 캔버스 해상도 (CSS px당) | 1.25 | 2.0 (CPU 4배 감속에서는 적응형으로 1.5) |
| 탭 → 첫 프레임 중앙값 (감속 없음, 3회) | 18~41 ms | 10~13 ms |
| 탭 → 첫 프레임 중앙값 (CPU 4배 감속, 3회) | 78~95 ms | 19~30 ms |
| 물리 시뮬레이션 중앙값 (4배) | 57~73 ms | 2~6 ms (사전 계산 재사용 4/5회) |
| 굴림 프레임 p95 (감속 없음) | 16.7 ms | 16.7~16.8 ms |
| 최악 프레임 (4배) | 66~83 ms | 100~117 ms (게임 첫 굴림: 사전 계산 전, 2배 해상도) |
| 굴림 애니메이션 길이 | 약 1.0~1.1 s | 약 1.0~1.1 s (변화 없음) |

- **아직 검증 못한 것:** 실제 기기(iPhone·Galaxy 등)의 fps, 발열, 배터리. 실제 휴대폰 GPU의 2배 해상도 비용은 적응형 화질이 처리하도록 설계했지만 실기기 측정은 하지 않았다.
- **선명도:** 같은 에뮬레이션 스크린샷에서 눈·모서리가 이전보다 선명하다(캔버스 픽셀 1.6배). 실제 기기에서 육안 확인이 필요하다.

## 3. 효과음

- **자산:** 모두 브라우저 Web Audio로 합성한다(`src/sound.ts`). 외부 음원 파일이 없어 라이선스 문제가 없다.
- **v2 설계**(플라스틱 주사위 모델)
  - 바닥 충돌: 감쇠하는 공진 모드 3개(약 1.9k·2.9k·4.4kHz)와, 충돌 강도에 비례하는 테이블 저음(150~220Hz)으로 낸다.
  - 주사위끼리: 더 높고 짧은 모드(약 3.3k·5k·6.8kHz)를 쓰고 저음은 없다.
  - 구르기: 모서리가 닿는 작은 틱이 속도에 따라 2~5개 연달아 난다.
  - 멈춤: 점점 약해지고 느려지는 2~3번의 틱이다.
  - 던지기: 손에서 주사위끼리 짧게 부딪히는 소리다.
  - 매 충돌마다 피치 ±6~12%, 음량, 좌우 위치를 무작위로 바꾼다.
- **과부하 방지**
  - 충돌음은 동시에 최대 10개까지 울린다.
  - 같은 종류는 18~80ms 안에 반복하지 않는다(훨씬 강한 충돌만 예외).
  - 강도 임계값을 두고, 마스터 버스의 컴프레서로 클리핑을 막는다. 이 동작은 단위 테스트로 확인한다.
  - 물리 쪽 기존 제한(던지기당 16회, 40ms 간격)도 유지한다.
- **모바일 재생 제한:** 첫 사용자 입력에서만 오디오를 깨우는 정책은 유지했다. 음소거와 볼륨은 저장된다.
- **재접속 효과음 일괄 재생 수정:** 재접속·새로고침 시의 따라잡기 동기화(welcome)는 점수 변화를 소리 없이 반영한다.
- **비교 시연:** 연구실 → 주사위 실험실 → **효과음 시연**에서 현재(v2)와 이전(v1)을 같은 버튼으로 비교할 수 있다. 실험실을 떠나면 게임은 항상 v2를 쓴다.
- **품질 확인 한계:** 최종 음질은 사람이 직접 들어 봐야 판단할 수 있다. 실제 휴대폰 스피커에서는 확인하지 못했다.

## 4. 요트 자동 강조
- 굴림이 화면에서 멈춘 뒤 다섯 눈이 같으면, 테이블에 "요트!" 플래시(1.7초)가 뜨고 반짝이는 효과음이 난다.
  - 클릭을 가로채지 않으며 입력을 잠그지 않는다.
  - 굴림마다 한 번만 재생한다(roll event 기준). 새로고침·재접속·다시 그리기로는 재생되지 않는다.
- 현재 플레이어의 비어 있는 요트 칸(데스크톱 점수판·휴대폰 점수 시트)과 휴대폰 점수 버튼("요트! 점수 기록")은 점수를 고를 때까지 강조된다.
- **점수는 자동으로 기록하지 않는다.**
- 온라인에서는 같은 굴림이 상대 화면에서도 재생되므로 양쪽 모두 같은 순간에 강조된다.
- 동작 줄이기 설정에서는 정적 테두리로 표시한다.
- 라지 스트레이트(제안만, 미구현): 요트보다 약한 강조로, 플래시 없이 점수 칸 테두리만 1회 깜빡이고 효과음은 기존 `combo` 정도를 권장한다.

## 5. 온라인 입장 효과음
- 다른 플레이어의 `playerJoined` 이벤트가 **실시간 업데이트**로 도착하면 짧은 2음 차임을 낸다.
- 다음 경우에는 소리를 내지 않는다.
  - 내 첫 화면 로드와 재접속·새로고침(따라잡기 동기화)
  - 상대의 재접속(이벤트 없이 접속 상태만 바뀜)
  - 이미 알린 플레이어(플레이어 ID당 1회)
- 서버 재전송 시 오래된 이벤트는 기존 seq 필터가 거른다.
- 음소거를 따르며, **서버 프로토콜 변경이 없어 Worker 재배포가 필요 없다.**
