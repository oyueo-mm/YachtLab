# 3D 물리 주사위 — 프로토타입 설계와 검증

> 상태: 게임·홈·주사위 실험실에 적용. 기존 2.5D 연출은 삭제하지 않고 **선택 가능한 품질**이자 **자동 대체 경로**로 유지한다.
> 직접 비교: 연구실 → **주사위 실험실**(`#dice-lab`).

## 1. 핵심 원칙: 결과와 연출의 분리

- 오프라인에서는 기존 엔진(`src/engine.ts`, `src/multi-engine.ts`)이, 향후 온라인에서는 서버가 눈을 결정한다. 3D 연출은 **이미 확정된 값**을 받아 보여 줄 뿐이다.
- 엔진의 난수·점수 계산은 한 줄도 바뀌지 않았다. 주사위 연출 코드는 엔진에 값을 돌려주지 않는다.

## 2. 구현 방식

| 단계 | 내용 |
|---|---|
| 1. 사전 시뮬레이션 | `src/dice3d/physics.ts` — [cannon-es](https://github.com/pmndrs/cannon-es)(MIT) 강체 물리. 바닥·벽(트레이 경계)·주사위 간 충돌, 마찰, 반발, 감쇠. 고정된 주사위는 질량 0 장애물. 1/120초 스텝, 60fps 기록. |
| 2. 면 배치 결정 | 시뮬레이션이 끝났을 때 위를 향한 **물리 면**을 읽고, 엔진 값이 그려진 면이 그 자리에 오도록 큐브 대칭 회전(24개 중 하나) `C`를 고른다. 화면의 큐브는 처음부터 `몸체 방향 × C`로 그린다 → **굴러가는 도중 눈이 바뀌거나 마지막에 갑자기 회전하는 일이 없다**. |
| 3. 품질 검사 | 모든 주사위가 시간 안에 정지, 바닥에 평평하게 착지(위쪽 법선 내적 > 0.985), 트레이 안. 실패하면 다른 초기값으로 최대 10회 재시도. 그래도 실패하면 그 굴림만 2.5D로 대체(`ok: false`). |
| 4. 정렬 | 모두 멈춘 뒤 각 주사위가 바닥을 미끄러지며 자기 칸(드래그 정렬·고정에 쓰는 DOM 주사위 위치)으로 이동. 이때 **수직축 회전만** 하므로 윗면은 바뀌지 않는다. 끝 방향은 2D 주사위 그림과 같은 눈 방향. |
| 5. 렌더링 | `src/dice3d/stage.ts` — three.js(MIT). 트레이 위에 `pointer-events: none` 캔버스를 겹치고, 날아가는 동안 해당 DOM 주사위 얼굴만 숨긴다. 끝나면 다음 프레임에 DOM 주사위로 교체. 1 world unit = 주사위 한 변(CSS px로 정확히 환산되는 원근 카메라). |
| 6. 소리 | 시뮬레이션이 기록한 충돌(바닥/벽/주사위, 충돌 속도)을 **화면에 해당 프레임이 그려질 때** 재생. 강도→음량·밝기, 45ms 간격·굴림당 14개 제한. 취소되면 렌더 루프와 함께 남은 소리도 재생되지 않는다. |

### 입력·접근성

- 굴리는 동안 굴리기 버튼·주사위·점수판 기록이 비활성(전역 "굴림 중" 상태, 안전 타임아웃 포함) → 중복 굴림·다른 주사위로 잘못 전달되는 입력 없음. AI도 주사위가 멈춘 뒤 다음 행동을 한다.
- 고정·드래그 정렬·키보드(Alt+←/→)는 기존 DOM 버튼 그대로. 스크린리더용 `aria-label`은 항상 엔진 값.
- `prefers-reduced-motion` → 움직임 없음. "모션 간단히" 또는 저사양(코어 ≤2 또는 메모리 ≤2GB) → 2.5D 가벼운 연출. WebGL 불가 → 2.5D.
- 품질: 자동(데스크톱 3D 고급, 760px 이하 3D 가볍게) / 3D 고급(그림자 맵·안티에일리어싱·DPR 2) / 3D 가볍게(블롭 그림자·DPR 1.25) / 2.5D.

### 로딩

three.js + cannon-es는 별도 청크(`stage-*.js`)로 분리되어 **유휴 시간에 미리 로드**된다. 아직 로드되지 않았으면 그 굴림은 2.5D로 진행된다. 홈·게임 첫 화면의 초기 번들에는 포함되지 않는다.

## 3. 검증 결과 (실제 측정)

### 물리 일괄 검증 (Node, 각 200회, 5개 중 2개 고정 비율 1/3)

| 트레이(주사위 단위) | 깨끗한 착지(3D 사용) | 최종 눈 일치 | 시간 내 정지 | 길이 중앙값 / p95 | 시뮬레이션 평균 |
|---|---|---|---|---|---|
| 데스크톱 9.5 × 5.5 | 200/200 | 200/200 | 200/200 | 82 / 103 프레임 | 4.4ms |
| 모바일 5.2 × 5.6 | 200/200 | 200/200 | 200/200 | 90 / 110 프레임 | 9.5ms |
| 작은 화면 5.0 × 4.4 | 198/200 | 200/200 | 197/200 | 89 / 111 프레임 | 15.2ms |
| 매우 좁음 4.6 × 4.0 | 191/200 | 200/200 | 186/200 | 91 / 122 프레임 | 24.4ms |

- 모든 경우 주사위 중심 간 최소 거리 ≥ 1.0(겹침 없음), 트레이 이탈 0, 끝부분 프레임당 최대 회전 ≈ 9°(정렬 단계의 수직축 회전).
- 재생 속도 1.15배 → 데스크톱 중앙값 약 1.2초, p95 약 1.5초.
- 단위 테스트(`tests/dice3d-physics.test.ts`): 두 트레이 크기 × 36회, 모든 눈 1~6·모든 위치에서 최종 윗면 = 엔진 값, 최종 위치 = 칸, 최종 방향 = 2D 주사위 그림과 같은 방향, 결정성, 고정 주사위 비애니메이션.

### 브라우저 검증 (Playwright, Chromium 헤드리스, 데스크톱·모바일)

- 3D 고급/가볍게 각각: 굴림 중 캔버스 표시, 5개(재굴림 시 고정 제외 3개)만 3D, 정지 후 3D 최종 눈 = 엔진 목표 = DOM 주사위 값, 고정 주사위 라벨 불변.
- 빠른 연속 입력(더블클릭+Enter) → 굴림 1회.
- WebGL 차단 → 2.5D로 대체, 3D 품질 옵션 비활성.
- 주사위 실험실: 지정 눈(1,2,3,4,6)으로 3D 굴림 일치, 실제 트레이 크기로 300회 일괄 검증 300/300 일치.
- 헤드리스(소프트웨어 렌더링 포함 환경) 프레임 시간 평균 약 17ms(첫 프레임은 셰이더 컴파일로 50~120ms).

### 검증하지 못한 것 (수동 확인 필요)

- 실제 저사양 휴대폰의 프레임 유지(헤드리스 Chromium 측정만 함).
- 효과음의 실제 청감(재생 기록·타이밍만 자동 검증).
- 실제 손가락 스와이프의 감각(마우스 제스처만 자동 테스트).

## 4. 2.5D와 3D 비교

| | 2.5D (기존) | 3D 물리 (신규) |
|---|---|---|
| 표현 | 평면 주사위 이미지의 이동·회전·확대 | 입체 큐브, 여러 면이 실제로 보이며 그림자 |
| 움직임 | 미리 정한 키프레임(주사위마다 경로 다름) | 실제 강체 물리(충돌·마찰·감쇠, 서로 부딪침) |
| 눈 표시 | 중간에 무작위 눈을 보이다 마지막에 실제 눈 | 처음부터 물리 몸체에 고정된 면 배치 — 바뀌지 않음 |
| 정지 시점 | 주사위마다 약간 다름 | 물리에 따라 주사위마다 다름 |
| 길이 | 약 0.7초 | 약 1.2초(중앙값) |
| 비용 | 의존성 없음 | 지연 로드 청크(아래), 굴림당 시뮬레이션 5~25ms |
| 대체 | — | WebGL 불가·착지 실패·로드 전 → 2.5D |

## 5. 알려진 한계와 개선안

- 정렬 단계(약 0.25초)에서 주사위가 칸으로 이동할 때 서로의 경로가 겹쳐 보일 수 있다(충돌 처리 없음). 개선안: 정렬 경로 충돌 회피 또는 칸 위치를 시뮬레이션 목표 영역으로 사용.
- 시뮬레이션은 메인 스레드에서 실행(굴림당 최대 수십 ms). 매우 좁은 트레이에서 재시도가 늘면 체감될 수 있다. 개선안: Web Worker로 이동.
- 아주 좁은 트레이(4.6×4.0 이하)에서는 약 4.5% 굴림이 2.5D로 대체된다.

## 6. 3차 개편: 자유 착지 + 고정 선반 (현재 게임 방식)

2차의 "정지 후 일렬 정렬 → 2D 주사위로 교체" 방식은 게임에서 더 이상 쓰지 않는다(물리 모듈에는 `landing: "slots"` 옵션으로 남아 있고 기존 테스트가 이를 검증한다).

| 구성 | 동작 |
|---|---|
| 굴림 트레이 | `src/PhysicalDice.tsx` + `src/dice3d/table.ts`. 첫 굴림은 트레이 가장자리에서 던지고, 재굴림은 **각 주사위가 놓인 자리에서 다시 튕겨 올린다**. 처음 8프레임은 현재 자세에서 부드럽게 이어지도록 보간 → 재굴림 시작에 순간이동 없음. 정지 후 위치·회전을 그대로 유지하고 3D 모델도 유지(2D 교체 없음) |
| 고정 선반 | 트레이 아래 별도 영역. 주사위를 누르면 자기 칸(순서 = `order`)으로 미끄러져 이동(수직축 회전만 → 윗면 유지). 선반에서 다시 누르면 원래 놓였던 자리 근처의 빈 곳으로 돌아감. 5개 모두 고정 가능 |
| 굴리기 버튼 | 캔버스 바깥(아래) 독립 영역. 캔버스는 트레이+선반 영역만 덮는다(테스트로 겹침 없음 확인) |
| 입력 | 각 주사위 위에 투명한 실제 버튼(포커스·Enter·스크린리더 라벨 "주사위 n, 값, 고정됨"). 포인터 위치에서 **가장 가까운 주사위 중심**을 선택 → 겹쳐도 원하는 주사위 선택, 주변 0.75칸 틈도 인식. Alt+←/→로 선반 순서 변경 |
| 엔진 일치 | 고정 상태 = 엔진 `held`, 굴림 대상 = 고정 안 된 주사위, 점수 = 보이는 5개 값(테스트로 Choice 합 확인) |
| 드문 경우 | 주사위가 다른 주사위 위에 멈추면 가까운 빈 바닥으로 미끄러뜨림(윗면 유지) |
| 렌더링 | 주사위가 움직일 때만 렌더(대기 중 GPU 0). 첫 굴림 끊김을 줄이려고 테이블 생성 시 셰이더를 미리 컴파일. 화면을 떠나면 WebGL 컨텍스트 해제(왕복 3회 후 캔버스 1개 이하 테스트) |
| 대체 | 3D 모듈 로드 전·WebGL 불가·모션 간단히·동작 줄이기 → 기존 DOM 주사위 줄(2.5D/무모션)에서 같은 고정·재굴림·점수 규칙. 표시 방식 전환은 차례가 바뀔 때만 |

### 측정 (개발 서버, 헤드리스 Chromium)

- 물리 계산 약 58ms(개발 모드, 시도 1회), 첫 프레임까지 약 170ms. 3D 고급(그림자)은 소프트웨어 렌더링 환경에서 평균 프레임 약 38~50ms, 3D 가볍게는 약 17~20ms. 실제 GPU 기기의 60fps 유지는 **수동 확인 필요**.
- 자유 착지 단위 테스트: 데스크톱·모바일 트레이 각 30회 — 최종 윗면 = 엔진 값, 트레이 안, 중심 간 거리 > 0.95, 일렬 정렬 0회, 재굴림 첫 프레임이 이전 자세에서 시작.

## 7. 4차 개편: 더 강한 던지기 · 족보 완성 연출 · 무광 테이블

### 던지기 물리 (`THROW_PROFILES`, 기본 `vigorous`)

단순 재생 속도 증가가 아니라 물리 초기 조건과 재질을 바꿨다. 3차 값은 `legacy` 프로필로 남겨 같은 조건에서 비교한다(`tests/dice3d-physics.test.ts`).

| 항목 | legacy (3차) | vigorous (4차) |
|---|---|---|
| 중력 | 52 | 60 (더 빠른 낙하·충돌) |
| 바닥 반발 / 마찰 | 0.30 / 0.40 | 0.42 / 0.34 |
| 주사위끼리 반발 | 0.30 | 0.44 |
| 벽 반발 | 0.50 | 0.58 |
| 선형·각 감쇠 | 0.20 / 0.26 | 0.10 / 0.17 (오래 굴러감) |
| 던지는 높이 | 1.25 | 2.3 (공중에서 시작) |
| 초기 각속도 | 30·18·30 | 52·30·52 |
| 주사위별 세기 | 동일 | 0.8~1.25배 (속도·회전 모두 주사위마다 다름) |
| 재굴림 | 제자리에서 약하게 | 제자리에서 더 높이(5.2~7.6) 튕겨 올림 |
| 재생 속도 | 1.15× | 1.25× |

**측정(150회, 5개 중 일부 고정 포함, 3개 트레이 크기 평균):**

| 지표 | legacy | vigorous |
|---|---|---|
| 최고 속도 (주사위 변/초) | 10.5~12.4 | 14.5~16.0 (+40%) |
| 주사위당 공중 회전량 | 209~229° | 355~424° (약 1.8배) |
| 첫 바닥 충돌 강도 | 7.9~8.2 | 12.3~13.1 (+60%) |
| 충돌 횟수 | 34~43 | 52~62 |
| 깨끗한 착지 / 눈 일치 | 150/150, 150/150 | 150/150 (좁은 트레이 149/150), 150/150 |
| 길이 중앙값 / p95 (프레임) | 68 / 84 | 77 / 104 |

전진 속도는 착지가 먼 벽에 몰리지 않도록 별도로 조정했다(수정 전 데스크톱 윗 1/3에 66% → 현재 약 40% 이하, 테스트로 고정). 눈 일치·트레이 안 유지·겹침 없음·끝부분 급회전 없음은 그대로 검증된다.

### 족보 완성 연출 (점수 규칙·엔진 불변)

- `src/combo.ts`: 족보를 이루는 주사위 **id** 선택(순수 함수). 겹치는 눈은 낮은 id. 포커는 네 개만 강조하지만 점수는 엔진의 5개 합계. 0점은 빈 목록(연출 없음). 7,776가지 조합 × 12칸 전수 테스트.
- `src/score-fx.ts`: 점수 기록 직전 `announceScore`로 연출 이벤트를 알린다. 이벤트는 표시 전용이며 엔진에는 영향이 없다. 오래된 이벤트(400ms 초과)는 무시.
- 3D: `DiceTable.celebrate` — 해당 주사위만 위로 솟구침(스프링)→머무름→복귀, 높이·크기·수직축 회전 몇 도만 변경(윗면 불변), 나머지는 약간 작아짐. 요트·라지는 더 높고 길게. 원근으로 화면 밖에 잘리지 않도록 가장자리 주사위는 안쪽으로 당김. 끝나면 짧게 페이드 후 다음 턴으로.
- 연출 동안 굴리기·주사위·점수·AI 다음 던지기를 잠금(`beginDiceMotion`). 재대결·화면 이탈 시 이벤트 취소와 함께 정리.
- 2.5D / 동작 줄이기: 같은 주사위들을 줄로 띄우는 간소 연출(동작 줄이기는 정적).
- 라벨(족보명 +점수)은 잠긴 굴리기 버튼 자리에 표시. 효과음: `combo`(일반), `grand`(라지), 요트는 기존 `yacht`.

### 무광 테이블

조명은 부드러운 반구광 + 약한 직사광, 재질 거칠기 0.62, 환경 반사 없음. 그림자 맵·바닥 그림자 재질을 제거하고 **접지 그림자**만 남겼다(공중에 뜨면 흐려지고 커짐). 보드는 단색 차콜(`#2a2a2a`) + 아주 약한 입자 질감, 외곽 그림자 1개(blur ≤ 6px), 트레이/선반은 1px 라인으로만 구분, 빈 고정 슬롯은 테두리 없는 연한 사각형.

### 연타 안정성

- `DiceTable.moveTo(id, to, ms)`: 주사위 id별 이동 1개만 유지, 새 이동은 **현재 그려진 위치**에서 시작해 이전 이동을 대체 → 고정/해제 연타, Alt+방향키, 이동 중 재굴림이 서로 덮어쓰지 않는다. 재굴림도 그려진 자세에서 시작.
- 클릭 영역(투명 버튼)은 `onPose` 콜백으로 **화면에 보이는 주사위를 실시간으로 따라가고**, 선택은 가장 가까운 중심 기준.
- 버그 수정: `requestAnimationFrame` 시각이 시작 시각보다 앞서면 진행도가 음수가 되어 첫 프레임 좌표가 `NaN`이 될 수 있던 문제(3차부터) → 0으로 고정.
- 정리: 렌더 루프·이동·페이드는 `dispose`에서 모두 취소, 소리는 렌더된 충돌 시점에 재생되므로 예약이 남지 않음.


## 8. 4차 후속: 모바일 AI 대전 족보 연출 축소

- 760px 이하 화면의 **사람 vs AI**에서는 `DiceTable.celebrate({ compact: true })`를 사용한다. 일반 족보는 최고 높이 2.5→1.5, 라지 스트레이트·요트는 3.4→2.0, 크기 배율은 일반 1.14/특별 1.22→1.0. 기존 점수와 애니메이션 시간, 연출 중 입력 잠금은 유지한다.
- 간소화된 2.5D 족보 강조 띠와 점수 라벨도 작게 표시한다. 데스크톱 연출은 그대로 둔다.
- 화면 순서는 주사위판과 굴리기 버튼 → 모바일 점수 기록 버튼 → 점수 요약 → 기보 보기/재대결/설정 변경. 보드 상단의 나의 차례·굴림 횟수는 모바일 AI 대전에서만 감춘다. 로컬 사람 대전은 차례 표시를 유지한다.

## 8. 5차 개편 (A1, 2026-11-27): 강하게 던진 느낌 — 실시간 물리

배속이 아니라 **초기 조건·형상·마찰 모델**을 바꿨다. 4차 `vigorous`는 비교용으로 남기고 기본을 `impulse`로 바꿨다(`DEFAULT_PROFILE`). 재생 속도는 1.25× → **1.0×(시뮬레이션 시간 그대로)**.

| 항목 | 분석(4차) | 5차 `impulse` |
|---|---|---|
| 출발 배치 | 무작위 자세의 큐브를 1.25 간격으로 나란히 → 대각선(1.73)보다 가까워 **첫 프레임에 서로·벽과 겹쳐** 튕겨 나감(던질 때마다 평균 10회의 0프레임 충돌, 회전 방향이 무작위화) | 이웃 주사위를 높이 1.8씩 엇갈린 손 안 묶음 → 0프레임 충돌 **0회** |
| 초기 impulse | 전진 4.2~7, 위로 1.8~4.4, 좌우 1.6~5.2(편차 큼) | 전진 7.2~9.8, **아래로** −3.2~−1.6(내리꽂기), 좌우 2.8~4.6(같이 던진 묶음), 중력 60→92 |
| 초기 각속도 | 세 축 무작위 | 70%가 **진행 방향으로 구르는 회전**(ω = 위×v / r), 30% 무작위 + 수직축 무작위 |
| 형상 | 날카로운 상자(바닥에서 미끄러짐) | **모서리를 깎은 큐브**(0.1, 24꼭짓점) → 모서리를 넘어 구름 |
| 반발·마찰 | 바닥 0.42/0.34, 벽 0.58, 주사위끼리 0.44 | 바닥 0.40/0.42, 벽 0.62, 주사위끼리 0.50 |
| 감속 | 선형 0.10·각 0.17 감쇠 | 감쇠 0.06/0.12 + **바닥 접촉 중에만 구름 저항**(초당 3.2, 느려지면 2.4배) |
| 정지 | 마지막 0.5초 미세하게 미끄러짐 | 평평하게 놓인 거의 정지 상태를 정지 마찰로 바로 멈춤 |
| 고정/해제 이동 | 일정 높이로 미끄러짐 | 거리에 비례한 포물선 들어 올림 + 진행 방향 ≤7° 기울임 + 내려놓을 때 0.03 눌림(`carryPose`, 윗면 유지 테스트) |

- 화면에 보이는 속도는 4차(×1.25 배속)와 비슷하지만, 이제 **실제 물리 속도**가 그만큼 빠르고 충돌이 1.5~1.7배 많다(벽·주사위끼리 튕김, 구르는 모서리 소리). 실시간 재생이라 착지 후 감속이 자연스럽다.
- 비용: 깎은 큐브의 볼록 다면체 충돌로 계산이 약 1.5~2배. 정지 중 미리 계산(`prepareThrow`)이 그대로 동작해 탭 시점에는 보통 0 ms(사전 계산 재사용). 작은 트레이 p95 82 ms는 재시도 때문이며 Web Worker 이전이 후속 개선안.
- 결과·RNG·확률·AI는 변하지 않는다: 값은 기존처럼 정지 후 큐브 대칭으로 면을 배정한다(테스트: 모든 굴림 최종 윗면 = 엔진 값, 결정성).
- 사람과 AI 차례 모두 같은 `PhysicalDice` → `DiceTable.play` 경로(같은 프로필·재생 속도·소리).

### 소재별 충돌음 (보드 표면)

주사위 소재 음색(`sound-packs.ts`)에 **보드 표면**을 더했다(`SURFACES`, `surfaceOf`). 펠트=고역을 삼키는 둔탁한 소리, 원목=노크 공명, 대리석·화산·폭풍=단단하고 밝은 딱 소리, 얼음=맑은 울림, 황금=금속 링, 바다·심해=물 먹은 저음, 사막=모래 서걱, 초원·꽃·숲=흙/풀 소리, 우주·네온·오로라=매끈한 아크릴. 바닥 충돌·구름·정지 소리에만 적용(주사위끼리는 주사위 소재만). **충돌 강도**가 음량뿐 아니라 저역통과 차단 주파수(0.45~1.2배)와 표면 공명 크기를 바꾼다. 기존 버스·리미터·음량·음소거·충돌음 예산(동시 10개·최소 간격)을 그대로 거치며, 추가 음성은 같은 예산의 허가를 받은 경우에만 생성된다. 보드 장착 화면은 `data-surface`로 표면을 알린다(Lv.1 포함). 사람 귀 청취 평가는 하지 않았다.

### Hover 제거

`.die-hit:hover`, `.die-button:hover`의 테두리 변화(주황·회색)를 없앴다. 선택(`.held`)·`:focus-visible` 외곽선·드래그 중 표시는 유지(Playwright로 hover 전후 테두리 색 동일, 선택 상태 확인).
