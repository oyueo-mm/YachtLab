# 3D 물리 주사위 — 프로토타입 설계와 검증

> 상태: 게임·홈·주사위 실험실에 적용. 기존 2.5D 연출은 삭제하지 않고 **선택 가능한 품질**이자 **자동 대체 경로**로 유지한다.
> 직접 비교: 연구실 → **주사위 실험실**(`#dice-lab`).

## 1. 핵심 원칙: 결과와 연출의 분리

- 오프라인에서는 기존 엔진(`src/engine.ts`, `src/multi-engine.ts`)이, 향후 온라인에서는 서버가 눈을 결정한다. 3D 연출은 **이미 확정된 값**을 받아 보여 줄 뿐이다.
- 엔진의 난수·점수 계산은 한 줄도 바뀌지 않았다. 주사위 연출 코드는 엔진에 값을 돌려주지 않는다.

## 2. 구현 방식

| 단계 | 내용 |
|---|---|
| 1. 사전 시뮬레이션 | `src/dice3d/physics.ts` — [cannon-es](https://github.com/pmndrs/cannon-es)(MIT) 강체 물리. 바닥·벽(트레이 경계)·주사위 간 충돌, 마찰, 반발, 감쇠. 고정된 주사위는 질량 0 장애물. 1/120초 스텝, 60fps 기록. |
| 2. 면 배치 결정 | 시뮬레이션이 끝났을 때 위를 향한 **물리 면**을 읽고, 엔진 값이 그려진 면이 그 자리에 오도록 큐브 대칭 회전(24개 중 하나) `C`를 고른다. 화면의 큐브는 처음부터 `몸체 방향 × C`로 그린다 → **굴러가는 도중 눈이 바뀌거나 마지막에 갑자기 회전하는 일이 없다**. |
| 3. 품질 검사 | 모든 주사위가 시간 안에 정지, 바닥에 평평하게 착지(위쪽 법선 내적 > 0.985), 트레이 안. 실패하면 다른 초기값으로 최대 10회 재시도. 그래도 실패하면 그 굴림만 2.5D로 대체(`ok: false`). |
| 4. 정렬 | 모두 멈춘 뒤 각 주사위가 바닥을 미끄러지며 자기 칸(드래그 정렬·고정에 쓰는 DOM 주사위 위치)으로 이동. 이때 **수직축 회전만** 하므로 윗면은 바뀌지 않는다. 끝 방향은 2D 주사위 그림과 같은 눈 방향. |
| 5. 렌더링 | `src/dice3d/stage.ts` — three.js(MIT). 트레이 위에 `pointer-events: none` 캔버스를 겹치고, 날아가는 동안 해당 DOM 주사위 얼굴만 숨긴다. 끝나면 다음 프레임에 DOM 주사위로 교체. 1 world unit = 주사위 한 변(CSS px로 정확히 환산되는 원근 카메라). |
| 6. 소리 | 시뮬레이션이 기록한 충돌(바닥/벽/주사위, 충돌 속도)을 **화면에 해당 프레임이 그려질 때** 재생. 강도→음량·밝기, 45ms 간격·굴림당 14개 제한. 취소되면 렌더 루프와 함께 남은 소리도 재생되지 않는다. |

### 입력·접근성

- 굴리는 동안 굴리기 버튼·주사위·점수판 기록이 비활성(전역 "굴림 중" 상태, 안전 타임아웃 포함) → 중복 굴림·다른 주사위로 잘못 전달되는 입력 없음. AI도 주사위가 멈춘 뒤 다음 행동을 한다.
- 고정·드래그 정렬·키보드(Alt+←/→)는 기존 DOM 버튼 그대로. 스크린리더용 `aria-label`은 항상 엔진 값.
- `prefers-reduced-motion` → 움직임 없음. "모션 간단히" 또는 저사양(코어 ≤2 또는 메모리 ≤2GB) → 2.5D 가벼운 연출. WebGL 불가 → 2.5D.
- 품질: 자동(데스크톱 3D 고급, 760px 이하 3D 가볍게) / 3D 고급(그림자 맵·안티에일리어싱·DPR 2) / 3D 가볍게(블롭 그림자·DPR 1.25) / 2.5D.

### 로딩

three.js + cannon-es는 별도 청크(`stage-*.js`)로 분리되어 **유휴 시간에 미리 로드**된다. 아직 로드되지 않았으면 그 굴림은 2.5D로 진행된다. 홈·게임 첫 화면의 초기 번들에는 포함되지 않는다.

## 3. 검증 결과 (실제 측정)

### 물리 일괄 검증 (Node, 각 200회, 5개 중 2개 고정 비율 1/3)

| 트레이(주사위 단위) | 깨끗한 착지(3D 사용) | 최종 눈 일치 | 시간 내 정지 | 길이 중앙값 / p95 | 시뮬레이션 평균 |
|---|---|---|---|---|---|
| 데스크톱 9.5 × 5.5 | 200/200 | 200/200 | 200/200 | 82 / 103 프레임 | 4.4ms |
| 모바일 5.2 × 5.6 | 200/200 | 200/200 | 200/200 | 90 / 110 프레임 | 9.5ms |
| 작은 화면 5.0 × 4.4 | 198/200 | 200/200 | 197/200 | 89 / 111 프레임 | 15.2ms |
| 매우 좁음 4.6 × 4.0 | 191/200 | 200/200 | 186/200 | 91 / 122 프레임 | 24.4ms |

- 모든 경우 주사위 중심 간 최소 거리 ≥ 1.0(겹침 없음), 트레이 이탈 0, 끝부분 프레임당 최대 회전 ≈ 9°(정렬 단계의 수직축 회전).
- 재생 속도 1.15배 → 데스크톱 중앙값 약 1.2초, p95 약 1.5초.
- 단위 테스트(`tests/dice3d-physics.test.ts`): 두 트레이 크기 × 36회, 모든 눈 1~6·모든 위치에서 최종 윗면 = 엔진 값, 최종 위치 = 칸, 최종 방향 = 2D 주사위 그림과 같은 방향, 결정성, 고정 주사위 비애니메이션.

### 브라우저 검증 (Playwright, Chromium 헤드리스, 데스크톱·모바일)

- 3D 고급/가볍게 각각: 굴림 중 캔버스 표시, 5개(재굴림 시 고정 제외 3개)만 3D, 정지 후 3D 최종 눈 = 엔진 목표 = DOM 주사위 값, 고정 주사위 라벨 불변.
- 빠른 연속 입력(더블클릭+Enter) → 굴림 1회.
- WebGL 차단 → 2.5D로 대체, 3D 품질 옵션 비활성.
- 주사위 실험실: 지정 눈(1,2,3,4,6)으로 3D 굴림 일치, 실제 트레이 크기로 300회 일괄 검증 300/300 일치.
- 헤드리스(소프트웨어 렌더링 포함 환경) 프레임 시간 평균 약 17ms(첫 프레임은 셰이더 컴파일로 50~120ms).

### 검증하지 못한 것 (수동 확인 필요)

- 실제 저사양 휴대폰의 프레임 유지(헤드리스 Chromium 측정만 함).
- 효과음의 실제 청감(재생 기록·타이밍만 자동 검증).
- 실제 손가락 스와이프의 감각(마우스 제스처만 자동 테스트).

## 4. 2.5D와 3D 비교

| | 2.5D (기존) | 3D 물리 (신규) |
|---|---|---|
| 표현 | 평면 주사위 이미지의 이동·회전·확대 | 입체 큐브, 여러 면이 실제로 보이며 그림자 |
| 움직임 | 미리 정한 키프레임(주사위마다 경로 다름) | 실제 강체 물리(충돌·마찰·감쇠, 서로 부딪침) |
| 눈 표시 | 중간에 무작위 눈을 보이다 마지막에 실제 눈 | 처음부터 물리 몸체에 고정된 면 배치 — 바뀌지 않음 |
| 정지 시점 | 주사위마다 약간 다름 | 물리에 따라 주사위마다 다름 |
| 길이 | 약 0.7초 | 약 1.2초(중앙값) |
| 비용 | 의존성 없음 | 지연 로드 청크(아래), 굴림당 시뮬레이션 5~25ms |
| 대체 | — | WebGL 불가·착지 실패·로드 전 → 2.5D |

## 5. 알려진 한계와 개선안

- 정렬 단계(약 0.25초)에서 주사위가 칸으로 이동할 때 서로의 경로가 겹쳐 보일 수 있다(충돌 처리 없음). 개선안: 정렬 경로 충돌 회피 또는 칸 위치를 시뮬레이션 목표 영역으로 사용.
- 시뮬레이션은 메인 스레드에서 실행(굴림당 최대 수십 ms). 매우 좁은 트레이에서 재시도가 늘면 체감될 수 있다. 개선안: Web Worker로 이동.
- 아주 좁은 트레이(4.6×4.0 이하)에서는 약 4.5% 굴림이 2.5D로 대체된다.
