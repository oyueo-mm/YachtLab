## 2. 공개 게이트

- `src/legal/release.ts`: `OPERATOR`(모두 `null`), `LEGAL_RELEASED = false`. `LEGAL_VISIBLE = LEGAL_RELEASED || LEGAL_PREVIEW`이고, `LEGAL_PREVIEW`는 개발 서버 또는 `LEGAL_PREVIEW=1`로 만든 빌드에서만 참이다(Vite `define` 빌드 상수).
- 운영 빌드(GitHub Pages, `deploy.yml`의 `dist-pages`)에서는 상수 `false`라서 초안 청크(`LegalPage-*.js`)가 번들에서 **빠진다**. 초안 경로로 들어오면 홈으로 돌아가고 링크도 보이지 않는다. 확인: 로컬 운영 빌드에 초안 문구 0건, `LEGAL_PREVIEW=1` 빌드에만 `LegalPage` 청크 존재. CI `build` 단계가 운영 빌드에 "검토용 초안" 문구가 있으면 실패하고, 라이선스 청크가 없어도 실패한다.
- CI 테스트 빌드(`dist-test`, 배포되지 않음)는 `LEGAL_PREVIEW=1`로 만들어 Playwright가 초안 화면을 검사한다.
- `tests/legal.test.ts`: `LEGAL_RELEASED`가 참인데 운영자 값이 비었거나 `[[확인 필요]]`가 남아 있으면 실패. 공개 전에는 운영자 값이 모두 비어 있어야 통과(임의 입력 방지).

## 4. 공개 절차 (승인 후)

1. 운영자가 [OPERATOR-CHECKLIST](./OPERATOR-CHECKLIST.md)의 A·B·C 항목을 확정하고, 필요하면 전문가 검토를 받는다.
2. D 항목(코드 수정)을 먼저 배포하거나, 하지 않을 경우 해당 문구를 현재 동작에 맞게 확정한다.
3. `OPERATOR` 값을 채우고 `[[확인 필요]]`를 모두 해소한 뒤 `LEGAL_RELEASED = true` — `npm test`가 통과해야 한다.
4. 정적 검색 페이지(`public/` 규칙·FAQ 등)와 Google OAuth 동의 화면에 처리방침·약관 링크를 추가한다(공개 후 작업).
