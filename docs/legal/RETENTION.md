## 3. PR #124 배포 후에도 남는 한계 (처리방침에 "즉시·완전 삭제"를 쓰지 않는 이유)

1. 배포 전에 탈퇴한 회원이 남긴 요청·한쪽 친구 행·차단 목록의 닉네임·코드: 정리 기능(`FRIEND_RESIDUE_CLEANUP`)이 **기본 꺼짐**이고 실제 삭제는 **운영자 미승인**(7일 dry-run만 계획). 승인 전까지 남는다.
2. 배포 전에 만들어진 차단: 서버 전용 역방향 기록이 없어 배포 후 차단된 회원이 탈퇴해도 익명화되지 않는다. 1번 승인이 필요하다.
3. 재시도 중인 정리: 성공할 때까지(최대 약 9.5일, 보류 시 30일) 상대 회원 쪽 정보가 남는다.
4. 30일까지 실패한 정리: 1번 승인 전에는 지워지지 않는다.
5. 친구 화면을 열지 않는 회원: 1번의 정리는 친구 목록을 열 때 하루 1번 동작한다.
6. 전역 친구 색인 정리 실패: 옛 코드가 탈퇴 계정 내부 ID와 연결된 채 남을 수 있다(조회되는 정보는 없음).
7. 다시 오지 않는 계정의 만료 세션 행(§2).
8. 다른 회원의 경기 기록과 차단한 회원의 가명 ID는 탈퇴로 지워지지 않는다.

## 5. 처리방침 초안 반영 방식

- 3~5항은 **현재 운영 Worker** 기준으로 썼다. 1인 플레이 기록 서버 보관은 main에만 있어 "확인 필요"로 표시했다.
- PR #124·C4.1 배포 후 바뀌는 문구는 이 문서의 "배포 후" 열로 교체한다. 교체 시 처리방침 시행일과 배포일을 맞추고, 운영자 체크리스트 D1·D2를 "완료(배포일)"로 바꾸면서 §3 한계를 함께 적는다.
- 차단 회피 방지용 가명 ID의 보관 근거·기간, 정리 대기 기록·옛 친구 코드·탈퇴 일시의 보관 근거는 법률 검토 전까지 확정하지 않는다.
