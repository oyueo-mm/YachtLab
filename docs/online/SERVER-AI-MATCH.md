## 1. Workers Free에서 실행 가능한 AI·구조 검증

| 후보 | 경로 | CPU(결정 1회, Node 측정) | 번들 | 판단 |
|---|---|---|---|---|
| 보통(Greedy: 지금 최고 점수 vs 한 번 더 굴린 기대 최고 점수) | `src/online/server-ai.ts`(엔진 점수 함수만 사용, 재구현) | **평균 1.05 ms, p99 2.8 ms**(300개 상태) · 기존 `decide()` 기준 평균 1.2/최악 5.4 ms | 추가 수 KB | **채택** |

`src/ai.ts`는 PPO·증류 모델(600 KB×2)·v4 체크포인트를 함께 불러오므로 Worker에서 import하지 않고, 같은 정책을 엔진 함수만으로 다시 구현했다. AI는 자기 주사위·굴림 횟수·점수판만 본다(주사위 공급원·RNG 상태 접근 없음 → 미래 주사위 예측 불가).

## 2. 경기 구조

- **PvP와 같은 저장 Durable Object**(`YachtRoom`): AI 좌석을 가진 방. 상태는 서버 권위, 주사위는 서버 CSPRNG, 모든 행동(사람·AI)은 같은 엔진으로 검증하고 **저장한 뒤에만** 공개(fail-closed). 서명만 확인하는 무상태 방식은 쓰지 않음(D-037).
- AI 좌석에는 좌석 토큰이 없어 누구도 AI로 접속할 수 없다. AI 행동은 방이 직접 적용(명령 ID `ai-<버전>` → 타이머·알람이 겹쳐도 멱등).
- 진행: 0.7초마다 한 동작(굴림·고정·기록이 화면에 보임). 객체가 퇴출돼도 5초 뒤 알람이 깨워 이어 감(AI 차례당 알람 쓰기 약 1회).
- 시작: `POST /api/ai/start`(회원 세션 필수) → 계정 저장소에서 **시작 횟수**를 먼저 기록(하루 30회) → 디렉터리 AI 일일 예산(`DAILY_AI_LIMIT` 100, 전체 300에 포함) → 방 생성(선공 무작위). 시작 수와 완료 수는 따로 관리(완료는 경기 기록).
- 재접속·복구: 일반 온라인 방과 같다(좌석 토큰, 이벤트 로그 재실행 감사). 사람이 나가면 턴 제한(120초) 후 AI가 시간 초과를 청구해 경기 종료(본인 탈주 → 보상 없음).
- 재대결 없음(새로 시작), 관전·공개 목록 없음, AI는 항상 "AI (보통)" + "서버 AI" 표시.
- 기록: `kind: "ai"`, `opponent.kind: "ai"`, server-verified. 보상은 경제 PR(M3i-W30: 완료 7·승리 +2).

## 3. 어뷰징 대응

| 공격 | 대응 |
|---|---|
| 같은 상태 재사용·분기(fork) | 상태는 DO 한 곳에만 있고 명령은 순서대로 한 번씩 적용, 클라이언트가 상태를 들고 있지 않음 |
| 재전송 | 명령 ID 멱등(기존 구조) |
| 주사위 결과 선별(불리하면 끊고 새로 시작) | 시작 횟수 하루 30회 차감, 끊은 경기는 시간 초과 패배·보상 없음, 업적은 완료 경기만 |
| AI 판단 조작 | AI는 서버에서만 계산 |
| 미래 주사위 예측 | 시드·RNG 상태 비공개(D-004/D-010) |

## 4. 비용

한 경기 ≈ PvP와 같은 행 쓰기(약 110행, D-037) + AI 알람 약 12행. AI 결정 CPU는 호출당 약 1 ms. 일일 상한 100경기(전체 300 중). `SERVER_AI=off`로 즉시 끌 수 있다(기본 켜짐, 로그인 설정이 있어야 동작).
