## 2. 무작위 매칭(R1) 설계 초안

- **큐 위치:** 전역 `MatchQueue` Durable Object 1개(이미 `RoomDirectory`가 전역 DO). 새 Cloudflare 리소스(새 Worker·D1·KV)는 만들지 않는다 — 기존 Worker의 DO 마이그레이션으로 추가.
- **흐름:** 클라이언트 `POST /queue`(닉네임·로그인 세션 또는 게스트 키) → 큐가 대기열에 넣고 짝이 생기면 기존 방 생성 경로로 방을 만들어 두 좌석 토큰을 발급 → 각 클라이언트는 기존 `?room=` 입장 흐름 재사용.
- **대기 방식:** WebSocket 대기(수신 메시지 20:1 환산이라 저렴) 또는 2~3초 폴링 중 WebSocket을 우선 검토. 대기열 상태는 **메모리**(행 쓰기 0), 매칭 성사 시에만 방 생성 쓰기.
- **실력 매칭:** 처음에는 FIFO(+같은 IP 해시 금지). 레이팅 도입 후 ±구간 확대 방식. 레이팅·랭크 업적은 **서버 검증 무작위 대전만** 입력(친구 대전·AI 대전 제외 → 승리 거래 차단).
- **한도:** 매칭 경기도 `DAILY_ROOM_LIMIT`(현재 300)에 포함. 경제 보상이 붙으면 경기 수가 늘 수 있으므로 [경제 연구 §Cloudflare](../economy/ECONOMY-RESEARCH.md#8-cloudflare-무료-플랜과-서버-비용) 수치로 한도를 다시 정한다.
- **어뷰징:** 같은 사람의 두 계정 자동 매칭(승리 거래) 방지 — 같은 기기 키·IP 해시 쌍 금지, 같은 상대와 연속 매칭 시 보상 감소 후보.

## 3. 관전방 탭(R2~R5) 설계 초안

- **동의:** 지금의 관전 허용(D-027)은 비공개 키 링크다. 공개 목록은 **별도 동의 "공개 관전 허용"**(모든 플레이어 동의, 기본 꺼짐). 무작위 매칭은 설정에서 "내 경기를 공개 관전에 표시" 기본값을 사용자가 고르게 한다(기본 꺼짐 권장 — 개인정보 기본값).
- **목록 저장소:** 전역 `SpectateDirectory` DO의 **메모리 맵**(roomCode → {닉네임들, 점수, 라운드, 관전자 수, 갱신 시각}). 방 DO가 라운드가 바뀔 때만 RPC로 갱신(턴마다 X) → 행 쓰기 0, DO 요청은 경기당 약 12~24회. DO가 퇴출되면 목록은 다음 갱신 때 다시 채워진다(목록은 손실 허용 캐시).
- **표시 항목(R4):** 닉네임(닉네임 정책 통과값), 현재 총점, 라운드(1~12), 관전자 수. 좌석 토큰·관전 키·게스트 ID는 노출하지 않는다. 공개 목록에서 입장하면 서버가 1회용 관전 토큰을 발급.
- **제거(R5):** 방의 `match.finished`/기권/만료 이벤트에서 즉시 삭제 + 갱신이 3분 이상 없으면 TTL로 삭제. 공개 관전을 끄면 즉시 삭제.
- **한도:** 기존 방당 관전자 5명(D-027)을 공개 관전에서는 그대로 시작해 대시보드 지표로 조정. 목록 조회는 IP당 속도 제한(메모리).
- **친구 대전(R6):** 공개 플래그와 무관하게 기존 비공개 링크 그대로.

## 4. 장착 아이템 공개(R9)

- 상대에게 보이는 것: 닉네임, 프로필(아이콘·테두리), **주사위 외형**, 장착 이모티콘·프리셋 목록(사용 시 보임), 칭호(업적 전용 포함).
- 방은 입장 시 서버가 **계정 저장소의 장착 정보(loadout)를 읽어** 좌석 정보에 붙여 전파한다. 클라이언트가 보낸 장착 정보는 신뢰하지 않는다(보유하지 않은 아이템 표시 방지). 게스트는 기본 외형만.
- 형식: `{ dice: itemId, frame: itemId, title: itemId|null, emotes: id[≤8], chats: id[≤10] }` — 모두 불변 ID(`src/social/catalog.ts` 규칙과 동일하게 재사용 금지·`retired` 표시).
- 외형은 **결과와 무관한 표시 계층**(D-014, D-017과 같은 원칙). 주사위 외형이 눈 판독성을 해치면 안 되므로 상점 등록 전 판독성 검사(대비·눈 크기)를 둔다.
- 슬롯: 이모티콘 기본 4·최대 8, 프리셋 기본 6·최대 10. **현재 무료 기본 세트가 이미 이모티콘 8개·프리셋 10개**이므로, 슬롯 도입 시 기본 장착 4/6개를 사용자가 고르게 하고 나머지는 보관함에 남긴다(기존 사용자 기능 축소처럼 느끼지 않도록 첫 도입 시 기본 슬롯 상향 또는 무료 지급 검토 필요 — 미결정).

## 5. PC에서 채팅·이모티콘·관전 버튼 미표시(R7) 조사 결과

**결론: 현재 main 코드와 현재 배포본에서는 재현되지 않음. 원인 미확정.**

- 방법: 로컬 Node 온라인 서버 + Vite 개발 서버, Chromium 두 컨텍스트로 방 생성·입장·게임 시작 후 데스크톱 6개 해상도(1920×1080, 1440×900, 1366×768, 1280×720, 1024×768, 820×1180)에서 `.game-tools`의 버튼 위치·`display`·`visibility`·뷰포트 포함 여부를 측정했다. 6개 모두 `관전`·`채팅`·`기권` 버튼이 상단 도구 줄(y≈76px)에 보였다. 대기실에서도 같은 도구가 보인다. 기존 CI의 `tests/ui/online.spec.ts`(데스크톱 1280×900)도 `채팅·이모티콘` 버튼을 클릭한다.
- 배포본: 2026-11-24 GitHub Pages 메인 번들(`assets/index-*.js`)에 `채팅·이모티콘` 문자열이 포함되어 있다(PR B·C 반영).
- **가능한 원인(확인 필요):**
  1. **오프라인 AI 대전·로컬 2인 화면**을 보고 있는 경우 — 채팅·이모티콘·관전은 온라인 방 전용이라 원래 없다(설계상). 가장 가능성 높음 → 오프라인 화면에 "온라인 대전에서만 사용 가능" 안내를 둘지 결정 필요.
  2. **관전자 화면**(관전 링크) — 관전자는 설계상 채팅·조작 불가(D-027).
  3. 브라우저 캐시로 **PR B 이전 번들**이 남은 경우 — 강력 새로고침으로 확인.
  4. 브라우저 확대 배율·좁은 창 — 760px 이하에서는 모바일 배치(도구가 보드 아래)로 바뀐다.
- 다음 단계: 사용자에게 (화면 종류: 온라인 방/오프라인/관전, 브라우저·OS, 창 크기·배율, 스크린샷)을 받아 재현. 재현 스크립트는 이 조사에 쓴 방식(두 컨텍스트 + 크기별 측정)을 Playwright 테스트로 옮길 수 있다.

## 6. 기본 이모티콘·프리셋 검수 규칙(R8)

- 현재 기본 18개(프리셋 10, 이모티콘 8)는 인사·응원·칭찬·축하·감사·대기 요청뿐이며 조롱·도발 표현이 없다 — 유지.
- 신규 무료 기본 항목: 상대를 깎아내리거나 결과를 조롱할 수 있는 표현(예: 비웃음·"쉽네요" 류) 금지. 유료·업적 항목도 같은 기준(구매로 도발 수단을 얻지 않게).
- 상대 표시 숨기기(이미 있음)와 속도 제한(D-026)은 유지.

## 7. 순서 제안

1. 경제 서버 기반(원장·멱등 처리, server-verified만) — 제품 Phase 5/6 공통 토대.
2. 장착 정보 공개 스키마(R9)와 슬롯(기본 4/6).
3. 무작위 매칭(R1) — 레이팅 없이 FIFO.
4. 공개 관전 목록(R2~R5).
5. R7은 사용자 정보 수신 즉시 별도 처리.
