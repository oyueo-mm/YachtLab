# 친구 목록·친구 초대 (I/J, 2026-11-25)

Google 로그인 회원 전용. 게스트는 기존처럼 방 코드·초대 링크로 친구 대전에 참여한다.

## 식별자와 개인정보

- **공개 친구 코드**: `YL` + Crockford base32 8자리(헷갈리는 I·L·O·U 없음, 무작위, 전역 유일). 사람이 입력한 `yl-7k3q 9p2x`, 소문자, `YL` 생략, O/I/L 오타를 정규화한다.
- 닉네임이 같아도 코드로 정확한 사람에게 요청한다. 응답에는 내부 계정 ID(`u_…`)·이메일·OAuth 식별자가 없다(테스트로 확인). 친구 프로필은 기존 공개 프로필(닉네임·가입 월·서버 검증 온라인 전적)에서 내부 ID를 빼고 코드로 연다.

## 저장 구조 (Cloudflare Workers Free, SQLite Durable Objects)

- 각 계정의 `UserStore` SQLite에 `fr_meta`(코드·일일 카운터)·`fr_friends`·`fr_in`·`fr_out`(거절 시각 포함)·`fr_blocks`·`fr_invites`. 계정 간 단계는 RPC로 순서대로 하고 모두 멱등이다(재시도해도 두 번 처리되지 않음).
- 새 SQLite DO `FriendIndex`(마이그레이션 v4, 무료 플랜 범위): 친구 코드 → 계정, **정확한 닉네임** → 계정. 친구 기능을 쓴 회원만 등록(코드 발급 시·닉네임 변경 시 갱신). 탈퇴 시 관계가 있는 모든 계정(친구·받은/보낸 요청·차단 양방향)에 세대 한정 정리가 가고 색인에서도 삭제(실패분은 재시도 대기열, C4.2). 친구 코드는 계정 세대라 재가입하면 새 코드를 받고, 옛 요청·친구·초대는 효력이 없다. 탈퇴자를 차단한 목록은 "탈퇴한 사용자"로 익명화돼 남는다(재가입 후에도 차단 유지). [C4.2](../audits/c4-2026-11-28/C4-2-ACCOUNT-SECURITY.md)
- 접속 상태는 저장하지 않는다(각 계정 객체 메모리). "접속 중" = 최근 2분 30초 안에 사이트가 받은함을 확인함(화면이 보일 때 1분마다 한 번), "경기 중" = 방이 경기 시작·종료 때 알려 준 상태(메모리, 최대 3시간). 친구 목록을 볼 때만 친구들의 상태를 모은다(전역 실시간 추적·추가 폴링 없음).

## 남용 방지

| 항목 | 규칙 |
|---|---|
| 검색 | 회원만, 정확한 닉네임 전체 또는 친구 코드(부분 검색 없음), 최대 10명, 분당 20·하루 200회 |
| 요청 | 하루 30건, 보낸 대기 요청 100건, 받은 대기 200건(초과분은 조용히 무시), 거절당하면 24시간 뒤 재요청 |
| 차단 | 친구·요청·초대가 즉시 삭제, 차단된 쪽의 요청·초대는 성공처럼 보이지만 저장되지 않음, 검색·프로필에서도 숨김 |
| 초대 | 친구에게만, 같은 친구·방은 1분에 한 번, 초대자 분당 20건, 10분 뒤 만료, 받은 초대 최대 50건 |
| 친구 수 | 200명 |

## 흐름

1. 친구 메뉴(홈)에서 내 코드 복사 / 닉네임 전체·코드로 찾기 → 요청. 서로 동시에 요청하면 바로 친구.
2. 받은 요청: 홈 메뉴 배지 + 친구 페이지에서 수락·거절·차단. 보낸 요청 취소, 친구 삭제, 차단·해제.
3. 친구 대전 대기실(회원)에서 "친구 초대" → 접속 중인 친구 먼저 정렬 → 빈자리 수만큼 선택 → 초대.
4. 받은 사람은 사이트 어디서나(진행 중 경기 화면 제외) 초대 카드로 수락·거절. 수락하면 계정 닉네임·장착 외형으로 그 방에 입장. 방이 가득 찼거나 시작됐거나 닫혔으면 이유를 보여 주고 초대를 지운다.
5. 외부 푸시 알림은 이번 범위가 아니다(사이트 내부 알림만).
