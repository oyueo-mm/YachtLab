# 온라인 친구 다인전 (2~20명) — 순차·동시 진행 (2026-11-24)

> 결정 기록: DECISIONS D-044. 2인 무작위 매칭([MATCHMAKING](./MATCHMAKING.md))·서버 AI 대전([SERVER-AI-MATCH](./SERVER-AI-MATCH.md))은 그대로(2좌석·순차 진행).
> 재현: `npx tsx scripts/online/load-sim.ts 3`(→ `results/load-sim.json`), `npx tsx scripts/online/load-workers.ts`(→ `results/load-workers.json`).

## 1. 기능

| 요구 | 구현 |
|---|---|
| 2~20명 친구 대전, 방 생성 시 최대 인원 | `POST /api/rooms {name, maxPlayers}`(2~20, 기본 2). 엔진 `MAX_SEATS` 20 |
| 초대 링크·방 코드 입장 | 기존 그대로(`?room=CODE`, 6자리 코드). 초대 화면에 `현재/최대 인원 · 진행 방식` |
| 게스트·회원 | 둘 다. 회원 좌석은 친구 방에서도 계정의 **검증된 장착 외형**을 사용(이전에는 빠른·AI 대전만) |
| 대기실·참가자·준비·방장 | 참가자 목록(접속 표시·장착 외형), **준비 완료**(3명 이상 방: 방장 외 전원 준비해야 시작; 1:1 방은 기존처럼 바로 시작), 방장만 설정·시작·방장 넘기기 |
| 순차 / 동시 진행 | 방장이 대기실에서 선택. 순차 = 좌석 순서대로 한 명씩(기존 엔진). **동시 = 모든 참가자가 같은 라운드를 각자 주사위로 동시에** 진행, 전원 기록하면 다음 라운드 |
| 턴·라운드 시간 제한 | 순차: 없음·30·60·90·120·180초(턴), 동시: 60·90·120·180초(라운드, 필수) |
| 적응형 점수판 | 8명까지 전원 열, 9명 이상은 "내 점수판/현재 차례 ↔ 전체 점수판" 전환(로컬 다인전 점수판 재사용). 휴대폰은 표가 자기 영역에서 가로 스크롤(페이지는 넘치지 않음) |
| 실시간·최종 순위 | 순위·점수·채운 칸·이번 라운드 상태(동시: "진행 중 · 굴림 n / 기록 완료", 순차: "차례")·기권·접속 표시. 종료 후 최종 순위와 내 순위 |
| 채팅·이모티콘·장착 아이템 | 기존 프리셋 채팅·이모티콘(장착한 것만), 말풍선은 순위표의 내 줄에, 주사위 테마(동시: 내 테마, 순차: 현재 차례), 닉네임 효과·칭호 |
| 중도 기권·재접속·방장 이전 | 기권은 라운드 진행을 막지 않음. 재접속은 같은 좌석 토큰(새로고침·연결 끊김·서버 재시작). 방장은 넘기기 가능, 방장이 떠나면 남은 사람 중 가장 먼저 들어온 사람이 자동 승계 |
| 재대결 | 1:1은 기존(둘 다 요청). 3명 이상은 원하는 사람이 "재대결"을 누르고 **방장이 "지금 시작"** → 요청한 사람(2명 이상)으로 새 경기, 나머지 좌석은 닫힘. 선공은 한 칸씩 회전 |
| 방 정리 | 대기실 30분·종료 후 30분 무접속이면 삭제(기존), 3명 이상 방에서 **경기 중 전원 이탈 2시간**이면 삭제(1:1은 기존 24시간 유지), 방 최대 보존 48시간 |
| 재화·퀘스트·업적·전적 | 친구 대전으로 집계(완료 10코인, 승리 보너스 없음, 하루 10경기). 승리 = **단독 1위**, 공동 1위 = 무승부. 서버 기록에 `field: {players, rank, mode}`. 다른 사람이 모두 떠나 일찍 끝난 경기는 상대 기권 규칙(6칸 이상 채워야 완료 보상) |

## 2. 동시 진행 규칙 (엔진 `src/online/server-engine.ts`)

- `matchCreated.mode = "simultaneous"`(순차 경기 로그는 바이트 단위로 이전과 같음).
- `roundStarted {round, deadline}` → 활동 중인 모든 참가자에게 각자의 턴(굴림 0). 굴림·고정·기록은 각자 자기 턴에만 적용, 기록하면 그 라운드 턴이 닫힘. 모두 기록하면 다음 `roundStarted`, 12라운드 후 `matchFinished`.
- **라운드 시간 초과**(서버 알람): `roundTimedOut` 후 미기록자마다 서버가 자동 기록 — 한 번도 안 굴렸으면 서버가 한 번 굴리고, 지금 가장 점수가 높은 빈 칸에 기록(`auto: true`). 자동 기록이 **3라운드 연속**이면 그 참가자는 시간 초과 기권. 직접 기록하면 연속 횟수 초기화.
- 다른 참가자의 행동으로 버전이 계속 바뀌므로 동시 진행에서는 버전 검사(STALE_VERSION)를 하지 않는다. 각자의 턴 상태(굴림 수·라운드)를 엔진이 검사하고, 명령 ID 멱등은 그대로.
- 감사(재실행) 호환: 시간 초과 그룹은 서버 굴림이 여러 번 들어갈 수 있어, 감사가 그룹 안의 모든 `diceRolled`에서 주사위 값을 재생한다. 이벤트 비교를 먼저 하고 주사위 수 검사를 나중에 해 변조 위치를 정확히 보고한다(기존 감사 테스트 그대로 통과).
- 보기(viewFor): 동시 진행에서 `turn`은 **보는 사람 자신의 턴**, `progress`는 아직 기록하지 않은 참가자별 굴림 수(다른 사람의 주사위 값은 보내지 않음 — 메시지 크기), `roundRemainingMs`.

## 3. 대기실·설정·시작 (방 `src/online/room.ts`)

- 방 기록에 `settings {mode, timeoutMs}`·`ready`·`hostId`. 준비·설정·방장 변경은 저장 1회씩, 사람당 0.3초 간격·경기 사이 200회 상한(쓰기 루프 방지).
- 시작: 방장 확인 → 인원 ≥ 2 → (3명 이상) 전원 준비 → **일일 예산 추가 차감** → 설정을 적용해 새 경기를 만든다(방장 선공, 이후 좌석 순서; 좌석 토큰·플레이어 ID 유지) → 저장 → 화면 갱신 → 응답.
- 일일 예산(`DAILY_ROOM_LIMIT` 300 단위): 경기당 **⌈인원/2⌉ 단위**(방 생성 1 + 시작 시 나머지). 실측 쓰기가 인원에 비례(2인 78행/경기, 20인 758행)하므로 단위당 쓰기가 인원과 관계없이 약 76~78행으로 일정 → 300단위 ≈ 하루 2.3만 행(무료 10만 행의 약 23%, 다른 Worker와 공유 몫 고려). 재대결도 같은 규칙.
- 연결 한도: 방당 소켓 48(20명 + 예비 탭·재연결 + 관전 5), 방당 분당 연결 120(20명이 동시에 재연결해도 통과).

## 5. 보안·동시성

- 플레이어 ID는 인증된 소켓에서만(페이로드 무시), 좌석 토큰은 해시로만 저장(기존). 방장 권한(설정·시작·방장 넘기기·재대결 시작)은 서버가 검사.
- 한 객체가 명령을 하나씩 처리(직렬) → 동시 진행에서도 같은 라운드 이중 기록·라운드 꼬임 없음(테스트: 10명 교차 굴림·기록, 20명 동시 굴림).
- 주사위는 서버 CSPRNG, 저장 후 공개(fail-closed) 그대로. 동시 진행에서 다른 사람의 주사위 값은 화면에 보내지 않음.
- 속도 제한: 소켓당 토큰 버킷(기존), 채팅·이모티콘 도배 제한(기존), 대기실 변경 간격·횟수 제한.
- 감사: 저장된 로그는 깨어날 때 엔진 재실행으로 검증(20인 로그 포함 테스트).

## 6. 한계

- 관전 화면(`?watch=`)은 1:1 배치라 3명 이상 방은 앞의 두 명만 크게 보인다(관전은 모든 참가자 동의가 필요해 다인 방에서는 드묾) — 후속.
- 20인 동시 진행에서 모두 같은 순간 누르면 응답이 수십 ms 늦어진다(4.2).
- Workers Free CPU: 명령당 수 ms 이하로 측정됐지만 실제 workerd CPU 시간은 운영 대시보드로 확인해야 한다(퇴출 후 20인 로그 재감사 10~16 ms).
