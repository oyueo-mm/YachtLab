# YachtLab

한국어 요트 다이스 게임과 AI 전략 실험실. React · TypeScript · Vite · Tailwind CSS · Web Worker · PyTorch.

대상 공개 주소: https://oyueo-mm.github.io/YachtLab/

## v0.4 기보·분기·DP 정책 증류

알고리즘 선택창을 키보드·터치로 조작하는 커스텀 드롭다운으로 교체하고 난이도를 표시합니다. 사람 대전에서는 AI의 굴림·고정·기록을 단계별로 보여줍니다. 홈 시연의 기존 속도는 유지합니다.

사람 대전·AI 관전·토너먼트를 공통 `YachtLabReplay` v1 형식으로 기록합니다. 기보 뷰어, IndexedDB 저장·이름 변경·삭제, JSON 내보내기·불러오기, v0.3 Match 가져오기와 중간 상태의 AI 아레나 분기를 지원합니다. 외부 기보는 엔진으로 모든 행동을 재실행해 점수·주사위·난수 상태를 검증합니다. 분기는 원본과 과거 행동을 보존합니다. [기보 형식과 검증·분기 설계](docs/REPLAY.md).

전략 분석실은 모든 AI의 선택을 동일한 `Q_DP(s,a)`로 평가하고 최선 대비 기대점수 손실을 표시합니다. 기보에서 **이 수를 분석하기**로 실제 선택 직전 상태를 비교할 수 있습니다. 입력을 바꾸면 이전 결과를 지워 실제 선택과 가상 분석을 혼동하지 않도록 했습니다. 점수 기준은 단독 기대 총점이며 상대 승률의 손실을 뜻하지 않습니다.

DP·Greedy·Random·혼합 정책의 실제 대국에서 학습 상태 **228,956개**, 검증 상태 **25,503개**를 생성했습니다. 64×64와 128×128 PyTorch 모방학습을 비교하고 128×128 모델을 선택했습니다. 검증 동등 최적 행동 일치율 **92.15%**, Top-3 **99.22%**, 평균 DP 손실 **0.075점**입니다. 추가 PPO와 무작위 초기화 대조 실험을 각각 **262,144 환경 스텝** 실행했습니다. 기존 PPO와 DP 자산은 보존했습니다.

별도로 분리한 최종 1,000경기 평가에서 DP Expert **191.88점**, Distilled Policy **187.82점**, Distilled PPO **185.98점**, 기존 PPO **100.18점**입니다. PPO 추가 학습은 모방학습보다 낮아진 결과도 그대로 보존했습니다. 두 새 모델은 검증된 추가 선택지이며 기본 상대와 최고 성능 기준은 DP Expert입니다. 새 가중치는 선택 시에만 Worker에서 불러옵니다. [실험 설정·전체 비교·신뢰구간·승률·모델 크기·실제 학습 곡선](benchmarks/v04/REPORT.md).

학습 재현은 `node scripts/distill-data.mjs 3600 400` 다음 `python training/distill.py`로 실행합니다. 데이터·체크포인트는 로컬에 보존하고 Git에서 제외하며, 모델 JSON·설정·로그·해시·원시 평가 결과를 추적합니다. 상세 재현 명령은 실험 보고서에 있습니다.

v0.4 최종 로컬 검증: 단위 46개, Python 3개, 데스크톱·모바일 브라우저 69개 통과(터치 전용 1개 제외), 타입 검사·빌드 통과. [검증 범위와 실행 기록](docs/VERIFICATION-v04.md).

## v0.3 홈 UX와 전체 게임 DP

홈 문구 아래 `사람 vs AI`와 `AI vs AI` 바로가기를 추가했습니다. 기존 6개 실제 턴 기록은 유지하며, 대기 시간은 `src/demo-timing.ts`에서 굴림 240ms·첫 화면 450ms·고정 650ms·일반 행동 750ms·완료 1250ms로 관리합니다. CSS 굴림·이동·점수 기록 효과도 이 설정을 사용합니다. 백그라운드 정지와 모션 감소 동작은 보존했습니다.

새 **DP Expert**는 현재 턴의 휴리스틱 대신 남은 12개 카테고리와 상단 보너스를 포함한 전체 게임의 미래 기대점수를 사용합니다. 독립·공정한 주사위 확률모형에서 Bellman 재귀를 전부 계산하며 Float64 수치 산술을 사용합니다. 상대 승률이나 PRNG 시드 예측을 최적화하지 않으며 `Optimal` 표시는 하지 않습니다. [상태·재귀·정확성·재현 방법](training/dp/README.md)을 확인하세요.

상태는 4096개 남은 카테고리 마스크 × 상단 누적 점수 64개입니다. C++로 오프라인 계산한 테이블은 2MiB, 압축 전송은 약 1.26MiB이며 최초 굴림 전 기대 총점은 191.76088점입니다. 브라우저는 필요한 시점에만 Worker에서 로드·검증합니다. 사람 대전에서는 게임 동안 Worker를 재사용해 테이블을 한 번만 준비하고, 재대결·화면 이탈 시 종료합니다. 분석실은 전체 게임 기대 최종점수와 최선 대비 후보 차이를 표시합니다.

기존 5종 AI의 정책과 PPO 모델은 보존했습니다. DP 정책을 이용한 모방학습·Value Network·PPO 후속 학습은 이번에 수행하지 않았으며 후속 연구 과제로 남깁니다.

고정 혼합 시드에서 각 AI 1000경기 본 평가를 완료했습니다. 평균 총점은 DP Expert **193.82** (95% CI 191.53~196.11), Expectimax 173.87, Greedy 163.45, MCTS(600회) 136.34, PPO 101.18, Random 39.30입니다. DP의 Expectimax 대비 점수 우위는 19.95점(95% CI 17.22~22.68), 상대별 승률은 67.70%입니다(무승부 0.5승). 모든 기존 모델 대비 짝별 평균 차이의 95% 구간이 양수인 것을 확인해 DP Expert를 기본 상대로 설정했습니다. 최고 성능 표시는 **이 벤치마크의 평균 총점 기준**입니다.

[전체 비교표·상대별 승률·메모리·실행 시간](benchmarks/REPORT.md), [개별 원시 점수와 실험 설정](benchmarks/summary.json), [브라우저 측정](benchmarks/browser-dp.json)을 보존했습니다. 실제 맞대결 100경기로 정책별 점수 쌍의 재현 일치를 확인했습니다. 로컬 브라우저 최초 준비는 50.1ms, 준비한 Worker의 100회 왕복은 평균 0.551ms였으며 공개 네트워크 성능 보장은 아닙니다.

재현: `npm run benchmark` (기존 Expectimax 1000경기는 이 환경에서 약 22분 소요). 단독 정책의 기대 총점 최대화와 상대를 이길 확률 최대화는 구분해야 합니다.

2026-10-28 최종 검증: Vitest 35개, Python 3개, 프로덕션 빌드 대상 Playwright 49개 통과(데스크톱에서 터치 전용 1개 제외). 타입 검사·빌드 통과, npm audit 취약점 0건. 기존 5종 AI와 PPO 배포 모델을 보존했으며, DP 테이블 1회 로딩·취소·재시도·리플레이·모바일 320px 배치까지 확인했습니다.

## 규칙 및 상태

`src/engine.ts`가 웹과 모든 AI의 유일한 TypeScript 규칙 엔진입니다. 불변 상태 전이와 명시적 LCG 난수 상태로 재현합니다. 주사위 ID와 화면 순서를 분리하여 정렬이 난수 및 점수에 영향을 주지 않습니다. 관전은 모든 행동 뒤 전체 상태를 저장하여 정확하게 복원합니다.

상단 6종, 초이스, 포커(4개 이상), 풀 하우스(서로 다른 3+2), 스몰(15), 라지(30), 요트(50). 5개 같은 눈은 풀 하우스가 아닙니다. 상단 63점부터 보너스 35점. 이 규칙에서 이론상 총점 상한은 323점입니다.

양측 플레이어는 동일한 초기 시드의 독립 난수 스트림을 사용합니다. 고정한 주사위 수가 달라지면 이후 소비하는 난수의 개수도 달라지므로 모든 결과가 같은 짝별 대조 실험은 아닙니다. 토너먼트는 같은 시드 묶음을 AI 쌍에 공유하고 경기마다 선후공을 바꿉니다. 무승부는 0.5승, 표준편차는 모집단 공식, 실행 시간은 AI 판단 함수 실행 시간의 합(통신·화면 재생 제외)입니다.

## 실제 AI 구현

| 알고리즘   | 구현 및 해석                                                                                                                                          |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Random     | 합법 행동 중 확률적으로 점수 선택/재굴림. 재굴림 시 각 주사위 50% 고정. 모든 합법 행동의 균등 분포는 아님                                             |
| Greedy     | 모든 고유 고정 조합의 한 번 재굴림 기댓점수와 즉시 최고점을 비교. 전략 기회비용 없음                                                                  |
| Expectimax | 남은 최대 2회 굴림을 완전 탐색. 같은 눈의 조합별 다항확률 집계, 상태 메모이제이션. 아래 근사 효용 사용                                                |
| MCTS       | 결정 노드 UCT 선택·미방문 행동 확장·확률 결과 샘플링·남은 턴 롤아웃·역전파. 방문 수가 가장 많은 루트 행동 선택. 예산 50~50,000회                      |
| PPO        | PyTorch로 실제 학습한 초기 정책. 60차원 관측 → 64 tanh → 64 tanh → 44 행동. 불가능한 행동 마스킹, 결정적 argmax. JSON 가중치를 브라우저에서 직접 추론 |
| DP Expert  | 전체 게임 미래 가치 테이블 + 현재 턴 완전 DP. 상단 보너스 포함, 독립 공정 주사위 모형과 Float64 수치 계산. 기대 최종 총점 최대화                      |

Expectimax와 MCTS는 **전체 경기 최적해가 아닙니다**. 턴 종료 근사 효용은 `획득 점수 - 카테고리 기준값 × (남은 칸 수 - 1) / 11`이며 기준값은 순서대로 `[2,4,6,8,10,12,18,12,10,11,16,12]`입니다. 상단 카테고리는 이번 기록으로 보너스에 도달하면 실제 +35, 아직 도달하지 못하면 남은 63점까지의 점수에 0.35의 가치를 추가합니다. 미래 턴 점수 분포와 상대방 상황은 탐색하지 않습니다. MCTS의 롤아웃은 최다 빈도 눈을 고정하여 남은 굴림을 진행하고 이 효용으로 평가합니다. 화면의 근사 효용은 최종 경기 예상 점수가 아닙니다.

AI 계산, 경기 생성, 토너먼트는 Web Worker에서 실행합니다. 취소는 해당 Worker를 종료하여 현재 탐색도 중단합니다. 관전 속도는 이미 계산한 상태 기록의 재생 간격만 바꿉니다.

## PPO 학습 및 평가

```sh
python -m pip install -r training/requirements.txt
python training/test_env.py
python training/train.py --steps 1048576 --seed 42
npm test
```

- 관측 60차원: 고유 ID 순서 주사위 one-hot 30, 굴림 one-hot 4, 사용한 칸 12, 기록 점수/50 12, 상단 진행도 및 남은 칸 수 2
- 행동: 0~31은 ID 비트 마스크로 고정 후 재굴림, 32~43은 카테고리 기록
- 학습 환경은 턴 시작 자동 굴림. 사용한 칸과 3회 이후 재굴림을 마스킹
- 보상: 획득 점수와 보너스 증가량 / 100. PPO clipped objective(0.2), GAE λ=0.95, γ=1, value loss, entropy bonus, gradient clipping
- 실제 학습: 1,048,576 환경 스텝, seed 42. 별도 100개 평가 시드 100000~100099에서 평균 **99.42점**, 최저 69, 최고 136, 보너스 1%, 요트 0%
- 이 결과는 초기 학습 기준선입니다. 강한 AI 또는 다른 알고리즘보다 우수한 모델이라고 주장하지 않습니다. 승률은 사용자가 실제 토너먼트를 실행한 결과에서만 표시합니다.
- `src/ppo-model.json`: 브라우저 배포 가중치, 형식·스텝·학습 시드·PyTorch 확률 검증 fixture
- `training/evaluation.json`: 실제 평가의 개별 점수와 통계
- `training/checkpoints/ppo.pt`: 로컬 모델·optimizer 체크포인트(Git 제외). 학습 재실행 시 이 파일과 내보낸 모델을 덮어씁니다.
- 학습 규칙 Python 구현은 252개 모든 주사위 멀티셋 × 12개 점수를 TypeScript 엔진과 교차 검증합니다. PyTorch 정책 확률과 TypeScript 추론도 비교합니다.

## 배포

`.github/workflows/deploy.yml`은 main에 푸시할 때 단위 테스트·타입 검사·빌드·브라우저 테스트를 모두 통과한 경우 GitHub Pages에 배포합니다. 저장소 Settings → Pages의 Source를 **GitHub Actions**로 설정해야 합니다. PR은 검증만 수행합니다. Vite base는 `/YachtLab/`입니다.

CI는 GitHub 호스팅 Ubuntu 24.04의 시스템 라이브러리를 사용하고 테스트용 Chromium 헤드리스 브라우저만 설치합니다. OS 글꼴 패키지 저장소의 다운로드 지연을 피하며 모든 브라우저 테스트는 그대로 실행합니다. 브라우저 설치에는 5분 제한을 둡니다.

## 현재 한계와 다음 개선

- PPO는 학습을 완료한 초기 모델이며 성능 개선, 장기 학습, 하이퍼파라미터 탐색이 필요합니다.
- Expectimax/MCTS는 이번 턴 탐색과 수작업 근사 효용으로 평가합니다. 전체 경기 가치 함수 및 상대 점수는 미반영입니다.
- 실험 결과 저장은 현재 브라우저 localStorage와 JSON 다운로드입니다. 서버 동기화, 외부 JSON 리플레이 가져오기는 포함하지 않습니다.
- 관전은 Worker에서 경기 전체를 먼저 계산합니다. 긴 탐색 예산에서는 준비 시간이 필요하며 취소할 수 있습니다.
- 자동화한 브라우저 검증 범위는 Chromium입니다. 실제 iOS Safari·Android 기기 검증은 추가로 필요합니다.
