# DP Expert

목표는 **독립·공정한 주사위 확률모형에서 단독 플레이의 기대 최종 총점 최대화**입니다. 상대 승률이나 공개된 PRNG 시드를 이용한 다음 눈 예측을 최적화하지 않습니다. 이름은 DP Expert이며 `Optimal` 표시는 사용하지 않습니다.

## 상태와 재귀

- `M`: 남은 카테고리 12비트 마스크, 0~4095
- `u`: 상단 누적 점수 `min(63, upper)`, 0~63
- `D`: 순서를 무시한 주사위 5개, 252개 멀티셋
- `r`: 남은 재굴림 0~2회
- `V(M,u)`: 첫 굴림 이전부터 남은 경기에서 얻을 기대 추가 점수. 이미 기록한 점수와 이미 받은 보너스는 제외

`V(0,u)=0`. 점수 기록은 다음 값의 최댓값을 선택합니다.

```text
A0(D,M,u) = max over c in M:
  score(D,c) + newlyEarnedBonus(u,c) + V(M without c, updatedUpper(u,c))

Ar(D,M,u) = max(
  A0(D,M,u),
  max over held submultisets H of D: E[Ar-1(H + rerolled dice,M,u)]
)

V(M,u) = E over initial five dice [A2(D,M,u)]
```

기존 `src/engine.ts`에서 생성한 252×12 점수 배열을 사용합니다. 상단 보너스는 63점에 처음 도달하는 상태 전이에서만 +35를 지급합니다. 63점 이후를 하나로 묶어도 미래 보너스 행동이 같으므로 정보 손실이 없습니다. 이미 사용한 개별 칸의 점수는 미래 행동에 영향을 주지 않으며 화면에서 현재 총점에 미래 추가 기대점수를 더합니다.

남은 칸이 감소하는 순서로 계산하므로 순환 의존성이 없습니다. 각 턴 안에서는 남은 굴림이 감소합니다. 위 Bellman 재귀의 유한 상태·행동을 모두 평가하며 수작업 기회비용이나 학습된 가치 근사를 사용하지 않습니다. **전체 게임 DP이지만 IEEE754 Float64 수치 계산입니다.** 유리수 기반의 오차 없는 산술 또는 수치 오차 상한의 형식 증명은 포함하지 않습니다. 따라서 부동소수점 오차와 동률에 가까운 행동의 미세한 차이는 가능합니다.

## 확률 계산과 계산량

길이 0~5의 멀티셋은 총 462개입니다. 길이 5 미만의 210개 상태마다 공정한 6개 눈의 자식 상태를 저장합니다(1260개 간선). 각 길이 5 상태가 고정할 수 있는 모든 부분 멀티셋 간선은 합계 4368개입니다. 무작위 눈을 한 개씩 추가하며 평균하므로 중복 눈 조합의 다항확률이 정확히 반영됩니다. 굴림마다 7776개 순서 결과를 직접 열거할 필요가 없습니다.

카드 상태는 4096×64=262144개입니다. 빈 마스크 64개는 종료 상태입니다. `u + remainingUpperMaximum < 63`인 상태는 보너스가 불가능하므로 63점 상태와 같은 미래 점수값을 공유합니다. 실제 생성에서는 197119개 카드 상태를 풀고 64961개를 이 조건으로 재사용했습니다.

전처리 작업량은 카드 상태마다 대략 `252×남은 칸 수 + 2×(1260+4368)`입니다. C++ 전처리 실측은 `preprocessing.json`에 기록합니다. 현재 테이블은 2097152바이트(2MiB), gzip 1324626바이트이며, 초기 기대 총점은 **191.760879752165점**입니다.

## 생성과 재현

```sh
node scripts/prepare-dp.mjs
# Windows/MSYS2:
g++ -O3 -std=c++17 training/dp/solve.cpp -o training/dp/solve.exe -lpsapi
training/dp/solve.exe public/ai/dp-values.f64 > training/dp/preprocessing.json
# Linux에서는 .exe와 -lpsapi 없이 같은 소스를 컴파일·실행
node scripts/package-dp.mjs
npm test
```

`prepare-dp.mjs`는 기존 게임 엔진에서 커널과 C++ 헤더를 생성합니다. `solve.cpp`는 전체 DP를 계산하고 시간·프로세스 peak RSS를 측정합니다. 패키징은 gzip과 SHA-256, 콘텐츠 해시 파일명, 브라우저 manifest를 생성합니다. 테이블은 Float64 little-endian입니다. 바이너리 실행 파일과 비압축 중간 파일은 Git에서 제외하며 압축 배포 테이블은 포함합니다.

브라우저는 DP를 선택하여 실제 판단을 요청했을 때 Worker에서 테이블을 지연 로드합니다. gzip 해제와 SHA-256 검증 후 사용하며 홈에는 로드하지 않습니다. 추론은 현재 카드의 턴 내 DP만 수행하고 저장된 전체 경기 미래 가치를 참조합니다. Worker 종료로 계산과 로드를 취소할 수 있습니다.

## 검증

- 252×12 커널 점수와 기존 TypeScript 규칙 일치
- 부분 멀티셋 기대값과 독립 결과 열거 일치
- 남은 1~2칸에 대한 별도 재귀 완전탐색과 테이블 값 일치
- 여러 카드 마스크·상단 점수에서 Bellman 잔차 확인
- 0점 칸을 버리는 장기 선택, 63점 보너스 경계, 마지막 칸·굴림, 결정성, 합법 경기 완주
- 브라우저 지연 로딩, 전체 경기 기대값·후보 차이, 실제 관전과 리플레이, 토너먼트, 로드 취소·실패 후 재시도

`benchmarks/browser-dp.json`은 로컬 프로덕션 빌드의 첫 준비 시간, 100개 요청의 왕복 시간, Chrome DevTools가 측정한 전용 Worker 및 메인 페이지의 힙을 기록합니다. `usedSize`, `totalSize`, `backingStorageSize`는 서로 다른 메모리 항목이며 브라우저 전체 RSS로 합산해서 해석하면 안 됩니다. 공개 네트워크 로딩 시간과 로컬 측정값도 구분해야 합니다.

## 벤치마크 원칙

`node scripts/benchmark-all.mjs`로 6개 AI를 순서대로 각각 1000경기 평가합니다. 평가 시드는 고정 카운터 200000~200999를 32비트 혼합하여 만듭니다. 인접 LCG 초기 시드의 첫 굴림 상관을 피하려는 설계입니다. PPO의 초기 학습 시드 집합 및 기존 100000~100099 평가 시드와 분리합니다. DP는 학습 데이터를 사용하지 않습니다. MCTS 예산은 600회입니다.

각 표본은 기존 엔진의 완전한 경기에서 측정하고 표본마다 선후공을 바꿉니다. 목표 AI는 자신의 점수판과 독립 난수 스트림만 보므로 상대의 행동이 자신의 경로에 영향을 주지 않습니다. 같은 평가 시드의 단독 점수들을 짝지으면 실제 해당 두 AI의 경기 점수와 일치해야 하며 별도 실제 맞대결 재현으로 검증합니다. 난수 소비량은 고정 행동에 따라 달라지므로 서로 완전히 같은 주사위 경로라고 주장하지 않습니다.

평균 점수와 승률은 구분합니다. 평균과 짝별 평균 차이, 승리 1·무승부 0.5·패배 0 표본 평균의 95% 정규 근사 신뢰구간을 보고합니다. 점수 표준편차는 표본 공식을 사용합니다. 행동 계산 시간은 실제 판단 함수 실행 벽시계 시간이며 첫 테이블 로드와 Worker 통신은 별도 측정입니다. Node 프로세스 peak RSS는 Vite 검증 하네스·런타임·로드된 코드까지 포함하므로 순수 모델 크기가 아닙니다.
